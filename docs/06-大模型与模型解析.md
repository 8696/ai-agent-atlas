# 06 · 大模型与模型解析

## 6.1 模型接入方式

本项目**只用两个适配器**（都指 `base_url` 指向兼容端点），
但**在配置层支持五种供应商**（对齐 Hermes 的 `providers/`）：

| provider       | 适配器                | base_url 写法                | key                    | 典型服务                        |
| -------------- | --------------------- | ---------------------------- | ---------------------- | ------------------------------- |
| `anthropic`    | `@langchain/anthropic` | 留空（官方）                  | `ANTHROPIC_API_KEY`    | Anthropic 官方 / 智谱 GLM 兼容端点 |
| `openai`       | `@langchain/openai`    | 留空（官方）                  | `OPENAI_API_KEY`       | OpenAI 官方 / 硅基流动 / DeepSeek |
| `openrouter`   | `@langchain/openai`    | `https://openrouter.ai/api/v1` | `OPENROUTER_API_KEY` | 一个 key 通 200+ 模型            |
| `nous`         | `@langchain/openai`    | 留空（Nous Portal）           | `NOUS_API_KEY`         | Portal（另含搜索/图像/TTS 工具网关） |
| `local`        | `@langchain/openai`    | `http://127.0.0.1:11434/v1`  | **不需要 key**         | Ollama / LM Studio / vLLM / llama.cpp |

> ⚠️ **`local` 供应商是本期重点**（Hermes 的主打能力）：
> 本地模型 + 本地 Agent = 完全不出网的数据闭环。
> `local` 走 OpenAI 兼容协议，所以**一个适配器就够**。
> ⚠️ **`local` 的 base_url 允许回环地址**（那是用户自己的机器），
> 其余供应商仍要过 SSRF 校验。

**模型解析链**（`services/model.ts`）：

```
解析链：主模型（`LLM_*`）→ 备用模型（`LLM_FALLBACK_*`，没配就没有）→ 没有可用模型
```

- `.env` 的 `LLM_*` 就是全部（**没有另一套「平台默认」**）
- ⚠️ **没有可用模型时不能 500**：前端要显示「还没配置模型」的空状态，
  并**指明要改 `.env` 的 `LLM_MODEL`**（没有配置页可跳）

## 6.1.1 已验证的供应商（2026-10 实测）🎯

> 四家国产模型**全部提供 Anthropic 兼容端点** ——
> 所以 **Atlas 只需要一个 `anthropic` 适配器**，换供应商 = 改 `.env` 的三行。

| 供应商   | Anthropic 端点                                | 模型              |
| -------- | ---------- | --------------------------------------------- | --------------- |
| 智谱 GLM | `zhipu`     | `https://open.bigmodel.cn/api/anthropic`       | `glm-5.3`       |
| MiniMax  | `minimax`   | `https://api.minimaxi.com/anthropic`           | `MiniMax-M3`    |
| DeepSeek | `deepseek`  | `https://api.deepseek.com/anthropic`           | `deepseek-v4-pro` |
| 千问 Qwen | `qwen`      | `https://dashscope.aliyuncs.com/apps/anthropic` | `qwen3.8-max`  |

**实测结论**（五项能力全绿）：

| 能力               | 智谱 | MiniMax | DeepSeek | 千问 |
| ------------------ | ---- | ------- | -------- | ---- |
| 基础对话           | ✅   | ✅      | ✅       | ✅   |
| 思考模式（thinking）| ✅   | ✅      | ✅       | ✅   |
| 工具调用（tool_use）| ✅   | ✅      | ✅       | ✅   |
| **流式 SSE**       | ✅   | ✅      | ✅       | ✅   |
| **tool_result 回灌** | ✅   | ✅      | ✅       | ✅   |

**四家的 SSE 事件序列完全一致**（标准 Anthropic）：
`message_start` · `ping` · `content_block_start` · `content_block_delta` ·
`content_block_stop` · `message_delta` · `message_stop`

⚠️ **三个必须写进实现的细节**：

1. **thinking 块带 `signature`，多轮必须原样回传**
   —— 智谱等返回 `{"type":"thinking","thinking":"…","signature":"…"}`，
   Anthropic 的 extended thinking **要求把 thinking 块连同 signature 一起回传**，
   丢了 signature 多轮会报错。
   → **消息落库时要把 `thinking` 块和 `signature` 一起存**（`messages.parts` 里）
2. **`max_tokens` 必须 > `thinking.budget_tokens`**
   —— Anthropic 硬要求，超了直接 400。
   → 建模型时把上限抬到 `max(budget + 1024, maxTokens)`
3. ⚠️ **MiniMax 直连不稳定** —— 它的域名在你这台机器上解析到 `198.18.1.73`
   （保留段 = 走代理），直连会 `fetch failed`；要通需设 `HTTPS_PROXY`。
   → **Atlas 的出站要支持代理**（见 [10](./10-安全方案.md)）

### 6.1.2 供应商配置形态（每家只配三行）

```dotenv
# 每个供应商只配三样：Base URL + 模型 + Key
ZHIPU_BASE_URL=https://open.bigmodel.cn/api/anthropic
ZHIPU_MODEL=glm-5.3
ZHIPU_API_KEY=sk-xxxx

# 模型标识（只填模型名，不是完整 URL 路径）
LLM_MODEL=glm-5.3
```

⚠️ **换供应商只改这三行** —— **不改代码**。
⚠️ **`.env` 里没有 JSON、没有数组、没有供应商前缀** —— 全是标量。

## 6.2 供应商差异（踩过的坑）

| 坑                                       | 现象                                   | 处理                                        |
| ---------------------------------------- | -------------------------------------- | ------------------------------------------- |
| **系统提示词必须走 `system` 参数**        | 塞进 messages 的 system 角色 → 供应商 400 | LangChain 的 `systemMessage` / `system` 字段 |
| **智谱的 Anthropic 端点不吃 `cache_control`** | `cache_read_tokens` 恒为 0            | 提示词缓存在该供应商上无效，UI 要说明         |
| **推理模型思考 token 全额算输出 token**    | 成本比预期高好几倍                     | 调小 `LLM_THINKING_BUDGET`（本期只有一个模型，抽取也用它） |
| **部分供应商不支持 `parallel_tool_calls`** | 并行工具调用报错                       | 降级为串行（配置项 `parallel_tools`）          |
| **部分供应商不接受 `tool_choice='required'`** | 强制工具调用报错                     | 检测到 400 时重试为「不强制」                |

## 6.3 工具调用

- 工具定义用 **LangChain 的 `tool()`** 或 `StructuredTool`（zod schema 自动转 JSON Schema）
- 工具 schema 由 `tools/registry.ts` 统一产出 → 图的 `ToolNode` 直接吃这批工具
- ⚠️ **不要在工具 description 里写实现细节** —— description 是给模型看的，
  写「这个工具会读 /etc/passwd」等于教模型怎么越权
- ⚠️ **工具数量会挤占上下文**：工具太多时模型选错。
  本期工具少（5 个内置 + Skill + MCP），不做「按场景动态裁剪工具池」，
  但要**预留这个扩展位**（按当前问题相关度过滤工具池）

## 6.4 提示词（system prompt）的组装顺序

```
1. 基础人格与安全边界（内置，不可被用户改）
2. 当前生效的提示词文件（用户改 `prompts/*.md`）
3. 长期记忆（按相关性召回的 top N 条，条数 + token 双重裁剪）
4. 已加载的 Skill 说明（命中 Skill 时）
5. 工具使用规范（可用工具列表 + 权限档说明）
```

> ⚠️ **顺序有意义**：记忆要排在提示词版本之后 —— 冲突时以「提示词版本」为准？
> 不，规则要写清楚：**工具输出的事实 > 长期记忆 > 提示词里的通用知识**。
> 记忆是「关于这个用户的偏好」，不是「世界事实」。
> ⚠️ **工具返回的内容必须标注为「不可信数据」**（外部内容可能含注入指令），
> 不能和系统指令同等对待。

## 6.5 检索（不用嵌入模型）

⚠️ **本期不需要嵌入模型** —— 检索改走 **SQLite FTS5 全文索引**
（见 [05-b](./05-b-数据模型-全文检索.md)）。

| 用途         | 用哪张索引              | 说明                                |
| ------------ | ----------------------- | ----------------------------------- |
| 长期记忆召回 | `memory_fts`            | 记忆条目全文匹配                    |
| Skill 匹配   | `skill_fts`             | 技能 name + description 全文匹配     |
| 跨会话检索   | `messages_fts`          | 历史消息正文全文匹配                |

- ⚠️ **分词器必须 `trigram`** 才能搜中文（见 [05-b §5.2](./05-b-数据模型-全文检索.md)）
- ⚠️ **FTS5 不可用不能阻断对话**：检索降级为「按时间倒序取最近 N 条」
- ⚠️ **换分词器不用重算** —— 这是选 FTS5 而不是向量的最大好处

## 6.6 思考 / 推理预算

- 每条模型配置有 `thinking_budget`（token 数，0 = 关）
- 用户在聊天页也可以临时勾选「思考模式」→ 请求体带 `thinking`
- 解析顺序：`resolveThinkingBudget(模型配置, 用户勾选)`
  - 配了 > 0 → 一直生效
  - 没配但用户勾了 → 用兜底预算（1024）
  - 没配也没勾 → 0（关）
- ⚠️ **推理模型的思考 token 全额算输出 token** —— 这是「抽取成本实测 2000+」的原因
- ⚠️ **部分供应商不支持思考参数** → 传了报 400 时要能降级为「不带思考参数重试」

## 6.7 重试与抖动

- AI SDK **没有**给 LangChain 这条路加抖动；上游挂掉时所有并发请求在同一毫秒一起重试（惊群）
- 自己在 `lib/retry.ts` 里做：**全抖动** `random(0, min(cap, base * factor^n))`
- 尊重 `Retry-After` 头
- ⚠️ **只包非流式调用**：流式中途失败已经吐了一半，重来会吐两遍
- ⚠️ **工具调用同理不重试**：工具可能有副作用（写文件、发请求），
  重试 = 执行两遍。工具的错误**回灌给模型**让模型自己决定怎么办

## 6.8 熔断

- 按 `provider|base_url` 分桶，连续失败到阈值就断开，期间快速失败
- 冷却后半开一个探活
- ⚠️ **进程内状态**：多实例部署时每个实例各断各的（本期单机，不构成问题）

## 6.9 成本

| 项                     | 口径                                                     |
| ---------------------- | -------------------------------------------------------- |
| 输入 token             | `usage.prompt_tokens`                                     |
| 输出 token             | `usage.completion_tokens`（**含推理模型的思考 token**）    |
| 缓存命中 token         | `usage.cached_tokens`（⚠️ 智谱恒为 0）                   |
| 单价                   | 按模型配置里的价格表（可配）· 没配就用内置默认价          |
| 记账时点               | **每一轮结束立刻记**（`cost_logs`），不能等会话结束才记   |
| ⚠️ 记忆抽取 / 摘要      | **单独记**（`usage_scope` 区分），别混进对话成本里       |

> ⚠️ **换模型要能换价**：价格表跟着模型配置走，
> 否则「换了便宜模型但成本反而涨了」这种问题会查不出来。

## 6.10 不做的事

- ❌ **不做微调 / 训练**
- ✅ **支持本地模型**（`local` 供应商：Ollama / LM Studio / vLLM / llama.cpp，
  走 OpenAI 兼容协议，**不需要 API Key**）——
  ⚠️ 但 `local` 的 `base_url` **允许回环地址**（那是用户自己的机器），
  其余供应商仍要过 SSRF 校验
- ❌ **不做本地模型的训练 / 量化 / 部署**（只连接，不生产模型）
- ❌ **不做提示词自动优化**（A/B 对比只做「跑两遍比结果」，不做自动改写）
- ❌ **不做向量模型的自训练**
