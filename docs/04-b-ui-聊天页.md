# 04-b · UI · 聊天页与历史会话页

> UI 规格。写代码前先对这份。
>
> ⚠️ **本期没有登录页** —— 服务完全无鉴权，打开 `/chat` 直接用
> （见 [12-a A1](./12-a-需求-应用外壳与上下文.md)）。
> 本文件只有两个页面：**聊天页** 与 **历史会话页**。

## 4.1 聊天页 `/chat` ★

主界面。三块：会话栏（左）· 消息区（中）· 输入区（下）。

### 4.1.1 消息区

| 元素         | 规格                                                                   |
| ------------ | ---------------------------------------------------------------------- |
| 用户气泡     | 右对齐，浅色底，右侧头像字母 M（尺寸与 AI 头像相同）                   |
| AI 气泡      | 左对齐，**不要拉满整行**（⚠️ 拉满 = 一大块空白，难读）                 |
| 工具卡片     | 在对应消息**上方**，可折叠                                             |
| 待确认卡片   | 在对应消息**上方**，突出显示（这是要人做决定的）                       |
| 时间戳       | 消息右上角小字；「今天」只显示 `HH:mm`                                 |
| 引用块       | Markdown 渲染，蓝色左边线                                              |
| 表格         | GFM 表格（`react-markdown` + `remark-gfm`）· 表头浅底 · 边框 · 支持 `:---:` 对齐 · 宽表格**横向滚动**（套一层可滚动容器，别撑破气泡） |
| 代码块       | highlight.js 高亮 + 复制按钮（⚠️ 配色要跟深色模式切）                  |
| 流式中的光标 | 尾部一个闪烁光标                                                       |
| 等待态       | **第一个字到之前**显示三个呼吸的点（见 [B12](./12-b-需求-对话与编排.md)）—— ⚠️ **没有它看着像卡死**；气泡建出来之前占一个 AI 行，建好但没字就画在气泡里 |
| 思考过程     | 在 AI 正文**上方**。思考中展开、限高并跟着滚到底；结束后收起，可再展开 |
| 命令结果     | 斜杠命令的输出用**独立气泡样式**（灰底、带命令名），**不进模型轮次**   |
| 子代理卡片   | 在对应消息**上方**，可折叠                                             |
| 空状态       | 没消息时显示欢迎语 + 几个建议问题（可配）                              |

#### 长会话的渲染（2026-11-01 优化批次）

| 做法                     | 为什么                                                                 |
| ------------------------ | -------------------------------------------------------------------- |
| **每条消息单独 `memo`**  | 流式时每来一个 chunk，整个消息数组都换新 → 全部行重渲染 → **每条旧消息的 Markdown 被重新解析一遍**。`memo` 之后只有「正在流的那一条」重渲染 |
| **回调引用要稳定**       | `onRegenerate` / `onConfirm` 一变就等于「全部行重渲染」—— `useCallback` + 忙状态放 `useRef` |
| **更早的消息折叠**       | 一次最多渲染**最后 150 条**，更早的给一个「显示更早的 N 条消息」按钮 —— 打开几百条的老会话不用一次性解析几百段 Markdown |
| ⚠️ **不做虚拟滚动**     | 虚拟滚动要算高度，会跟「滚到底」打架；本地单用户的会话普遍不长（实测最长约 10 条），不值得 |
| ⚠️ **不用 `content-visibility`** | 它让 `scrollHeight` 估算失准 → 「滚到底」会滚不到位，收益不明 |

### 4.1.2 输入区

| 元素     | 规格                                                                      |
| -------- | ------------------------------------------------------------------------- |
| 输入框   | 多行 textarea，`Enter` 发送 · `Shift+Enter` 换行                          |
| 发送     | 空内容时禁用；发送中变成「停止」                                          |
| 停止     | 调 `chat.stop()`；停止后已输出的内容保留                                  |
| 重新生成 | 在**最后一条 AI 消息**上；⚠️ **必须传 `messageId`**                       |
| 思考模式 | **不放开关**。预算在 `.env` 的 `LLM_THINKING_BUDGET`（默认 1024，0 = 关） |
| 斜杠命令 | 输入 `/` 触发补全浮层（见下）                                             |
| 附件     | 本期不做（留位）                                                          |

> ⚠️ **「重新生成」的坑**：不传 `messageId` 时 SDK 会重生成**最后一条**消息 ——
> 传错消息就重生了空气泡。必须 `regenerate({ messageId: msg.id })`。
> ⚠️ **顺带暴露的后端 bug**：SDK 重生成时会先把那条 assistant 从本地数组砍掉，
> 后端收到的末条是 user → 靠「末条是 assistant」判断**永远判错** →
> 后端要**按请求体的 `messageId` 定位**，不能靠「末条是什么」。

#### 斜杠命令补全（`CommandHint`）

- 输入框检测到**行首是 `/`** → 在输入框上方弹浮层，列出候选项
- 候选项四类：**斜杠命令**（`/help` `/usage` `/model` …）·
  **已装技能名** · **可用人格文件** · **可用模型名**
- 交互：`↑` `↓` 选择 · `Tab` 补全 · `Enter` 确认 · `Esc` 关闭
- ⚠️ **拿整个输入去筛** —— `/model glm` 这种**带参数的**也要能补全
- ⚠️ **补全只是辅助，不改变语义** —— 命令在**服务端解析**，
  前端只是帮用户少打字（见 [12-b B9](./12-b-需求-对话与编排.md)）
- ⚠️ **未知命令要有明确反馈**：服务端返回「未知命令 `/xxx`，`/help` 看全部」，
  **不发给模型**（否则白白消耗一次 LLM 调用，还可能触发工具）
- 📌 **清单从 `GET /api/v1/commands` 拿** —— 前端不维护一份命令表
  （命令表只有一份，在服务端）

#### 命令结果的气泡

- 命令结果**照常渲染成普通气泡**（正文是 Markdown），只是上方多一行小标签
  「命令 /help」
- ⚠️ **命令结果不进模型上下文** —— 它不是模型轮次
  （后端在转换前端历史时跳过带 `data-command` part 的 assistant 消息）
- 📌 **命令结果照常落库** —— 刷新后还在，标签也还在
- 📌 **命令可能带动作**（`/new` 换会话 · `/retry` 重新生成 · `/undo` 撤销）——
  前端收到 `data-command` part 后执行对应动作（**同一个动作只做一次**）

### 4.1.3 会话栏

| 元素     | 规格                                              |
| -------- | ------------------------------------------------- |
| 新对话   | 顶部按钮（→ `/chat`）                             |
| 会话项   | 标题 + 相对时间；悬停显示「重命名 / 收藏 / 删除」 |
| 只看收藏 | 开关                                              |
| 搜索     | 输入框（服务端搜，**防抖 250ms**）                |
| 折叠     | 窄屏自动折叠                                      |

> 📌 **点会话项 → `/chat?session=<id>`** —— 会话 id 就在 URL 里，刷新能回到同一个会话。
> 📌 **「历史会话」小标题是个链接** → `/sessions`（完整的列表页：表格 · 分页 · 批量删除）。
> 📌 **重命名是行内编辑** —— 点铅笔后标题变成输入框，`Enter` 保存、失焦取消。

> ⚠️ **切「只看收藏」不能掐断正在流式的回答**（见 [12-b B2](./12-b-需求-对话与编排.md)）——
> **侧栏列表的 loading 与聊天面板的 loading 是两个独立状态**，
> 切筛选只重拉列表，不碰聊天。
> ⚠️ **侧栏列表与历史会话页的列表是两份独立的状态** ——
> 侧栏永远是**最近 20 条 · 第 1 页**；
> 在 `/sessions` 翻页 / 改搜索词 / 切「只看收藏」**不许动侧栏那份**
> （否则侧栏「今天」的分组会被换掉）。
> ⚠️ **但改名 / 收藏 / 删除要同步到两份** —— 在历史页改了标题，侧栏那份也得跟着改。
> ⚠️ **自动发送不能在 mount effect 里直接调 `sendMessage`**（StrictMode + `chat.stop()` 会掐掉发送）——
> 用 `setTimeout(0)` 延后一拍，**并在定时器回调里打「已发过」的标记**
> （标记打在 effect 里会被 StrictMode 的第二次执行挡掉，消息就永远发不出去了）。

### 4.1.4 工具卡片

| 状态   | 表现                                      |
| ------ | ----------------------------------------- |
| 执行中 | 旋转图标 + 「正在执行…」                  |
| 成功   | ✓ + 工具名 + 耗时；出参默认折叠           |
| 失败   | ✗ + 工具名 + **错误原因**                 |
| 已拒绝 | ⊘ + 「用户已取消」                        |
| 待确认 | 橙色 + 「批准 / 取消」两个按钮 + 参数预览 |

> ⚠️ **失败必须显示原因**，不能吞掉 —— 用户要能判断是工具坏了还是模型用错了。
> ⚠️ **入参出参里的密钥要打码**。

> 📌 **本期做到哪（2026-10）**：✅ 已实现
> —— 组件在 `web/pages/chat/ToolCallCard.tsx`，
> 数据是 `data-tool-call` part（落库 → 刷新后还在）。
> ⚠️ **同一次调用的多张卡片共用一个 part id** ——
> 「执行中」会被最终状态**原地替换**，不会堆成两张。

### 4.1.5 待确认卡片

- 明确写出**要执行什么、影响什么**（不是只给一串参数）
- 两个按钮：**批准**（主）/ **取消**（次）
- ⚠️ **批准按钮要有 loading**（执行可能要几秒），避免重复点击执行两遍
- ⚠️ **批准后模型改了参数 → 要重新弹确认**（不能沿用旧的批准）

> 📌 **本期做到哪（2026-10）**：✅ 已实现
> —— 组件在 `web/pages/chat/ToolCallCard.tsx`，
> 数据是 `data-pending-confirm` part。
> - **两条恢复路径**：进程还在 → 原来的 SSE 继续往下流；
>   进程重启过 → `POST /api/v1/chat/confirm` 自己恢复图，一次性返回结果
> - ⚠️ **「模型改了参数」当前不会发生** —— 挂起期间模型不会被调用，
>   参数是固定的；批准**绑定参数指纹**，指纹对不上会重新弹确认（防御性）

### 4.1.6 子代理卡片

| 元素        | 规格                                     |
| ----------- | ---------------------------------------- |
| 标题        | 子代理名 + 任务一句话摘要                |
| 状态        | 运行中（旋转图标）/ 成功 / 失败          |
| 摘要        | 子代理返回的摘要（默认折叠，展开看全文） |
| 耗时 / 步数 | 跑了几步 · 用了多久                      |

> ⚠️ **不显示子代理的完整过程** —— 只给摘要，
> 否则主对话会被子代理的中间过程淹没（子代理产物有 2000 字符上限，见 [12-b B10](./12-b-需求-对话与编排.md)）。
> ⚠️ **子代理要人工确认时，弹的是同一个「待确认卡片」**（4.1.5），
> 不是另一套 UI —— 用户不需要知道这是子代理要做的。

## 4.2 消息级收藏 📌

- 每条 AI 消息右上角一个 📌（在「重新生成」旁边）
- 收藏状态存 `messages.favorite`
- 「只看收藏」筛选同时看会话级与消息级
  （**会话里有被收藏的消息，那个会话也算命中**）

> ⚠️ **不写审计**（跟会话级收藏一致）—— 收藏是个人偏好，不是管理动作。

## 4.3 会话历史页 `/sessions`

- 表格：标题 · 消息数 · **Token** · 最后活跃 · 收藏 · 操作
  📌 **Token 列** —— 这个会话一共用了多少 token（缩写 `43k` + 悬停给精确值）
  （见 [12-d D7](./12-d-需求-记忆与配置.md)）
  ⚠️ **「工具调用数」列暂时没有** —— `tool_call_logs` 表还没建
  （见 [12-c C6](./12-c-需求-工具技能与扩展.md)）
- 搜索 + 只看收藏筛选（**服务端筛**）
- 批量删除（带二次确认）
- ⚠️ **「总数」卡要显示筛选后的数量**（⚠️ 常见 bug：卡上写总数、筛选后不变）
  —— 分页器的 `共 N 个（筛选后）` 与右上角的 `N 个会话` 都取**筛选后**的总数
- ⚠️ **这一页的列表状态与侧栏那份是分开的**（见 [§4.1.3](#413-会话栏)）——
  在这里翻页 / 搜索 / 切筛选**不影响侧栏**；反过来也一样
