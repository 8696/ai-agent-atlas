## 模块 04 · 工具注册表 ★

**职责**：把三种来源的工具汇成**模型看到的一池工具**，并保证它们走同一条执行入口。

**输入**：`builtin` 工具集 + `skill` 目录扫描 + `mcp` server 连接结果
**输出**：工具定义数组（名称 / 描述 / 入参 schema / 敏感档 / 实现）

**关键约束**：

- ⚠️ **唯一入口**（`tools/registry.ts`）—— 工具执行**必须**经由
  `agent/tool-node.ts`，
  ⚠️ **不许在图节点里直接 `await tool.invoke()`**（绕过权限闸 = 开后门）
- 工具名**全局唯一**：冲突时 Skill / MCP 工具改名或拒绝注册，**并报告**，
  ⚠️ **不静默覆盖内置工具**
- 禁用 / 不可用的工具**不进工具池**（模型看不见）
- ⚠️ **描述不缓存到进程**（改描述要下一轮就生效 —— 这是「调教模型」的主要抓手）
- 三种来源的**元信息统一**：模型看到的不该有差别（来源信息只给用户看）

**降级**：

| 情况             | 行为                                       |
| ---------------- | ------------------------------------------ |
| MCP server 断了  | 该 server 的工具从池里移除，其余不受影响   |
| Skill 目录读不到 | 跳过该 Skill，其余正常                     |
| 某个工具 schema 非法 | 跳过该工具 + 告警（**不让整个池挂掉**） |

**已知边界**：

- ❌ 不做工具池的动态裁剪（按相关度只给模型看一部分工具）——
  **预留扩展位**（`registry.ts` 里留一个 filter 钩子）
- ❌ 不做工具的版本管理

## 模块 05 · 内置工具实现

**职责**：5 个通用工具的实现（文件 / 目录 / 命令 / 请求 / 时间）。

**清单**（⚠️ 刻意做少 —— 见 [12-c C2](./12-c-需求-工具技能与扩展.md)）：

| 工具           | 敏感档   | 关键实现约束                                      |
| -------------- | -------- | ------------------------------------------------- |
| `read_file`    | normal   | 路径沙箱；行范围；大文件截断；编码探测（UTF-8 优先，失败回退） |
| `write_file`   | **high** | 路径沙箱；覆盖写要显式 `overwrite`；自动建父目录（可选） |
| `list_dir`     | low      | 不递归；分页；区分文件 / 目录；隐藏项可选显示      |
| `shell`        | **high** | 超时杀进程；输出截断（**保尾部**）；跨平台（`cmd /c` vs `/bin/sh -c`）；黑名单 |
| `http_request` | normal   | 出网校验（**含重定向逐跳校验**）；超时；大小上限；只允许 http/https |

**共用约束**：

- 所有文件路径**先 resolve（含 symlink）再判沙箱**
- 所有入参有长度 / 数量上限
- 所有工具**统一超时**（`tool_timeout_ms`）
- 输出**截断**并标注原始长度（截断要保留最有信息量的部分：
  shell 保尾部，文件保头部 + 省略标记）

**降级**：超时不抛异常给用户，而是返回 `{ ok: false, error, partial }`，
⚠️ **让模型能看到部分结果**（比如 shell 超时但已经产出了编译错误）。

**已知边界**：

- ❌ 不做 `delete_path`（危险且少用；需要时由用户手工删）
- ❌ 不做全文搜索（grep 全盘慢且容易越界）
- ❌ 不做交互式命令（无法喂 stdin）

## 模块 06 · Skill 加载与执行

**职责**：发现本地技能包，把匹配的 Skill 说明注入上下文，并执行 Skill 自带脚本。

**目录约定**：

```
data/skills/<name>/
├── SKILL.md        # 必需
├── scripts/        # 可选
└── references/     # 可选
```

**`SKILL.md` 格式**：

```markdown
---
name: pdf-report
description: 当用户要生成 PDF 报告时使用
version: 1.0.0
---

# PDF 报告生成

步骤：
1. …
2. …
```

**关键约束**：

- `description` 是**触发条件描述**，要写给模型看（跟工具描述同理）
- 匹配用 `description` 的向量相似度，
  ⚠️ **不写绝对阈值**（不同嵌入模型的「不相关」基线差很多）→ 只做相对排序取 top N
- ⚠️ **Skill 脚本走同一套工具入口 + 权限闸** —— **不能绕过确认**
- 安装 / 卸载 / 更新都要**热生效**（不用重启）
- Skill 脚本 = **任意代码执行** → 安装时显式提示，且脚本工具默认 `high` 档

**降级**：

| 情况                | 行为                                        |
| ------------------- | ------------------------------------------- |
| `SKILL.md` 格式错  | 跳过该 Skill + 在 UI 上报告（不静默）      |
| 向量服务不可用      | 退回关键词匹配（名称 / 描述包含）           |
| Skill 脚本执行失败  | 错误回灌给模型，模型自己决定下一步         |

**已知边界**：

- ❌ 不做 Skill 的依赖安装（脚本要用什么得自己 ready）
- ❌ 不做 Skill 的版本升级 / 回滚
- ❌ 不做 Skill 之间的依赖关系
