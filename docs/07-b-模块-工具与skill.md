## 模块 04 · 工具注册表 ★

**职责**：把三种来源的工具汇成**模型看到的一池工具**，并保证它们走同一条执行入口。

**输入**：`builtin` 工具集 + `skill` 目录扫描 + `mcp` server 连接结果
**输出**：工具定义数组（名称 / 描述 / 入参 schema / 敏感档 / 实现 / 来源 / 执行后端）

**关键约束**：

- ⚠️ **唯一入口**（`tools/registry.ts`）—— 工具执行**必须**经由
  `agent/tool-node.ts`，
  ⚠️ **不许在图节点里直接 `await tool.invoke()`**（绕过权限闸 = 开后门）
- 工具名**全局唯一**：冲突时 Skill / MCP 工具改名或拒绝注册，**并报告**，
  ⚠️ **不静默覆盖内置工具**；冲突详情打进**启动日志**
- 禁用 / 不可用的工具**不进工具池**（模型看不见）
- ⚠️ **描述不缓存到进程**（改描述要下一轮就生效 —— 这是「调教模型」的主要抓手）
- 三种来源的**元信息统一**：模型看到的不该有差别（来源信息只给用户看）

### 工具池裁剪（本期实现，对标 Hermes 的 toolset）

- 工具全量（12 内置 + Skill + MCP）可能到几十个 → **模型选错工具**
- 裁剪发生在**调用模型之前**：按「工具名 + 描述」与**用户当前问题**的相关度打分，
  只给模型 top N（``.env` 的 `MAX_TOOLS_PER_TURN``，默认 12）
- ⚠️ **低档基础工具始终保留**（`read_file` / `list_dir` / `current_time`）
  —— 否则模型连「读个文件」都做不了
- ⚠️ **不写死相似度阈值**（不同分词器基线差很多）→ 只做**相对排序**
- 裁剪结果**要能看到**（记进 `traces.tools_used`），否则「模型没调那个工具」会变成灵异事件

**降级**：

| 情况                 | 行为                                     |
| -------------------- | ---------------------------------------- |
| MCP server 断了      | 该 server 的工具从池里移除，其余不受影响 |
| Skill 目录读不到     | 跳过该 Skill，其余正常                   |
| 某个工具 schema 非法 | 跳过该工具 + 告警（**不让整个池挂掉**）  |
| 相关度打分失败       | 退回**全量工具池**（宁可多给也不给少）   |

**已知边界**：

- ❌ 不做工具的版本管理
- ❌ 不做「按用户角色过滤工具」（本地单用户没有角色）

**本期做到哪（2026-10）**：✅ 模块 04 已落地
（`tools/registry.ts` + `tools/selection.ts` + `tools/types.ts`）——
**三个来源都接上了**：`builtin`（内置）· `skill`（技能）· `mcp`（外部 server）。
⚠️ **裁剪结果还没记进 trace** —— trace 本身还没做。

## 模块 05 · 内置工具实现

**职责**：12 个通用工具的实现（文件 / 目录 / 搜索 / 命令 / 网络 / 浏览器 / 沙箱 / 时间）。

**清单**（对齐 Hermes 的能力面，见 [12-c C2](./12-c-需求-工具技能与扩展.md)）：

> 📌 **本期做到哪（2026-11）**：**12 / 12 已落地** ——
> 文件 5 个 · `shell` · 网络 3 个 · `browser` · `execute_code` · `current_time`。

_文件与目录（5）_

| 工具           | 敏感档   | 关键实现约束                                                   |
| -------------- | -------- | -------------------------------------------------------------- |
| `read_file`    | normal   | 路径沙箱；行范围；大文件截断；编码探测（UTF-8 优先，失败回退） |
| `write_file`   | **high** | 路径沙箱；覆盖写要显式 `overwrite`；自动建父目录（可选）       |
| `list_dir`     | low      | 不递归；分页；区分文件 / 目录；隐藏项可选显示                  |
| `search_files` | low      | 路径沙箱；glob + 文本匹配；默认排除 `node_modules` / `.git`    |
| `delete_path`  | **high** | 路径沙箱；**不可撤销**；不跟随软链；工作区根不可删             |

_执行（1）_

| 工具    | 敏感档   | 关键实现约束                                                                   |
| ------- | -------- | ------------------------------------------------------------------------------ |
| `shell` | **high** | 超时杀进程；输出截断（**保尾部**）；跨平台（`cmd /c` vs `/bin/sh -c`）；黑名单 |

_网络（3）_

| 工具           | 敏感档 | 关键实现约束                                                        |
| -------------- | ------ | ------------------------------------------------------------------- |
| `http_request` | normal | 出网校验（**含重定向逐跳校验**）；超时；大小上限；只允许 http/https |
| `web_fetch`    | normal | 同上 + HTML→正文提取；正文大小上限                                  |
| `web_search`   | normal | ⚠️ **没配搜索后端就不注册**；结果条数上限；超时                     |

_浏览器（1）_

| 工具      | 敏感档   | 关键实现约束                                                                |
| --------- | -------- | --------------------------------------------------------------------------- |
| `browser` | **high** | Playwright；navigate/click/type/read/screenshot；域名白名单；超时；会话复用 |

_沙箱代码（1）_

| 工具           | 敏感档   | 关键实现约束                                                                      |
| -------------- | -------- | --------------------------------------------------------------------------------- |
| `execute_code` | **high** | 受限**子进程**跑 JS；⚠️ **可通过 RPC 调其他工具**；默认无网络；cwd 受限；超时强杀 |

_时间（1）_

| 工具           | 敏感档 | 关键实现约束       |
| -------------- | ------ | ------------------ |
| `current_time` | low    | 纯本地计算，不出网 |

### `execute_code` 的实现约束（Hermes 招牌能力，重点）

- **目的**：让模型写一段 JS，脚本内通过 **RPC 调其他工具**，
  ⚠️ **中间结果不进对话上下文** —— 只把最终输出带回来。
  一次推理完成多步管线，且上下文开销接近 0
- ⚠️ **沙箱不能用 Node 的 `vm` 模块** —— `vm` 不是安全边界
  （能拿 `require` 就等于拿到系统）
- 必须用**子进程 + 受限环境**：
  - 不给网络（除非显式放行）
  - `cwd` 限制在工作区
  - 不传 `NODE_OPTIONS` / 不继承敏感环境变量
  - 超时**强杀**整个进程组
- ⚠️ **在文档与代码注释里写明**：这是防「模型手滑写出破坏性脚本」的护栏，
  **不是**防有人故意投毒的强隔离
- ⚠️ **脚本里的 RPC 调用同样走权限闸** —— 高危工具照样要确认

**共用约束**：

- 所有文件路径**先 resolve（含 symlink）再判沙箱**
- 所有入参有长度 / 数量上限
- 所有工具**统一超时**（``.env` 的 `TOOL_TIMEOUT_MS``；
  ⚠️ `browser` / `execute_code` 可单独放宽到 120 秒）
- 输出**截断**并标注原始长度（截断要保留最有信息量的部分：
  shell 保尾部，文件保头部 + 省略标记）

**降级**：超时不抛异常给用户，而是返回 `{ ok: false, error, partial }`，
⚠️ **让模型能看到部分结果**（比如 shell 超时但已经产出了编译错误）。

**已知边界**：

- ❌ 不做交互式命令（无法喂 stdin）
- ❌ 不做语音转写（STT）
- ❌ 不做图像编辑（inpainting）
- ❌ 不做 DOM 级浏览器操作（只到 click/type/read）
- ❌ 不做 Git 操作

## 模块 06 · Skill 加载与执行（含自演化）

**职责**：发现本地技能包，把匹配的 Skill 说明注入上下文，执行 Skill 自带脚本，
**并在干完复杂任务后自动沉淀出新的 Skill**（对标 Hermes 的 self-evolution）。

**目录约定**：

```
data/skills/<name>/
├── SKILL.md        # 必需
├── scripts/        # 可选
└── references/     # 可选
```

**`SKILL.md` 格式**（对齐 [agentskills.io](https://agentskills.io) 开放格式）：

```markdown
---
name: pdf-report
description: 当用户要生成 PDF 报告时使用
version: 1.0.0
enabled: true
sensitivity: high
autoCreated: false
---

# PDF 报告生成

步骤：

1. …
2. …
```

**关键约束**：

- `description` 是**触发条件描述**，要写给模型看（跟工具描述同理）
- 匹配用 **FTS5 全文检索**（`name` + `description` + 正文摘要），
  ⚠️ **不写绝对阈值** → 只做相对排序取 top N
- ⚠️ **Skill 脚本走同一套工具入口 + 权限闸** —— **不能绕过确认**
- Skill 脚本 = **任意代码执行** → 拷目录时终端显式提示，且脚本工具默认 `high` 档
- ⚠️ **手工拷目录 / 删目录 → 重启后生效**（不是常驻 watcher）
  —— 但**运行期由 Agent 自己新建 / 改写的技能立刻可命中**（写盘后同步重建 FTS 索引）

### 6.1 · 运行时自演化（自动沉淀技能）

**触发**：每轮对话结束后，**异步**问模型一句
「这轮有没有值得沉淀成技能的经验？」（⚠️ **不阻塞本轮回答**）

**两个新工具**（走统一入口与权限闸）：

- `skill_create` —— `name` · `description` · `body` ·（可选）`scripts`
- `skill_update` —— `name` · 新正文（改进已有技能）

**写盘流程**：

1. 校验 `name` 合法（kebab-case，不与已有技能重名）
2. 校验 frontmatter 格式
3. ⚠️ **写盘前过一遍危险内容检查**
   （`rm -rf` / `curl | sh` / 「忽略之前指令」这类）
   —— **模型写的技能也是不可信内容**，不能直接落盘
4. 写入 `data/skills/<name>/SKILL.md`（**原子写**：临时文件 + `rename`）
5. 写审计 `SKILL_AUTOCREATED` / `SKILL_AUTOUPDATED`

**节制机制**（防止无限自演化）：

- 每轮**最多自动创建 1 个**技能
- 同一技能 **24 小时内不重复自动更新**
- ``.env`的`SKILL_AUTOCREATE_ENABLED` = false` → 完全关闭
- 自动创建的技能 frontmatter 标 `autoCreated: true`，
  **注入时在描述前加一行**「（自动沉淀，未经人工确认）」——
  让模型知道这条描述可能不准
- 人工编辑过 → `autoCreated` 去掉

**降级**：

| 情况                   | 行为                                          |
| ---------------------- | --------------------------------------------- |
| `SKILL.md` 格式错 / 技能名冲突 | **启动失败并报告**（不静默跳过 —— 猜不出该用哪个） |
| FTS5 不可用            | 退回覆盖率打分（`lib/text.ts` 的 `scoreRelevance`） |
| Skill 脚本执行失败     | 错误回灌给模型，模型自己决定下一步            |
| 自动沉淀被安全检查拦下 | 跳过写入 + 记 warn + 回灌「这次没能沉淀」     |

**已知边界**：

- ❌ 不做 Skill 的依赖安装（脚本要用什么得自己 ready）
- ❌ 不做 Skill 的版本升级 / 回滚
- ❌ 不做 Skill 之间的依赖关系
- ❌ 不做自动沉淀的「质量评估」（只有危险内容检查，没有效果验证）

### 6.2 · 实现状态（2026-10 已落地）

> **代码落点**：`src/skills/`
>
> | 文件            | 职责                                                     |
> | --------------- | -------------------------------------------------------- |
> | `types.ts`      | `SkillMeta` / `Skill` 与名字格式                          |
> | `frontmatter.ts`| frontmatter 解析与渲染（**YAML 的极小子集**，不引依赖）      |
> | `store.ts`      | 发现 / 读 / 写 / 改写 + **写盘前安全检查** + 索引重建      |
> | `match.ts`      | FTS5 匹配（不可用 → 退回覆盖率打分）                       |
> | `inject.ts`     | 组装注入系统提示词的那段（`{{skills}}`）                   |
> | `tools.ts`      | `skill_create` / `skill_update` / `skill_<名字>`（脚本）    |
> | `autocreate.ts` | 自演化（门槛 / 节制 / 冷却 / 落盘）                       |

**与本文档的三处差异**（**实现有意为之**）：

1. ⚠️ **技能名必须与目录名一致** —— 不一致就算**名字冲突**，
   **启动直接失败并报告**（而不是「跳过一个坏技能」）。
   理由：两个技能同名时，「该用哪个」是猜谜 —— 与其猜不如起不来。
2. 📌 **frontmatter 的 `name` 是必填的身份**，
   `autoCreated` / `autoUpdatedAt` 是实现加的两个字段
   （人工删掉 `autoCreated` 那一行 = 解除「自动沉淀」标记）。
3. 📌 **注入是「命中才注入」** —— 技能正文受条数（`SKILL_TOP_K`）
   与 token 预算（`SKILL_TOKEN_BUDGET`）双重裁剪，
   没命中就整段不出现（不留占位文字）。

**中文匹配的实现细节**（**本条需求最大的技术点**）：

- SQLite FTS5 的 `trigram` 分词器**按 3 个字符切** →
  「周报」这种 2 字词**没法作为查询短语**（不足 3 字符切不出 token）
- → **索引侧与查询侧都做「二元组 + 空格」展开**（`src/lib/text.ts` 的 `expandForTrigram`）：

  ```
  索引：「写周报时使用」 → 写周 周报 报时 时使 使用
  查询：「帮我写一份周报」 → 帮我 助写 写一 一份 份周 周报
  ```

  二者都能切出 trigram → **2 字中文词也能命中**
- 📌 **只做相对排序**（bm25）—— **不写死相似度阈值**
- ⚠️ **索引侧与查询侧必须用同一个展开函数** —— 两边不一致就永远对不上
