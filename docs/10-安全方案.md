# 10 · 安全方案

> 本项目的安全边界**比一般 SaaS 更要紧**：Agent 能读文件、跑命令、发请求。
> 需求侧见 [12-e E4](./12-e-需求-观测安全与验收.md)，模块侧见 [07-f](./07-f-模块-安全与全栈.md)。

## 10.1 威胁模型

| 威胁                  | 来源                         | 后果                     | 对策                                      |
| --------------------- | ---------------------------- | ------------------------ | ----------------------------------------- |
| **提示词注入**        | 文件 / 网页 / 工具返回内容   | 模型执行了不该执行的动作 | 工具结果标不可信 + 危险工具要确认         |
| **命令注入 / 误执行** | 模型生成命令                 | 破坏本机数据             | 默认确认 + 黑名单 + 沙箱工作目录          |
| **路径逃逸**          | 模型传 `../../etc/passwd`    | 读到不该读的文件         | resolve（含 symlink）+ 沙箱判定           |
| **SSRF**              | 模型指定内网地址             | 探测内网 / 读云元数据    | 出网校验（私网 + 元数据 + 重定向逐跳）    |
| **密钥泄露**          | 日志 / 工具出参 / 错误栈     | 凭据外泄                 | 加密存储 + 打码 + 不返回堆栈              |
| **资源耗尽**          | 死循环 / 超大文件 / 高频调用 | 烧钱 / 占满磁盘          | 步数上限 + 单轮预算 + 工具超时 + 输出截断 |
| **供应链**            | 第三方 Skill / MCP server    | 任意代码执行             | 默认确认 + 安装提示 + 按 server 授权      |
| **端口暴露**          | 本机服务被局域网访问         | 未授权使用               | 默认只听 `127.0.0.1` + 非回环时红色告警   |

## 10.2 边界划分

### 平台级（`.env`，用户改不了）

| 项                     | 默认        | 说明                                          |
| ---------------------- | ----------- | --------------------------------------------- |
| `HOST`                 | `127.0.0.1` | ⚠️ **默认只听本机**；改非回环时启动打红色告警 |
| `ALLOW_PRIVATE_EGRESS` | `false`     | 允许指向私网的出网（要显式开）                |
| `COST_BUDGET_BLOCK`    | `false`     | 超预算是否硬拦                                |

### 用户可配（代码常量 `.env`）

`WORKSPACE_ROOT` · `SHELL_ENABLED` · `TOOL_CONFIRM_LEVEL` · `ALLOW_PRIVATE_EGRESS` ·
`MEMORY_ENABLED` · 预算类项

> ⚠️ **没有「脱敏开关」**：脱敏是「写进历史库前的最后一道防线」，
> 能关就等于允许把身份证明文存库。
> ⚠️ 但**出网私网开关和 shell 开关是给用户的** ——
> 这两项本来就是「这台机器上我自己的机器」的决定，不是平台的安全承诺。

## 10.3 认证与会话

⚠️ **本期没有鉴权**（见 [12-a A1](./12-a-需求-应用外壳与上下文.md)）——
没有账号、没有 JWT、没有登录失败锁定。

**替代的防线是「边界收窄」**：

| 措施                    | 说明                                                           |
| ----------------------- | -------------------------------------------------------------- |
| **默认只听回环**        | `HOST=127.0.0.1`；局域网访问不到                               |
| **非回环时红色告警**    | 启动日志明确写出「局域网内任何人都能执行命令」                 |
| **CORS 只允许本机来源** | 浏览器侧挡一层（不是安全边界，只是防误用）                     |
| **没有账号体系**        | 没有「猜密码」这一类攻击面；也没有「谁干的」可查 —— 靠审计日志 |

> ⚠️ **「无鉴权」不等于「无边界」**：
> 这个服务能执行命令、读文件、发请求 —— **它必须只在自己机器上跑**。
> 想在局域网用，先想清楚同一个网段里都有谁。
> ⚠️ **审计日志更重要了**（没有账号就不知道谁干的）——
> 工具调用、配置变更、记忆删除都留痕。

## 10.4 文件系统安全

```
所有文件工具的路径：
  ① 规范化（resolve，⚠️ 含 symlink）
  ② 判是否在 workspace_root 内
  ③ 越界 → 明确报错
```

- ⚠️ **必须 resolve symlink** —— 只做字符串前缀判断的话，
  工作区里放一个指向 `/etc/passwd` 的软链就出去了
- ⚠️ **路径本身要查**：`../`、绝对路径、null 字节、超长路径
- 写文件默认要确认（`high` 档）
- **工作区根目录可配**，⚠️ 改这个配置要在 UI 上明确提示「会改变文件工具能碰到的范围」

## 10.5 出网安全

```
http_request：
  ① 协议只允许 http / https
  ② 解析目标域名 → IP
  ③ 判 IP 是否属私网 / 回环 / 链路本地 / 云元数据
  ④ 请求（带超时）
  ⑤ 遇到重定向 → 对新地址回到 ②（逐跳校验）
```

- 拒绝网段：`127.0.0.0/8` · `10/8` · `172.16/12` · `192.168/16` · `169.254/16` ·
  `::1` · `fc00::/7` · `fe80::/10`
- 云元数据：`169.254.169.254`（AWS/GCP/阿里云）· `metadata.google.internal`
- ⚠️ **DNS rebinding**：校验用的 IP 与实际连接的 IP 要一致
  - 📌 **现状（2026-11-01）**：`assertEgressAllowed` 解析一次 DNS 做判定，
    **随后 `fetch(url)` 自己会再解析一次** —— 中间有一个 TOCTOU 窗口，
    **校验过的 IP 从未被钉住**。
  - ⚠️ **要真正关上**：得让请求**直接连那个校验过的 IP**（Host 头另设），
    而不是让 HTTP 客户端重新解析。**本期没做**。
- ⚠️ **重定向逐跳校验** —— 只校验第一跳 = 换个 `Location` 就出去了
- 要指本机服务（本地 MCP server / 本机推理服务）→ 显式开 `allow_private_egress`

### 10.5.1 模型端点也是出网 ⚠️

> 📌 **`LLM_BASE_URL` 与出网工具的口径不同** —— 那道闸管的是「模型主动发起的请求」，
> 这道闸管的是「**用户自己配的模型服务地址**」。

```
LLM_BASE_URL：
  ① 协议只允许 http / https
  ② 主机名不能是云元数据域名
  ③ IP 字面量：链路本地 / 0.0.0.0/8 / 组播 → 拒
  ④ ⚠️ 回环放行（本机跑的服务就住在 127.0.0.1）
  ⑤ ⚠️ 私网自建放行（NAS 上的推理机）
  ⑥ 每次调用前再解析一次 DNS → 解析到被禁地址也拒
```

- 拒：`169.254.0.0/16`（含 `169.254.169.254`）· `100.100.100.200`（阿里云）·
  `metadata.google.internal` · `fe80::/10` · `0.0.0.0/8` · `224+/4`
- ⚠️ **启动时校验一次**（静态）→ **每次调用前再校验一次**（带 DNS）
- 📌 **本地端点可以没有 API Key**（回环 + 缺 Key → 放行）
- 实现：`src/lib/security/model-endpoint.ts`

### 10.5.2 浏览器与沙箱代码 ⚠️

| 能力            | 边界                                                                     |
| --------------- | ------------------------------------------------------------------------ |
| **浏览器**      | `high` 档默认要确认 · **域名白名单**（`BROWSER_ALLOWED_DOMAINS`）· **每个请求都过一遍**（重定向、子资源一样）· 云元数据地址一律禁 |
| **沙箱代码**    | `high` 档默认要确认 · **子进程**（超时强杀）· `vm` 独立上下文（**没有 `require` / `process` / `fetch`**）· **只准调不需要确认的工具** |

- ⚠️ **Node 的 `vm` 不是安全沙箱** —— 它防的是「模型手滑写出破坏性脚本」，
  **不是防有人故意投毒**
- ⚠️ **`vm` 的经典漏洞**：`this.constructor.constructor('return process')()`
  能拿到宿主的 `process` → 沙箱对象**必须无原型** + **禁字符串生成代码**
- ⚠️ **但「禁字符串生成代码」只管上下文自己的 `Function`** —— 它管不到
  **从宿主传进来的函数**。所以暴露给脚本的 `atlas` / `console` / 定时器
  **必须全部在上下文 realm 里创建**，宿主实现只作为**闭包变量**被捕获；
  否则 `atlas.call.constructor('return process')()` 照样能逃出去
  （⚠️ **2026-11-01 修的** —— 之前就是这么写的，真能拿到宿主 `process`）。
  同理还有三处：返回值**深拷贝** · 异常**在上下文里重建** · 定时器句柄**换成数字**
- ⚠️ **沙箱里只准调不需要确认的工具** —— 否则「批准一次跑脚本」
  就等于批准脚本里的所有危险动作（确认闸形同虚设）

## 10.6 命令执行安全

- **默认「需确认」**（`high` 档）
- **黑名单直接拒绝**（不给确认的机会）：
  `rm -rf /` · `mkfs` · `dd if=` · `shutdown` · `reboot` · `:(){:|:&};:` · `curl | sh`
- ⚠️ **黑名单在「策略层」判**（`decideTool()` 看得到入参）——
  不是在工具内部判：内部判的话用户会**先看到确认卡片**，
  批准之后才被告知「其实不让跑」
- 黑名单可扩展
- 超时杀进程（默认 30 秒）
- ⚠️ **工作目录也在路径沙箱里** —— `cwd` 传 `/etc` 或 `../..` 一律拒绝
  （⚠️ **2026-11-01 补的** —— 以前只判了「命令参数里的路径」，`cwd` 是漏的）
- ⚠️ **子进程环境变量走白名单** —— `shell` / 技能脚本 / 沙箱一律
  **不继承 `process.env`**（否则一句 `printenv LLM_API_KEY` 就把密钥读出来；
  ⚠️ **2026-11-01 补的**）
- ⚠️ **黑名单是兜底不是主防线** —— 主防线是「默认要确认」

## 10.7 提示词注入

| 层次     | 做法                                                                |
| -------- | ------------------------------------------------------------------- |
| **标注** | 工具返回内容在回灌时明确标为「不可信数据，不能当指令执行」          |
| **隔离** | 工具结果进 `tool` 角色，不进 system                                 |
| **检测** | 用户消息与工具结果过注入检测                                        |
| **处置** | ⚠️ **命中只告警 + 收紧工具档，不直接拒答**（误报会让 Agent 变哑巴） |
| **兜底** | 危险工具无论如何都要人确认 —— **注入检测失效也不至于出事**          |

> ⚠️ **最后一条是关键**：安全不能只靠检测。
> 检测是概率性的，**确认闸门是确定性的**。
>
> ⚠️ **收紧必须发生在「权限闸」里**（⚠️ **2026-11-01 修的**）——
> 以前只收紧了「给模型看的那份副本」，而权限闸读的是**注册表里的原定义**，
> 那个控制等于**从没生效过**。

## 10.8 密钥与数据

| 数据         | 处理                                                |
| ------------ | --------------------------------------------------- |
| 模型 API Key | **只存 `.env`**（不入库）；不落库、不写日志、不回显 |
| 日志 / 流水  | 密钥类字段打码                                      |
| 工具输出     | 落库前截断；密钥类字段打码                          |
| 对话内容     | 明文存本地（用户自己的机器）                        |
| 文件内容     | 不复制进 DB（只存路径与工具出参）                   |

> ⚠️ **`.env` 不进 git**；`.env.example` 里 secret 行留空
>
> ⚠️ **打码不能只靠正则** —— 正则只认常见形态（`sk-` / `Bearer` / `AKIA` / `api_key:`），
> 供应商自己的格式一条都不匹配（本项目在用的智谱 key 是 `32位hex.16位base62`）。
> 所以启动时按配置里的**真值登记**一份，打码时**按精确值替换**
> （⚠️ **2026-11-01 补的** —— 之前智谱 key 是**裸着进流水与日志**的）。

## 10.9 审计

写 `audit_logs` 的动作：

| action                          | 触发                   |
| ------------------------------- | ---------------------- |
| `MODEL_CREATED/UPDATED/DELETED` | 增删改模型配置         |
| `PROMPT_PUBLISHED/ROLLED_BACK`  | 发布 / 回滚提示词      |
| `SKILL_INSTALLED/REMOVED`       | 装 / 卸 Skill          |
| `MCP_CONNECTED`                 | 接上一个 MCP server    |
| `TOOL_ENABLED/DISABLED`         | 工具启停               |
| `MEMORY_DELETED`                | 删记忆                 |
| `WORKSPACE_ROOT_CHANGED`        | 改工作区根目录 ⚠️ 高危 |
| `SETTINGS_UPDATED`              | 改通用配置             |

- ⚠️ **`details` 里绝不记密钥明文**
- ⚠️ **「用户点了批准」也要记**（谁在什么时候批准了哪个命令）

## 10.10 已知边界

- ⚠️ **本地项目没有网络隔离**：服务只听 `127.0.0.1`，但用户可能改成 `0.0.0.0`
  → 改成局域网暴露时，UI 上要提示风险
- ⚠️ **注入检测是概率性的**，不能当唯一防线
- ⚠️ **命令黑名单可被绕过**（编码、变量展开、别名）→ 靠确认闸门兜底
- ⚠️ **Skill 脚本 = 任意代码执行**，装之前用户要知情
- ⚠️ **`AGENTS.md` / `SOUL.md` 能被 `read_file` 读**（只读口子）——
  它们是项目指令与人格，不含密钥；**写 / 删仍然越界**
- ⚠️ **沙箱代码不是强隔离**（`vm` 的天花板）—— 防手滑，不防投毒
- ❌ 不做内容 DLP（只管地址与密钥，不管业务内容）
- ❌ 不做端到端加密（本地单用户）
