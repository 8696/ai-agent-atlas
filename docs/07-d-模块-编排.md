## 模块 10 · LangGraph 图 ★

**职责**：定义对话的**状态机** —— 什么时候调模型、什么时候调工具、什么时候停。

**图形状**：

```
prepare → plan ─┬─(要工具)→ tools ─┐
                 │                   │
                 │                   └──→ plan（可循环，受步数上限约束）
                 │                        或 → tools（同一批还有下一个调用）
                 │
                 └─(直接答)→ answer → END
```

> 📌 **落地版（2026-10）**：
> - **`prepare` 节点**：每轮开头把图状态对齐到前端的历史
>   （`RemoveMessage(REMOVE_ALL_MESSAGES)` + 重写）——
>   「重新生成」要把状态里那条砍掉，否则模型会看到一条已经不存在的回答
> - **没有 `recall` 节点** —— 长期记忆还没做（[D2](./12-d-需求-记忆与配置.md)）
> - **没有 `finalize` 节点** —— 落库在**网关层**做（parts 必须与推给前端的 chunk 同源）
> - **`tools` 一次只处理一个调用** —— 见 [03-b §B.5.4](./03-b-技术栈-后端栈.md)

**状态字段**（`agent/state.ts`，用 `Annotation.Root` 声明）：

| 字段                | 说明                                      | reducer |
| ------------------- | ----------------------------------------- | ------- |
| `messages`          | 消息序列（含 tool 角色）                  | 追加    |
| `turnMessages`      | 本轮输入（前端的历史）—— `prepare` 写回 `messages` | 覆盖 |
| `executedToolCalls` | 本轮已执行的工具调用 id                   | 覆盖    |
| `lastToolName`      | 上一个工具名（算「连续」次数）            | 覆盖    |
| `lastToolCount`     | 上一个工具连续被调了几次                  | 覆盖    |
| `rejectedToolCalls` | 用户拒绝过的工具调用指纹（⚠️ 防重复追问） | 覆盖    |
| `steps`             | 已走步数（**循环上限靠它**）              | 覆盖    |
| `budgetUsed`        | 已用 token（随检查点持久化）              | 累加    |
| `notice`            | 要传给前端的提示（如「已达步数上限」）    | 覆盖    |
| `haltReason`        | 停下来的原因（非空 = 直接进 `answer`）    | 覆盖    |
| `finalText`         | 本轮最终正文                              | 覆盖    |
| `sessionId`         | 会话 id（写工具流水用）                   | 覆盖    |
| `messageId`         | 这一轮的 assistant 消息 id（**恢复时不变**）| 覆盖  |
| `memories`          | 本轮召回的记忆                            | 覆盖    |
| `command`           | 本轮解析出的斜杠命令（⚠️ **命令不进图**） | 覆盖    |
| `subagents`         | 本轮派发的子代理结果摘要                  | 追加    |

**关键约束**：

- ⚠️ **节点里不写业务逻辑** —— 节点只做「取输入 → 调 service/tool → 写 state」
- ⚠️ **循环必须有上限**：`steps` 超限 → 直接进 `answer` 并写 `notice`
- ⚠️ **同一个工具连续重复调用有额外限制**（默认 2 次）—— 这是模型陷入循环时唯一的刹车
- 条件边**只做路由**，不做事
- ⚠️ **不用 LangGraph 的预制 Agent 快捷方式**
  （`createReactAgent` / `AgentExecutor`）——
  本项目要的恰恰是**图的可控性**（精确的中断点、循环上限、事件映射），
  快捷方式一旦不够用就得重写，那时成本更高

**降级**：

| 情况           | 行为                                            |
| -------------- | ----------------------------------------------- |
| 模型调用失败   | 重试（带抖动）→ 备用模型 → 抛错（已吐内容保留） |
| 工具执行抛异常 | 转成文本回灌给模型，**不中断整轮**              |
| 步数超限       | 进 `answer`，说明「已达步数上限」               |
| 预算超限       | 进 `answer`，说明「超出预算未执行」             |

**已知边界**：

- ❌ 不做子图复用（主图是一张；子代理是**独立实例**，不是子图）
- ⚠️ **工具是串行的** —— 一次节点执行一个工具（换来「恢复不重跑」）
- ⚠️ **跨轮的上下文靠数据库，不靠检查点** ——
  工具结果只在**本轮**回灌给模型；下一轮模型看到的是上一轮的**回答正文**

**本期做到哪（2026-10）**：✅ 模块 10 / 11 / 12 的**主干**已落地
（图 · 工具节点与权限闸 · 事件翻译）；斜杠命令 / 子代理 / 定时任务三条路径还没做。
- ❌ 不做条件分支的动态生成（图形状是静态的）

### 10.1 · 斜杠命令（进图之前）★

**职责**：解析 `/` 开头的输入，**不进模型、不花 token**。

```
用户输入 → command.parse() ─┬─ 是已知命令 → 执行副作用 → 返回命令结果气泡（不进模型轮次）
                             ├─ 是未知命令 → 「未知命令 /xxx，/help 看全部」（**不发模型**）
                             └─ 不是命令   → 正常进图
```

**关键约束**：

- ⚠️ **命令在服务端解析**（不是前端拦截）—— 历史重放、多端一致
- ⚠️ **命令不产生任何 LLM 调用**（零 token 消耗）
- ⚠️ **未知命令绝不退化成普通消息** —— 否则白白调一次 LLM，还可能触发工具
- 命令结果用**独立气泡样式**渲染，**不进消息历史里的模型轮次**
- `/model` / `/personality` 的切换只改**当前会话**的运行时状态
- ⚠️ **`/reset` 只清上下文，不删会话记录**（消息表保留，工具流水保留）
- 命令表放 `lib/commands.ts`（前端补全用同一份），实现放 `services/command.ts`

**已知边界**：

- ❌ 命令不能组合（`/model x /usage` 不支持）
- ❌ 不做命令的参数解析器（参数一律按空格切字符串）

### 10.2 · 子代理（隔离子图实例）★

**职责**：让主 Agent 把子任务派给**独立上下文**的子代理并行执行。

```
主图 plan 节点 → spawn_subagent 工具 → 起一个独立图实例
                                    ├─ 独立 thread_id
                                    ├─ 独立上下文（只有 task + 少量传入）
                                    ├─ 共用工具池与权限闸
                                    └─ 跑完 → 摘要（≤ 2000 字符）→ 回灌主图
```

**关键约束**：

- ⚠️ **子代理是独立图实例**，不是主图的子图 ——
  **不共享主对话历史**，只拿到 `task` + 主 Agent 传的那点上下文
- ⚠️ **摘要必须有长度上限**（默认 2000 字符）——
  子代理的原始过程回灌主上下文会撑爆预算
- **并发控制**：``.env` 的 `SUBAGENT_MAX_CONCURRENCY``（默认 3）——
  超过上限**排队**，不报错
- **步数上限**：``.env` 的 `SUBAGENT_MAX_STEPS``（默认 8），子代理独立计数
- ⚠️ **子代理不得绕过人工确认** —— `shell` 等高危工具在子代理里照样要确认
- ⚠️ **子代理的 trace 独立**（`kind='subagent'`），不挂主对话 trace ——
  主 trace 的 duration 保持「用户感知耗时」（用户看到的是主 Agent 在等）
- ⚠️ **子代理的花费计入主对话预算**（同一场对话的一部分）
- 派发本身是一次**普通工具调用**（走统一入口与权限闸）

**降级**：

| 情况             | 行为                                             |
| ---------------- | ------------------------------------------------ |
| 子代理跑失败     | 错误摘要回灌主 Agent（不中断主轮）               |
| 并发超上限       | 排队等待（不报错）                               |
| 子代理要人工确认 | 弹**同一张**确认卡片（用户不需要知道这是子代理） |
| 子代理步数超限   | 交出当前摘要 + 说明「已达步数上限」              |

### 10.3 · 定时任务（图之外触发）★

**职责**：到点自动跑一次完整的图。

```
cron 调度器（每分钟 tick）→ 查 data/cron.json → 到期？
  │ 是 → 起一次图（新会话或指定会话）→ 结果落会话 + 日志
  │ 否 → 跳过
```

**关键约束**：

- **任务描述存 `data/cron.json`**（文件，不是数据库、不是界面）
- **自然语言 → cron 表达式只解析一次**，解析结果存下来（不每次重解析）
  - ⚠️ 解析不出合法表达式 → **报错并保留原文**，不静默丢弃
- 走 ``.env` 的 `TIMEZONE`` 判断「今天 9 点」
- ⚠️ **进程没跑就不会触发**（本地项目不做常驻保活）；
  错过的时间点**默认跳过**，并在日志里记「错过了 N 次」
- ⚠️ **无人值守的确认闸处理**：任务里若触发高危工具要确认 →
  **跳过该步并记录**（「因需人工确认已跳过」），**不能挂死**
  - 可在任务里显式声明 `autoApprove: ["shell"]` 允许放行（⚠️ 高危，要显式写出来）
- ⚠️ **不做消息平台投递**（本期不做网关）→ 结果只落地到会话 + 日志 + 终端打印一行
- ``.env` 的 `CRON_ENABLED`` 总开关
- 触发的花费记 `usage_scope='cron'`（与主对话分开统计）

**已知边界**：

- ❌ 不做常驻保活 / 错过补偿执行
- ❌ 不做任务依赖（任务 A 完成后触发任务 B）
- ❌ 不做时区夏令时处理（用系统本地时区）

## 模块 11 · 工具节点与权限闸 ★

**职责**：执行工具调用，并在执行前跑一遍**权限策略**。

**决策四档**（`lib/security/tool-policy.ts`）：

| 结果      | 含义                        | 后续                                     |
| --------- | --------------------------- | ---------------------------------------- |
| `allow`   | 直接执行                    | 调工具，把结果回灌                       |
| `await`   | 挂起等用户确认              | `interrupt()` → 前端弹卡片 → 恢复后执行  |
| `blocked` | 禁止执行（黑名单 / 功能关） | **不执行**，原因回灌给模型               |
| `reject`  | 用户拒绝                    | **不执行**，回灌「用户拒绝」，且不再追问 |

**关键约束**：

- ⚠️ **所有工具执行必须经过这里** —— 图节点不许自己 `invoke`
- ⚠️ **interrupt 的恢复必须用 `Command({ resume })`**，
  不是「前端再发一次请求从头跑」——
  后者会把挂起前已执行的工具**再执行一遍**
- ⚠️ **模型改了参数 → 必须重新确认**（旧的批准不能沿用）
- ⚠️ **用户拒绝后不得追问第三次**（`rejected` 记进状态）
- 危险档判定顺序见 [12-c C3](./12-c-需求-工具技能与扩展.md)
- ⚠️ **MCP 工具默认 `ask`** —— 第三方来源一律要确认
- ⚠️ **子代理与定时任务走同一道闸** —— 唯一的例外是定时任务里
  显式声明的 `autoApprove` 白名单

**降级**：策略模块本身出错 → **按最严的一档处理**（`await`），
⚠️ **绝不能 fail-open**（出错就放行 = 安全闸形同虚设）。

**已知边界**：

- ❌ 不做「一次性授权本轮所有工具」
- ❌ 不做按工具粒度的授权记忆（每次都要确认）

## 模块 12 · 事件翻译与流式 ★

**职责**：把 LangGraph 的事件翻译成前端能消费的 SSE 帧。

**映射表**：

| 图事件              | SSE part                           |
| ------------------- | ---------------------------------- |
| 模型输出文本增量    | `text-delta`                       |
| 文本开始 / 结束     | `text-start` / `text-end`          |
| 工具调用发起        | `data-tool-call`（running）        |
| 工具执行完成 / 失败 | `data-tool-call`（done / error）   |
| 需要人工确认        | `data-pending-confirm`             |
| 子代理派发 / 完成   | `data-subagent`（running / done）  |
| 斜杠命令结果        | `data-command`（**不进模型轮次**） |
| 步数超限 / 预算超限 | `data-notice`                      |
| 图结束              | `finish`                           |

**关键约束**：

- ⚠️ **翻译层与图逻辑解耦**（`agent/events.ts` 单独一个文件）——
  图不许知道 SSE 的存在，将来换前端只改这一层
- ⚠️ **落库的 parts 与推给前端的同源**（同一份 part 对象序列化两次）
- 客户端断开 → **真正停止上游调用**（不是前端不再收而已）
- ⚠️ **客户端断开不算错误**（记 success）——
  否则用户自己关页面会把错误率刷高
- 心跳：长时间无输出时发注释帧保活（防代理断连）
- ⚠️ **子代理的 SSE 事件走主连接**（不单独开连接）——
  前端只看到一张「子代理卡片」，不用管它内部在跑什么

**降级**：翻译层出错 → 至少保证 `finish` 帧发出去（前端不能永远转圈）。

**已知边界**：

- ❌ 不做断线续传（刷新后靠落库的 parts 恢复，不靠重放流）
- ❌ 不做多路流并行（一个会话一次只跑一个图；子代理并行算例外）
