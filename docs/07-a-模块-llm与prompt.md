# 07-a · 模块 · LLM 与 Prompt（模块 01-03）

> AI 模块规格。每个模块写清：**职责 / 输入输出 / 关键约束 / 降级 / 已知边界**。
> 需求侧见 [12-a A3/A4](./12-a-需求-应用外壳与上下文.md)。

## 模块 01 · 模型接入与解析

**职责**：把「用户配了哪些模型」变成「这一轮该用哪个 ChatModel 实例」。

**输入**：`usage_scope`（`chat` / `memory` / `summary` / `retrieval` / `subagent` / `cron` / `skill`）
**输出**：一个可调用的 ChatModel（已带 base_url / key / 参数 / 备用模型链）

**关键约束**：

- ⚠️ **解析逻辑只能有一处**（`services/model.ts`）——
  对话 / 抽取 / 摘要 / 嵌入全从这里拿模型，
  不许各处 `new ChatAnthropic(...)`（那会让「换模型」变成全局搜索改造）
- 回落链：`用途专用模型 → 同 scope 默认模型 → 平台默认（.env）`
- 模型定义在 `.env` 的 `LLM_*`（一个 Base URL + Key + 模型标识）；API Key 启动时读进内存
  （⚠️ **不入库、不写日志、不回显**）；读不到 key → 降级到平台默认 + 告警
- 备用模型：同 scope 另一条；⚠️ **仅在「一个内容 chunk 都没吐出去」时切**
- 温度 / 输出上限 / 思考预算取模型配置，缺省取通用配置，再缺省取内置默认

**降级**：

| 情况                 | 行为                                                              |
| -------------------- | ----------------------------------------------------------------- |
| 没有可用模型         | 抛 `AppError('NO_MODEL_CONFIGURED')` → 前端显示空状态（不是 500） |
| 主模型 5xx           | 切备用模型；没有备用则重试（带抖动）                              |
| 备用也没有           | 抛错 → 对话返回明确错误，**已吐出的内容保留**                     |
| 供应商不支持思考参数 | 去掉思考参数重试一次                                              |

**已知边界**：

- ❌ 不做供应商自动探测（要填 base_url）
- ❌ 不做按负载均衡（多个同 scope 模型之间轮询）—— 那是多实例的事

## 模块 02 · 提示词组装

**职责**：把「系统人格 + 用户提示词 + 记忆 + Skill + 工具说明」拼成最终 system prompt。

**输入**：当前轮的上下文（用户消息 / 召回的记忆 / 命中的 Skill / 可用工具池）
**输出**：一段 system prompt（string 或消息数组）

**组装顺序**（⚠️ 顺序有意义，见 [06 §6.4](./06-大模型与模型解析.md)）：

```
1. 基础人格与安全边界（内置，不可被用户改）
2. 当前生效的提示词文件（用户改 `prompts/*.md`）
3. 长期记忆（按相关性召回，top N + token 双重裁剪）
4. 已命中的 Skill 说明
5. 工具使用规范（可用工具列表 + 权限档说明）
```

**关键约束**：

- ⚠️ **工具返回的内容必须标注为不可信数据**（外部内容可能含注入指令）
- 工具输出**不进 system prompt**，进 messages（作为 tool 角色）
- 提示词与工具说明**不进向量**（污染检索）
- 每次组装要记录**最终长度**（超预算要能看出来）

**降级**：记忆召回失败 → 只发 1/2/5；Skill 加载失败 → 只发 1/2/5；
⚠️ **任何一块失败都不能让整轮失败**。

**已知边界**：

- ❌ 不做提示词模板引擎（不支持嵌套 / 条件语法，只支持 `{{占位符}}`）
- ❌ 不做提示词版本对比视图

## 模块 03 · 提示词文件

**职责**：读取提示词文件、替换占位符、回落默认。

**数据**：`prompts/<name>.md`（文件，name ∈ `system` / `tool` / `memory` / `summary`）
—— ⚠️ **没有版本表、没有发布指针**；
**版本与回滚 = git**。

**关键约束**：

- ⚠️ **每次读取都要走文件系统**（每轮读）→ ⚠️ **不能缓存到进程**
  （否则改完不立即生效）
- ⚠️ **未识别的占位符原样保留** —— 清空会把用户写的模板内容吞掉
  （占位符：`{{tools}}` `{{memories}}` `{{skills}}` `{{date}}`）
- 提示词文件读不到 / 解析失败 → 回落到内置默认提示词（`src/prompts/defaults.ts`；
  ⚠️ **正常情况是「启动时写回兜底文件」**，这里是「文件存在但这次读不出来」的运行时兜底），
  **不能没有 system prompt**，并在响应里标注「用了兜底提示词」
- 启动时检测到提示词文件内容变化 → 写一条 `PROMPT_UPDATED` 审计
  （记文件路径 + 内容 hash + git commit）

**降级**：文件缺失 / 读失败 → 用内置默认，并告警。

**已知边界**：

- ❌ 不做提示词 diff 视图（用 `git diff`）
- ❌ 不做按会话固定提示词版本（历史会话回放时用当前版本 —— 这是个已知取舍）
