## B. 后端技术栈

### B.1 语言与运行时

- **Node.js ≥ 22.4**，原生 **ESM**（`"type": "module"`）
- **TypeScript 7.x**，strict 模式
- 开发用 `tsx watch`，生产用 `tsc` 编译到 `dist/` 后 `node dist/src/server.js`
- **不用** `ts-node`、不用 `nodemon`、不用装饰器元数据之外的实验特性

### B.2 框架

| 层          | 选型                                         | 说明                                          |
| ----------- | -------------------------------------------- | --------------------------------------------- |
| HTTP        | **Koa 3**                                    | 极简，洋葱模型；配 `@koa/router` 3.x          |
| 参数校验    | **zod 4**                                    | 所有入参一个 schema，出错统一 400             |
| Agent 编排  | **LangGraph.js 1.5.x**                       | ★ 本期核心，见 §B.5                           |
| 模型接口    | **LangChain Core 1.3.x**                     | ChatModel / BaseMessage / ToolSchema          |
| 供应商      | `@langchain/anthropic` / `@langchain/openai` | 都支持指 `base_url`（兼容端点）               |
| 消息流协议  | `ai` 7.x（**仅协议**）                       | 后端把图事件翻译成 UI Message Stream，见 §B.6 |
| ORM         | **Sequelize 6**                              | + `sequelize-typescript`；迁移用 **umzug 3**  |
| 驱动        | `sqlite3`                                    | Sequelize 的 sqlite 方言                      |
| 检索        | SQLite FTS5（内置）                          | ⚠️ **与业务库同库**，`trigram` 分词，见 §B.8  |
| MCP（后期） | `@langchain/mcp-adapters` + MCP SDK          | C5                                            |
| 日志        | `pino` 10 + `pino-pretty`                    | 结构化 JSON，文件落 `logs/`                   |
| ID          | `nanoid` 6                                   |                                               |
| 时间        | `dayjs` 1.11                                 |                                               |

> ⚠️ **不要在 LangGraph 节点里直接用 AI SDK 的 `streamText`**。
> 图节点要用 **LangChain 的 ChatModel**（`@langchain/core` 的接口），
> LangGraph 的 `ToolNode` / 工具绑定都基于它。
> AI SDK 在本项目只出现在**协议层**（前端 `useChat` 消费的 wire format）。

### B.3 中间件

```
请求
 │
 ├─ cors          （dev 允许 Vite 端口；生产同源）
 ├─ requestId     （生成 request id，贯穿日志与 trace）
 ├─ auth          （JWT；公开路由白名单）
 ├─ rateLimit     （按用户 + 按 IP，进程内）
 ├─ errorHandler  （AppError → 统一响应体）
 │
 ▼
路由
```

> ⚠️ **限流是进程内状态**：多实例部署时上限会放大到实例数倍。
> 本期单机单实例，可接受；要多实例得换 Redis。

### B.5 LangGraph.js 使用约定 ★

> 这是本项目与「文档问答 SaaS」最大的差别，也是最容易写歪的地方。

#### B.5.1 图的形状

```
                    ┌──────────┐
     用户输入 ────► │  recall  │ 取长期记忆，注入 state
                    └────┬─────┘
                         ▼
                    ┌──────────┐
                    │   plan   │ 调模型：回答 还是 调工具？
                    └────┬─────┘
                         │
        ┌────────────────┴─────────────────┐
        │ 要工具                            │ 直接答
        ▼                                  │
   ┌──────────┐                            │
   │  tools   │ 执行工具                   │
   └────┬─────┘                            │
        │ 危险操作 → interrupt 挂起         │
        └──────────────┬───────────────────┘
                       ▼
                  ┌──────────┐
                  │  answer  │ 流式汇总
                  └────┬─────┘
                       ▼
                  ┌──────────┐
                  │ finalize │ 落库 / 记账 / 收 trace
                  └──────────┘
```

#### B.5.2 硬性约定

1. **状态定义集中在 `agent/state.ts`**，用 `Annotation.Root` 声明，
   带 reducer 的字段（`messages`）用 `messagesStateReducer`。
2. **节点里不写业务逻辑** —— 节点只做「取输入 → 调 service/tool → 写 state」。
3. **工具执行统一走 `agent/tool-node.ts`**，不允许节点自己 `await tool.invoke()` ——
   否则权限闸（interrupt）会被绕过。
4. **循环必须有上限**：图状态里带 `steps`，超过上限直接进 `answer` 并说明「已达到步数上限」。
5. **checkpointer 必须是 SQLite 实现**（进程内 MemorySaver 不算数：
   进程一重启，对话就丢了）。
6. **interrupt 的恢复用 `Command({ resume: ... })`**，不是重新跑一遍图。
7. **图事件到 SSE 的翻译单独一层**（`agent/events.ts`），
   图逻辑不许知道 SSE 的存在。

#### B.5.3 断点恢复

- `thread_id` = 会话 id
- 进程重启后，用同一个 `thread_id` 调 `graph.invoke` / `graph.stream` 即可续跑
- ⚠️ **interrupt 挂起状态要能在重启后恢复** —— 这是 checkpointer 必须落盘的直接原因

#### B.5.4 什么**不**用 LangGraph

| 不用                                         | 用什么                      | 为什么                                     |
| -------------------------------------------- | --------------------------- | ------------------------------------------ |
| LangChain 的 `AgentExecutor` / `createAgent` | 自己写 `StateGraph`         | 要完全控制图形状、interrupt 位置、循环上限 |
| LangGraph 的 `createReactAgent` 预制 Agent   | 同上                        | 预制 Agent 的中断点不可控                  |
| LangChain 的 memory 抽象                     | 自己的 `services/memory.ts` | 记忆要可编辑、可删、可按相关性召回         |
| LangChain 的 retrieval 抽象                  | 自己的工具                  | 本期没有 RAG                               |

> ⚠️ **不要用「预制 Agent 快捷方式」**：本项目要的恰恰是**图的可控性**
> （精确的中断点、精确的循环上限、精确的事件映射）。
> 快捷方式一旦不够用就得重写，那时成本更高。

### B.6 模型调用层与消息流协议

#### B.6.1 模型解析（`services/model.ts`）

```
按用途 scope 选模型：
  chat    → 对话模型
  memory  → 记忆抽取模型（可配）
  summary → 摘要模型（可配）
回落链：用途专用模型 → 对话模型 → 平台默认（.env）
```

- 供应商：`anthropic` / `openai`（都支持 `base_url` 指兼容端点）
- 密钥：来自 `.env` 的 `LLM_API_KEY`，
  **不入库**（不落 `model_configs` 表 —— 该表已删），不写日志、不回显
- 备用模型：配了 fallback 时，**仅在「一个内容 chunk 都没吐出去」时**切 ——
  吐出去的字收不回来，重切会让重复的工具调用**真的执行两遍**

#### B.6.2 消息流协议（前端 `useChat` ↔ 后端 SSE）

前端继续用 `@ai-sdk/react` 的 `useChat`，后端必须把 **LangGraph 的事件**
翻译成 **AI SDK UI Message Stream 的 part 序列**：

| 图事件           | SSE part                            | 前端表现                 |
| ---------------- | ----------------------------------- | ------------------------ |
| 模型输出思考增量 | `reasoning-delta`                   | 正文上方的思考区逐字出现 |
| 思考开始 / 结束  | `reasoning-start` / `reasoning-end` | —                        |
| 模型输出文本增量 | `text-delta`                        | 气泡里逐字出现           |
| 文本开始 / 结束  | `text-start` / `text-end`           | —                        |
| 工具调用发起     | `data-tool-call`（status=running）  | 工具卡片「执行中」       |
| 工具执行完成     | `data-tool-call`（status=done）     | 卡片显示结果，可展开     |
| 工具执行失败     | `data-tool-call`（status=error）    | 卡片显示错误             |
| 需要人工确认     | `data-pending-confirm`              | 卡片出现「批准 / 取消」  |
| 命中步骤上限     | `data-notice`                       | 一行提示                 |
| 图结束           | `finish`                            | 结束 loading 状态        |

- 消息的 `parts` 落库 → **刷新后工具卡片还在**
- ⚠️ **协议翻译层与图逻辑解耦**：`agent/events.ts` 单独一个文件。
  将来换前端框架（不用 `useChat`）时，只改这一层
- ⚠️ **落库的 parts 与推给前端的 parts 必须同源** ——
  否则会出现「刷新后卡片内容变了」

### B.7 存储层（SQLite + Sequelize）

- **单文件库**：`data/atlas.db`
- **WAL 模式**（读写并发；默认 rollback journal 会让读写互相阻塞）
- `PRAGMA foreign_keys = ON`（Sequelize 要显式开）
- `PRAGMA busy_timeout = 5000`（写锁等待，避免瞬时 `SQLITE_BUSY`）
- 迁移用 umzug，脚本 `scripts/migrate.ts`（`yarn migrate`）
- ⚠️ **不要用 Sequelize 的 `sync({ alter: true })`** —— 生产会改坏表；
  一律走迁移
- ⚠️ **JSON 列**：SQLite 没有 JSON 类型，用 `TEXT` 存 JSON 字符串，
  读写经 Sequelize 的 `DataTypes.TEXT` + 应用层 `JSON.parse`
  （或自定义 getter/setter）

### B.8 全文检索层（SQLite FTS5）

- **与业务库同一个文件** `data/atlas.db`（`messages_fts` 要跟 `messages` 同事务写）
- 虚表：`messages_fts` / `memory_fts` / `skill_fts`
- ⚠️ **分词器必须 `tokenize='trigram'`** —— 默认 `unicode61` 不切中文，
  一整句中文被当成一个 token，搜中文等于搜不了（见 [05-b §5.2](./05-b-数据模型-全文检索.md)）
- 检索：FTS5 `MATCH` + BM25 排序（**必须参数化**，别拼查询串）
- ⚠️ **FTS5 是 SQLite 的编译期可选特性**：不可用时**服务照常启动**，
  检索降级为「按时间倒序取最近 N 条」
- ⚠️ **探测要真建表** —— 只查 `pragma_compile_options` 会漏掉
  「编了但版本太老、没有 trigram」的情况

### B.9 安全基线

| 项             | 做法                                                            |
| -------------- | --------------------------------------------------------------- |
| 密钥存储       | 只存 `.env`，**不入库**；不写日志、不回显                       |
| 路径沙箱       | 所有文件工具的路径先规范化（resolve symlink）再判是否在沙箱根内 |
| 出网校验       | 解析目标 IP → 拒私网 / 回环 / 云元数据地址；可配放行            |
| Shell 工具     | 默认「需确认」档；命令黑名单；可整体禁用                        |
| 提示词注入检测 | 用户消息与工具结果都过检测；命中只告警 + 收紧工具档，不直接拒答 |
| 密钥不落日志   | 日志脱敏（`api_key` / `authorization` / `token` 一律打码）      |

### B.9.1 路径模块（`src/config/paths.ts`）⚠️

> **所有相对路径的唯一基准** —— 详见 [02 §路径基准](./02-系统架构与目录.md)。

**职责**：

- 确定 **项目根**：`ATLAS_HOME` → 向上找 `package.json` → `process.cwd()`
- `resolvePath(p)` —— 相对路径 → 绝对路径（相对项目根）；绝对路径原样返回
- 导出标准目录与文件（`DIRS` / `FILES`）
- `ensureDirs()` —— 启动时确保标准目录存在

**关键约束**：

- ⚠️ **代码里一律用 `paths.*` 的绝对路径**，不要自己拼相对路径
  （相对路径会被相对 cwd 解析 —— 最隐蔽的 bug 是在错误位置建一个新库）
- ⚠️ **`.env` 从项目根读**（`dotenv.config({ path: FILES.env })`）——
  dotenv 默认读 `cwd/.env`，换个目录启动就读不到配置
- ⚠️ **`src/config/schema.ts` 是纯 schema**（不读 `process.env`）——
  这样 `scripts/sync-env.ts` 能安全 import 它做契约校验
  （import `src/config.ts` 会触发启动校验并 `process.exit`）

### B.10 网关层约定

- 每个路由文件一个前缀：`/api/v1/...`
- **公开路由白名单**（不需鉴权）：`/api/v1/auth/login` · `/api/v1/health`
- 其余一律要 JWT；令牌过期 401
  （⚠️ **没有「必须改密」那套 403 逻辑** —— 首启密码即最终密码，
  忘记密码走 `yarn user:reset`，见 [12-a A1](./12-a-需求-应用外壳与上下文.md)）
- 错误统一体：`{ "error": { "code": "...", "message": "..." } }`
- 参数校验失败 → 400 并带上字段名
