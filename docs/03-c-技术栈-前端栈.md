## C. 前端技术栈

### C.1 总体约定

- **React 19** + **TypeScript 7**（strict）
- **Vite 8** 构建；`vite.config.ts` 里配 dev proxy：`/api` → `http://localhost:<PORT>`
- **Ant Design 6**（⚠️ v6，不是 v4/v5）
- **react-router-dom 7**（数据路由 + `errorElement`）
- **zustand 5** 做跨组件状态（会话列表、设置缓存、主题）
- **axios** 调 REST；**SSE 用 fetch + ReadableStream**（不用 EventSource ——
  EventSource 不支持 POST 和自定义头）
- 样式：**不用 CSS 预处理器**，一律用 antd token + CSS 变量；
  少量自定义样式写 CSS Module 或内联 `style`

### C.2 前端目录结构

> ⚠️ **只有 2 条路由**：`/chat` · `/sessions`。

> **没有设置页、没有观测页**：配置改代码 / 文件（见 [04-c](./04-c-ui-配置入口.md)），

### C.3 路由表

| 路径        | 页面     | 鉴权 | 备注                          |
| ----------- | -------- | ---- | ----------------------------- |
| `/`         | → `/chat` | 无   | 重定向                        |
| `/chat`     | 聊天     | 无   | 主界面                        |
| `/chat?session=<id>` | 聊天（指定） | 无 | 打开指定会话          |
| `/sessions` | 历史会话 | 无   | 列表 / 搜索 / 收藏             |
| `*`         | 404      | —    | 未知路径                      |

> ⚠️ **没有 `/settings/*` · `/traces` · `/cost` · `/change-password`**
> —— 配置在代码 / 文件里，观测走命令行（[04-c](./04-c-ui-配置入口.md)）。
>
> ⚠️ **没有 `/login`** —— 本期**完全无鉴权**，打开就能用
> （见 [12-a A1](./12-a-需求-应用外壳与上下文.md)）。
>
> ⚠️ **每条路由都要挂 `errorElement: <ErrorPage />`** ——
> React Router v7 **自带一层内部错误边界**，比 `main.tsx` 外层的 `<ErrorBoundary>`
> **更靠近路由组件**。不挂的话，路由里渲染炸了用户看到的是 RR 的默认英文页 + 堆栈。
> （这个坑在开发时才暴露，务必一开始就挂上。）

### C.4 状态管理（zustand）

| Store         | 管什么                                         | 要点                                 |
| ------------- | ---------------------------------------------- | ------------------------------------ |
| `sessionStore` | 当前会话、侧栏折叠、只看收藏、待发问题        | 会话列表刷新要跟 `reloadSessions` 对齐 |
| `themeStore`   | 深浅色                                         | 持久化到 `localStorage`；没存过则跟随系统 |

> ⚠️ **不要把所有状态塞进一个 store**。会话状态与主题分开，
> 否则「切只看收藏」这种小操作会触发整页重渲染。
> ⚠️ **没有 `settingsStore`** —— 没有设置页，模型与通用配置都不在前端缓存
> （前端只在「还没配置模型」时展示一段静态提示）。


### C.5 消息流与 `useChat`

- 用 `@ai-sdk/react` 的 `useChat`：
  - `messages` —— 消息数组（含 `parts`）
  - `sendMessage` / `regenerate` / `stop`
  - `status` —— `submitted` / `streaming` / `ready` / `error`
- **自定义 part**（工具卡片、待确认卡片）通过
  `useChat({ experimental_prepareRequestBody })` 之外的后端数据流 part 落进 `message.parts`
- ⚠️ **重新生成必须显式传 `messageId`**：
  `regenerate({ messageId: msg.id })`。
  不传的话 SDK 会重生成**最后一条**消息 —— 传错消息就重生了空气泡。
- ⚠️ **切「只看收藏」这类会换身份的开关，不能掐断正在流式的回答**：
  侧栏的 loading 与聊天面板的 loading **要拆开**，
  否则 `SessionLoader` 被卸载 → `useChat` cleanup → `chat.stop()` → 回答断掉
- ⚠️ **自动发送（从 URL 带问题进来）不能在 mount effect 里直接调 `sendMessage`**：
  `useChat` 在 unmount 时会 `chat.stop()`，StrictMode 下 mount effect 跑完立刻 cleanup，
  正好把「消息准备」阶段的 abort controller 取消掉 ——
  **消息永远发不出去而且不报错**。
  解法：`setTimeout(0)` 延后一拍再发，让 cleanup 先过去。

### C.6 主题与深浅色

- token 分三层：**品牌 / 浅色 / 深色**
  ⚠️ **背景色不能共用一份** —— 共用的话切了暗色还是白底
- 顶栏 ☀/🌙 按钮切换 + `localStorage` 持久化 + 未设置时跟随 `prefers-color-scheme`
- **页面里写死的浅色一律换成 token**（`colorTextTertiary` / `colorFillQuaternary` 等）
- `<html data-theme="dark">` 与 token 联动，滚动条也按它分深浅两套
- ⚠️ **ECharts 图表要显式把 antd token 合进 option**（`notMerge` 恒开）：
  ECharts 默认 `axisLabel` 色写死，深色卡片底上**对比度只有 2.2:1**（AA 要 4.5:1），
  深底上只看得见网格线、看不见刻度

### C.8 API 客户端约定

- 统一一个 axios 实例（`lib/api.ts`），baseURL `/api/v1`
- ⚠️ **没有鉴权头、没有 401 拦截** —— 服务端完全免鉴权（见 [12-a A1](./12-a-需求-应用外壳与上下文.md)）
- **错误文案唯一实现**（`lib/apiError.ts`）：
  ⚠️ 不要在各个 api 模块里各抄一份 `errorMessage` ——
  抄着抄着就会出现「用户看到英文 `Forbidden`」这种事故
- 状态码 → 文案约定：
  - 400 参数错 · 403 无权限 · 404 不存在
  - 429 触发限流（带 `Retry-After`）· 500 服务异常 · 503 依赖不可用
  - ⚠️ **503 有一条专用文案**：「还没配置模型，去改 `.env` 的 `LLM_MODEL`」
    —— 不要让用户看到「服务不可用」这种没法行动的提示
