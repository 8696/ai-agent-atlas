# 11 · 部署运维与成本

> 本项目**只跑本地**：不部署到任何云、不做多机集群、不做容器编排。
> 目标：一个人在一台机器上，`yarn dev` 就能用；数据能备份、能迁移、能重置。

## 11.1 本地启动

### 依赖

| 依赖        | 必需   | 说明                                                                   |
| ----------- | ------ | ---------------------------------------------------------------------- |
| Node ≥ 22.4 | 是     |                                                                        |
| Yarn 1.22+  | 是     |                                                                        |
| SQLite      | 内置   | 无需安装                                                               |
| FTS5        | 可选   | SQLite 没编 FTS5 时降级（见 [05-b §5.5](./05-b-数据模型-全文检索.md)） |
| Docker      | **否** | 本项目**不需要 Docker**（这是与当前项目最大的差别）                    |

### 步骤

```bash
yarn install
cp .env.example .env      # 填模型 API Key（用本地模型则可留空）
yarn dev                  # 前后端一起起
```

- 首次启动自动建库 + 跑迁移 + 写默认提示词文件
- 前端 <http://localhost:5180>，后端 <http://localhost:3100>
- ⚠️ **没有模型配置时聊天会提示「还没配置模型」** —— 去 `.env` 填 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`（改完重启）

### 生产模式

```bash
yarn build
yarn migrate
yarn start                # node dist/src/server.js
```

- ⚠️ **生产不自动跑迁移** —— 先 `yarn migrate` 再起
- ⚠️ **生产由谁跑 `yarn migrate`**：本项目没有 DBA 角色，
  就是使用者本人（或部署脚本）

## 11.2 环境变量

> 📌 **`.env` 是本项目唯一的配置入口**（共 39 个 key，完整清单见 `.env.example`）。
> 下表只列**必填 / 容易忘 / 危险**的那些。

| key                    | 默认              | 必填 | 说明                                         |
| ---------------------- | ----------------- | ---- | -------------------------------------------- |
| `PORT`                 | `3100`            | 否   | 后端端口                                     |
| `HOST`                 | `127.0.0.1`       | 否   | ⚠️ **默认只听本机**                          |
| `NODE_ENV`             | `development`     | 否   |                                              |
| `DATABASE_PATH`        | `data/atlas.db`   | 否   |                                              |
| `WORKSPACE_ROOT`       | `data/workspace/` | 否   | Agent 能碰到的目录                           |
| `LLM_BASE_URL`         | —                 | 否   | Anthropic 兼容端点                           |
| `LLM_API_KEY`          | —                 | 否   | 模型密钥                                     |
| `LLM_MODEL`            | —                 | 否   | 模型标识；留空 = 「还没配置模型」            |
| `MCP_CONFIG_PATH`      | `data/mcp.json`   | 否   | MCP server 列表放这个文件（`.env` 只放路径） |
| `OPENAI_API_KEY`       | —                 | 否   | OpenAI 密钥                                  |
| `OPENROUTER_API_KEY`   | —                 | 否   | OpenRouter 密钥                              |
| `NOUS_API_KEY`         | —                 | 否   | Nous Portal 密钥                             |
| `ALLOW_PRIVATE_EGRESS` | `false`           | 否   | 允许指向私网                                 |
| `SHELL_ENABLED`        | `true`            | 否   | ⚠️ 关掉 = 整个 shell 能力不可用              |
| `TOOL_CONFIRM_LEVEL`   | `high`            | 否   | 确认档位 none/normal/high                    |
| `MONTHLY_TOKEN_BUDGET` | `200000`          | 否   | 默认月度 token 预算                          |
| `COST_BUDGET_BLOCK`    | `false`           | 否   | 超预算是否硬拦                               |
| `LOG_LEVEL`            | `info`            | 否   |                                              |

> ⚠️ **`.env` 与 `.env.example` 是同一份东西的两副面孔**：
> 同一组 key、同一顺序、同一段注释，**只有值不同**。
> 「哪个 key 该存在」的唯一依据 = `src/config.ts` 的 `envSchema`。
> 改完跑 `yarn env:sync`（同步）/ `yarn env:check`（只校验，漂了退出码 1）。
> 兜底测试 `tests/unit/env-consistency.test.ts`。

## 11.3 数据与备份

### 数据位置

> ⚠️ **所有路径相对「项目根」**（不是当前工作目录）——
> 基准规则见 [02 §路径基准](./02-系统架构与目录.md)。
> 项目根由 `ATLAS_HOME` 或「向上找 `package.json`」确定。

| 路径              | 内容                                | 备份                                              |
| ----------------- | ----------------------------------- | ------------------------------------------------- |
| `data/atlas.db`   | 对话 / 工具流水 / 记忆索引 / 成本   | 必须                                              |
| `prompts/`        | 提示词文件（**在项目根，进 git**）  | 在 git 里就算                                     |
| `data/memory/`    | 长期记忆（`MEMORY.md` / `USER.md`） | **必须**（丢了记忆就没了；⚠️ 个人数据，不进 git） |
| `data/skills/`    | 技能包                              | 建议                                              |
| `data/cron.json`  | 定时任务                            | 建议                                              |
| `data/pricing.json` | 单价表（USD / 百万 token）        | 建议（**丢了就只记 token 数**，费用显示 0）        |
| `data/workspace/` | Agent 能碰到的文件                  | 看用户                                            |
| `logs/`           | 日志                                | 可选                                              |

### 备份

```bash
yarn backup            # → backups/atlas-<时间戳>.tar.gz
```

- ⚠️ **SQLite 在线备份用 `VACUUM INTO`**，不要直接拷文件
  （WAL 模式下拷文件可能拿到不一致的快照）
- 备份要**同时包含业务库与记忆文件**（记忆的真源在文件里，**文件丢了就真丢了**）
- 恢复后**校验索引条数与业务表条数**；对不上就重建索引
  （索引可以重建，**记忆文件不能丢**）

### 迁移

```bash
yarn migrate           # 跑 pending 迁移
yarn migrate:undo      # 回滚最后一个
```

### 命令行速查

```bash
yarn tool:logs [--tool <名>] [--status <状态>] [--since <iso>] [--limit 50]   # 工具流水
yarn memory:list [MEMORY|USER]                                                # 看记忆
yarn memory:add USER prefers-pnpm "用户用 pnpm，不用 npm"                      # 加一条
yarn memory:edit USER prefers-pnpm "用户用 pnpm 装依赖"                        # 改一条
yarn memory:archive USER prefers-pnpm                                          # 归档（软删）
yarn memory:delete USER prefers-pnpm                                           # 真删
yarn memory:clear USER                                                        # 清空
yarn search <关键词>                                                            # 跨会话 + 记忆检索
yarn cost:report [--session <id>]                                             # 本月用量
```

## 11.4 重置与救火

| 症状              | 处理                                                                                      |
| ----------------- | ----------------------------------------------------------------------------------------- |
| **配置搞坏了**    | 改 `.env` 的 `LLM_*`（改完重启）                                                          |
| **FTS5 索引坏了** | 重建索引（`messages_fts` / `memory_fts`）；⚠️ **记忆真源是 `data/memory/*.md`，文件别删** |
| **数据库坏了**    | 从备份恢复；没有备份就删 `data/atlas.db` 重来（**数据全丢**）                             |
| **迁移卡住**      | `yarn migrate:undo` 回滚；⚠️ 不要手改表                                                   |
| **端口被占**      | `lsof -i :3100` 找到并 kill；或改 `PORT`                                                  |
| **进程起不来**    | 看 `logs/app-*.log`；⚠️ 常见原因：端口占用 / `HOST` 写成非法值                            |

## 11.5 成本

### 成本来源

| 来源         | 说明                                         | 控制手段                          |
| ------------ | -------------------------------------------- | --------------------------------- |
| **对话**     | 主成本                                       | 选便宜模型 + 提示词缓存           |
| **记忆抽取** | 每次抽取 ≈ 一次额外调用（思考 token 占大头） | 单独配便宜的 `memory` 模型        |
| **会话摘要** | 长会话触发                                   | 关 `summary_enabled` 或配便宜模型 |
| **跨会话检索** | 有命中时多一次调用（把命中折成一段）   | 量级小 · 关掉 `MEMORY_ENABLED`    |
| **评测跑批** | 一题 = 2 次调用（生成 + 裁判）               | 单次 ≤ 50 题                      |

### 成本闸

| 闸              | 默认   | 行为                                 |
| --------------- | ------ | ------------------------------------ |
| 月度 token 预算 | 200000 | 超了**写 WARN 日志 + 对话里回一句提示** |
| 硬拦            | 关     | 开则超预算直接拒绝（**并说清原因**） |
| 单轮步数上限    | 5      | 防死循环烧钱                         |
| 工具超时        | 30 秒  | 防长任务挂住                         |
| 上下文预算      | 2000   | 超了折成摘要（关掉就截断）           |

> ⚠️ **本期没有顶栏告警条** —— 超比例时是**一条 WARN 日志 + 对话里的一句提示**
> （见 [12-d D4](./12-d-需求-记忆与配置.md)）。

> ⚠️ **限流与成本累计是进程内 / DB 状态**，多实例部署时上限会放大（本期单机，可接受）

## 11.6 已知边界

- ⚠️ **只支持单机单实例**（SQLite + 进程内限流 / 熔断 / BM25 类的进程内状态）
- ⚠️ **没有多用户 / 多租户的运维维度**（没有「租户 A 超预算」这种视图）
- ⚠️ **升级不自动迁移数据**（换检索实现要手动重建 FTS5 索引）
- ❌ 不做容器化部署（虽然可以自己 Docker 化，但没有现成 compose）
- ❌ 不做自动备份（脚本有，靠 cron 之类自己接）
- ❌ 不做远程管理
