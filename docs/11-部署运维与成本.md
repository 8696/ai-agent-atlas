# 11 · 部署运维与成本

> 本项目**只跑本地**：不部署到任何云、不做多机集群、不做容器编排。
> 目标：一个人在一台机器上，`yarn dev` 就能用；数据能备份、能迁移、能重置。

## 11.1 本地启动

### 依赖

| 依赖         | 必需 | 说明                                        |
| ------------ | ---- | ------------------------------------------- |
| Node ≥ 22.4 | 是   |                                             |
| Yarn 1.22+  | 是   |                                             |
| SQLite       | 内置 | 无需安装                                    |
| sqlite-vec   | 可选 | 装不上会降级（见 [05-b §5.5](./05-b-数据模型-向量库.md)） |
| Docker       | **否** | 本项目**不需要 Docker**（这是与当前项目最大的差别） |

### 步骤

```bash
yarn install
cp .env.example .env      # 填 JWT_SECRET（必须）
yarn dev                  # 前后端一起起
```

- 首次启动自动建库 + 跑迁移 + 写默认配置
- 前端 <http://localhost:5180>，后端 <http://localhost:3100>
- ⚠️ **没有模型配置时聊天会提示「还没配置模型」** —— 去 `/settings/models` 配一条

### 生产模式

```bash
yarn build
yarn migrate
yarn start                # node dist/server.js
```

- ⚠️ **生产不自动跑迁移** —— 先 `yarn migrate` 再起
- ⚠️ **生产由谁跑 `yarn migrate`**：本项目没有 DBA 角色，
  就是使用者本人（或部署脚本）

## 11.2 环境变量

| key                        | 默认            | 必填 | 说明                             |
| -------------------------- | --------------- | ---- | -------------------------------- |
| `PORT`                     | `3100`          | 否   | 后端端口                         |
| `HOST`                     | `127.0.0.1`     | 否   | ⚠️ **默认只听本机**              |
| `NODE_ENV`                 | `development`   | 否   |                                 |
| `DATABASE_PATH`            | `data/atlas.db` | 否   |                                 |
| `VECTOR_DB_PATH`           | `data/vectors.db` | 否 |                                 |
| `WORKSPACE_ROOT`           | `data/workspace/` | 否 | Agent 能碰到的目录             |
| `JWT_SECRET`               | —               | **是** | 不配则启动失败                  |
| `CONFIG_ENCRYPTION_KEY`    | —               | 否   | 不配则**不能保存模型 key**      |
| `LLM_PROVIDER`             | `anthropic`     | 否   | 平台默认供应商                   |
| `LLM_BASE_URL`             | —               | 否   | 平台默认端点                     |
| `LLM_API_KEY`              | —               | 否   | 平台默认密钥                     |
| `LLM_MODEL`                | —               | 否   | 平台默认模型                     |
| `ALLOW_PRIVATE_EGRESS`     | `false`         | 否   | 允许指向私网                    |
| `DEFAULT_TOKEN_BUDGET`     | `200000`        | 否   | 默认月度 token 预算              |
| `COST_BUDGET_BLOCK`        | `false`         | 否   | 超预算是否硬拦                   |
| `LOG_LEVEL`                | `info`          | 否   |                                 |

> ⚠️ **`.env` 与 `.env.example` 是同一份东西的两副面孔**：
> 同一组 key、同一顺序、同一段注释，**只有值不同**。
> 「哪个 key 该存在」的唯一依据 = `src/config.ts` 的 `envSchema`。
> 改完跑 `yarn env:sync`（同步）/ `yarn env:check`（只校验，漂了退出码 1）。
> 兜底测试 `tests/unit/env-consistency.test.ts`。

## 11.3 数据与备份

### 数据位置

| 路径              | 内容                          | 备份 |
| ----------------- | ----------------------------- | ---- |
| `data/atlas.db`   | 对话 / 配置 / 记忆 / trace    | 必须 |
| `data/vectors.db` | 向量                          | 必须（要与业务库对应） |
| `data/skills/`    | 安装的技能包                   | 建议 |
| `data/workspace/` | Agent 能碰到的文件            | 看用户 |
| `logs/`           | 日志                          | 可选 |

### 备份

```bash
yarn backup            # → backups/atlas-<时间戳>.tar.gz
```

- ⚠️ **SQLite 在线备份用 `VACUUM INTO`**，不要直接拷文件
  （WAL 模式下拷文件可能拿到不一致的快照）
- 备份要**同时包含业务库与向量库**（两者要对得上）
- 恢复后**校验向量条数与业务表条数**；对不上提示「需要重算」

### 迁移

```bash
yarn migrate           # 跑 pending 迁移
yarn migrate:undo      # 回滚最后一个
```

## 11.4 重置与救火

| 症状                   | 处理                                                          |
| ---------------------- | ------------------------------------------------------------- |
| **忘了密码**           | 删掉 `users` 表那一行 → 前端会重新显示「首次创建账号」        |
| **配置搞坏了**         | 删掉 `app_settings` 里对应的行 → 回到内置默认                |
| **向量库坏了**         | 删 `data/vectors.db` → 服务重建，相关性召回降级为固定顺序      |
| **数据库坏了**         | 从备份恢复；没有备份就删 `data/atlas.db` 重来（**数据全丢**）  |
| **迁移卡住**           | `yarn migrate:undo` 回滚；⚠️ 不要手改表                        |
| **端口被占**           | `lsof -i :3100` 找到并 kill；或改 `PORT`                       |
| **进程起不来**         | 看 `logs/app-*.log`；⚠️ 常见原因：`JWT_SECRET` 没配 / 端口占用 |

## 11.5 成本

### 成本来源

| 来源              | 说明                                       | 控制手段                        |
| ----------------- | ------------------------------------------ | ------------------------------- |
| **对话**          | 主成本                                      | 选便宜模型 + 提示词缓存         |
| **记忆抽取**      | 每次抽取 ≈ 一次额外调用（思考 token 占大头）| 单独配便宜的 `memory` 模型       |
| **会话摘要**      | 长会话触发                                  | 关 `summary_enabled` 或配便宜模型 |
| **评测跑批**      | 一题 = 2 次调用（生成 + 裁判）              | 单次 ≤ 50 题                    |
| **嵌入**          | 记忆 / Skill 向量                            | 量级小                           |

### 成本闸

| 闸                | 默认      | 行为                                   |
| ----------------- | --------- | -------------------------------------- |
| 月度 token 预算   | 200000    | 超了告警（顶栏）                       |
| 硬拦              | 关        | 开则超预算直接拒绝（**并说清原因**）   |
| 单轮步数上限      | 5         | 防死循环烧钱                           |
| 工具超时          | 30 秒     | 防长任务挂住                           |

> ⚠️ **限流与成本累计是进程内 / DB 状态**，多实例部署时上限会放大（本期单机，可接受）

## 11.6 已知边界

- ⚠️ **只支持单机单实例**（SQLite + 进程内限流 / 熔断 / BM25 类的进程内状态）
- ⚠️ **没有多用户 / 多租户的运维维度**（没有「租户 A 超预算」这种视图）
- ⚠️ **升级不自动迁移数据**（换 embedding 模型要手动重算向量）
- ❌ 不做容器化部署（虽然可以自己 Docker 化，但没有现成 compose）
- ❌ 不做自动备份（脚本有，靠 cron 之类自己接）
- ❌ 不做远程管理
