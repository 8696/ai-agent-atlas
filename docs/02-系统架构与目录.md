### 三个关键设计约定

1. **编排只在 `agent/`，业务不在图里**
   图节点只做「路由 + 调用 + 收结果」，真正的逻辑在 `tools/` 和 `services/`。
   换框架（图 → 别的编排库）时，业务代码不动。

2. **工具只有一个入口：`tools/registry.ts`**
   内置工具、Skill 自带工具、MCP 暴露的工具，
   在模型看来是**同一池工具**，同一种 schema、同一种执行入口、同一套权限闸。
   ⚠️ **这是 C5（MCP）能安全接进来的前提** —— 否则第三方工具会绕过闸门。

3. **模型调用统一走 `services/model.ts`**
   图节点和工具都不直接 new ChatModel；
   供应商 / base_url / 密钥 / 用途（chat / memory / summary）全从配置读。

## 2.2 数据流（一次典型请求）

```
POST /api/v1/chat  { session_id, messages, ... }
   │
   ├─ ① 限流 → ② 会话存在？→ ③ 预算够吗？
   │
   ▼
⑤ 从 checkpointer 恢复该会话的图状态（没有则新建）
   │
   ▼
⑥ graph.stream(input, { config: { thread_id: session_id } })
   │
   ├─ node: recall        ← 按当前问题召回长期记忆 → 注入 state
   ├─ node: plan          ← 调模型，判断意图、决定调不调工具
   │     ├─ 不用工具 → node: answer → 结束
   │     └─ 要用工具 → node: tools（LangGraph ToolNode）
   │            ├─ 命中危险策略 → interrupt → 推「待确认」卡片 → **挂起**
   │            └─ 通过 → 执行 → 结果回灌 state → 回到 node: plan（可循环）
   ├─ node: answer        ← 汇总，流式吐字
   └─ node: persist       ← 消息落库 + 成本记账 + trace 收尾
   │
   ▼
⑦ SSE 帧持续下推（text-delta / data-tool-call / data-pending / finish）
   │
   ▼
⑧ 前端 useChat 增量渲染；工具卡片可展开看入参 / 出参
```

**图状态的持久化点**：

| 时机             | 落什么                                        | 落在哪                |
| ---------------- | --------------------------------------------- | --------------------- |
| 每次节点转移后   | 图状态（含 messages、工具结果、预算余量）     | SQLite checkpointer   |
| interrupt 挂起时 | 状态 + 待确认的工具调用                       | 同上                  |
| 一轮对话结束时   | user / assistant 消息 + parts                 | SQLite `messages` 表  |
| 一轮对话结束时   | token 用量 + 费用                             | SQLite `cost_logs` 表 |
| 一轮对话结束时   | 一轮记录（状态 / 耗时 / token / 费用 / 工具） | SQLite `traces`       |

### 路径基准 ⚠️

> **所有相对路径一律相对「项目根」解析，不相对 `process.cwd()`。**

**项目根的确定顺序**（`src/config/paths.ts`）：

1. 环境变量 `ATLAS_HOME`（显式指定；⚠️ 只能来自**真实环境变量**，
   不是 `.env` —— `.env` 自己的路径就要靠项目根来定位）
2. 从代码位置**向上找含 `package.json` 的目录**
   （源码 `src/config/paths.ts` → 上 2 层；编译后 `dist/src/config/paths.js` → 上 3 层）
3. 兜底 `process.cwd()`

**为什么必须有这个** —— 相对 cwd 的话，从不同目录启动（systemd / cron / IDE / `npx`）：

- `.env` 读不到（dotenv 默认读 `cwd/.env`）→ 配置全丢
- `data/atlas.db` 会在**错误的位置建一个新库**（最隐蔽的一类 bug：看着能跑，数据全空）
- `data/skills/` 扫不到 → Skill 全失效
- `data/memory/` 读不到 → 记忆全丢

**代码里怎么用**：

```ts
import { paths } from './config';
import { join } from 'node:path';

const prompt = readFileSync(join(paths.prompts, 'system.md'), 'utf8');
```

| `paths.*`         | 指向                      | 可配？              |
| ----------------- | ------------------------- | ------------------- |
| `projectRoot`     | 项目根                    | `ATLAS_HOME`        |
| `data`            | `data/`                   | 否                  |
| `prompts`         | `prompts/`                | 否                  |
| `memory`          | `data/memory/`            | 否                  |
| `skills`          | `data/skills/`            | 否                  |
| `workspace`       | `data/workspace/`（默认） | ✅ `WORKSPACE_ROOT` |
| `logs`            | `logs/`                   | 否                  |
| `cron`            | `data/cron.json`          | 否                  |
| `databaseFile`    | `data/atlas.db`（默认）   | ✅ `DATABASE_PATH`  |
| `agents` / `soul` | `AGENTS.md` / `SOUL.md`   | 否                  |

> ⚠️ **文档与 `.env` 里写相对路径，代码里必须用 `paths.*` 绝对路径** ——
> 相对路径只给人看，代码不认。

### 哪些进 git、哪些不进 ⚠️

| 东西                     | 位置       | 进 git？ | 理由                                              |
| ------------------------ | ---------- | -------- | ------------------------------------------------- |
| 项目指令 `AGENTS.md`     | 项目根     | ✅       | 项目资产，跟代码一起                              |
| 人格 `SOUL.md`           | 项目根     | ✅       | 同上                                              |
| 提示词 `prompts/*.md`    | 项目根     | ✅       | **版本与回滚靠 git**                              |
| 技能包 `data/skills/`    | `data/` 下 | ⚠️ 建议  | 二进制/大文件建议另存，代码库只留说明             |
| 长期记忆 `data/memory/`  | `data/` 下 | ❌       | ⚠️ **个人数据**，不进版本库；迁移用 `yarn backup` |
| 业务库 `data/atlas.db`   | `data/` 下 | ❌       | 运行时数据                                        |
| 工作区 `data/workspace/` | `data/` 下 | ❌       | 用户自己的文件                                    |
| 日志 `logs/`             | `logs/` 下 | ❌       | 运行时数据                                        |
| 配置 `.env`              | 项目根     | ❌       | 有密钥；模板 `.env.example` 进 git                |

> ⚠️ **提示词特意放在项目根 `prompts/` 而不是 `data/prompts/`** ——
> `data/` 整个在 `.gitignore` 里，放那儿就**根本进不了 git**，
> 而提示词的「版本与回滚靠 git」是硬需求。
> ⚠️ **记忆相反**：它是个人数据，默认**不进**版本库。

### 目录约定（要点）

| 目录            | 放什么                                         | 禁止                                        |
| --------------- | ---------------------------------------------- | ------------------------------------------- |
| `src/agent/`    | 图定义、节点、边、状态、checkpointer、事件翻译 | **不放业务逻辑**、不直接碰 DB               |
| `src/tools/`    | 工具实现 + 注册表                              | 不直接调 LLM；不做权限判断（策略在 `lib/`） |
| `src/lib/`      | 无状态工具：安全闸、预算、埋点、路径沙箱、错误 | 不 import `models/`（避免循环依赖）         |
| `src/services/` | 有状态业务：会话 / 记忆 / 提示词 / 模型 / 成本 | 不 import `gateway/`                        |
| `src/gateway/`  | 只做协议转换                                   | 不写业务逻辑                                |
| `web/`          | 只做展示与交互                                 | 不直连 DB、不在后端拉模型                   |

> ⚠️ **`data/` 必须进 `.gitignore`**：里面有对话内容、文件路径。
> `data/workspace/` 里是 Agent 能碰到的文件 —— **默认沙箱根目录就是这个目录**，
> 换根要改 `.env` 的 `WORKSPACE_ROOT`（见 [12-c](./12-c-需求-工具技能与扩展.md) C2）。
