## A1 · 本地账号与鉴权 · P0

**需求**：首次启动时创建一个本地账号，之后所有页面与接口都要登录才能用。

**技术要求**：

- **单用户**：全库只有一行 `users`；不实现租户、角色矩阵、用户管理页面
- 首次访问 `/login` 时若库中无账号 → 显示「首次使用，请创建本地账号」的初始化表单
- 初始化：邮箱 + 密码（**≥ 8 位**）→ 创建账号 → `must_change_password = 1`
- 密码 bcrypt（cost ≥ 10）存储；改密后 `must_change_password` 清零
- 登录成功签发 JWT（HS256，`JWT_SECRET`）；令牌有效期默认 7 天
- **鉴权闸门**：
  - 公开路由只有 `/api/v1/auth/login` 和 `/api/v1/health`
  - 其余接口一律要 `Authorization: Bearer <token>`
  - `must_change_password = 1` 的账号，除 `/api/v1/auth/me` 与
    `/api/v1/auth/change-password` 外一律 **403**（服务端强制，不只靠前端拦）
- 登录失败计数：连续失败锁定（防暴力破解），成功后计数清零
- 令牌过期 → 401；前端 401 拦截跳 `/login`

**验收**：

- [ ] 空库启动 → 打开前端 → 自动跳初始化表单 → 创建成功 → 强制改密页
- [ ] 未登录访问 `/api/v1/chat` → 401
- [ ] 改密前的账号访问除白名单外的接口 → 403
- [ ] 连续 5 次密码错 → 锁定；用正确密码也进不去
- [ ] 改密成功后旧令牌失效（重新签发）

## A2 · Web 应用外壳 · P0

**需求**：一套骨架贯穿全站 —— 侧栏（会话 + 设置入口）、顶栏（主题 / 用户 / 预算告警）、内容区。

**技术要求**：

- 路由表见 [03-c §C.3](./03-c-技术栈-前端栈.md)；未登录一律重定向 `/login`
- **每条路由挂 `errorElement: <ErrorPage />`**
  ⚠️ React Router v7 自带的内部错误边界比顶层 `<ErrorBoundary>` 更靠近路由组件，
  不挂的话用户看到的是默认英文页 + 堆栈
- 侧栏分组：
  - **对话**：新对话 / 历史会话 / 收藏筛选
  - **设置**：模型 / 提示词 / 工具 / Skill / MCP / 记忆 / 通用配置
  - **观测**：调用链路 / 成本
- 顶栏：主题切换（☀/🌙）、用户菜单、**预算告警条**（超 80% 时显示进度条）
- 主题：token 三层（品牌 / 浅色 / 深色），`localStorage` 持久化，未设置时跟随系统
  ⚠️ **背景色不能共用一份** —— 共用则切暗色仍是白底
- 窄屏（< 992px）自动折叠侧栏
- 403 / 404 / 500 各有专门文案（不显示英文原始错误）
- 页面里写死的浅色一律换成 antd token

**验收**：

- [ ] 未登录访问任意受保护页 → 重定向 `/login`
- [ ] 切深色模式后**全站无写死浅色**（逐页目视 + `preview_inspect` 抽查）
- [ ] 任意路由渲染抛错 → 显示 500 页而不是白屏 / 英文堆栈
- [ ] 窄屏侧栏自动折叠，且有手动展开按钮

## A3 · AI 模型配置 · P0

**需求**：在 UI 里配多个模型，指定用途（对话 / 记忆 / 摘要 / 嵌入），启用切换，配备用模型。

**技术要求**：

- 字段：显示名 · 供应商（`anthropic` / `openai`）· `base_url` · API Key · 模型标识 ·
  用途 `usage_scope` · 启用 · 是否默认 · 备用模型 · 输出上限 · 温度 · 思考预算 · 额外参数
- **模型解析链**：用途专用模型 → 同 scope 默认模型 → 平台默认（`.env`）
  ⚠️ 解析逻辑只能有**一处**（`services/model.ts`），
  对话 / 记忆抽取 / 摘要 / 嵌入都从这里拿 —— 不许各处自己 new ChatModel
- **API Key 加密存储**（AES-256-GCM）；⚠️ **`CONFIG_ENCRYPTION_KEY` 没配就不许保存**
  （不降级成明文）；配了之后不能换（换了旧密文解不开 → 降级到平台默认并告警）
- **`base_url` 走 SSRF 校验**：生产默认禁止指向内网 / 回环 / 云元数据地址；
  编辑时**留空 = 保持原样**这条默认路径**也必须走校验**（新建 / 编辑共用同一份归一化函数）
  ⚠️ 这是一个真实踩过的坑：只校验新建、漏了编辑，租户能在生产把端点指到 `169.254.169.254`
- **备用模型**：同租户（这里是同一用户）同 scope 的另一条；
  ⚠️ **仅在「一个内容 chunk 都还没吐出去」时切** ——
  吐出去的字收不回来，重切会让重复的工具调用**真的执行两遍**
- **没有可用模型**时：前端显示「还没配置模型」空状态 + 跳转按钮，**不是 500**

**验收**：

- [ ] 配一条模型 → 回 `/chat` 能正常对话
- [ ] 删掉全部模型 → 聊天页显示空状态与跳转按钮，不报 500
- [ ] `base_url` 填 `http://169.254.169.254/` → 保存被拒（400）
- [ ] 编辑模型时 `base_url` 留空 → 原值不变，且**这条路径也过 SSRF 校验**
- [ ] 模型列表页**不返回 API Key 明文**（只显示掩码）
- [ ] 配两条同 scope 模型 + 备用 → 主模型 500 时自动切备用，且**在已吐字之后不切**

## A4 · 提示词版本管理 · P0

**需求**：系统提示词可以改，可以存多个版本，可以发布、回滚，改完下一轮立即生效。

**技术要求**：

- 提示词按**名称**分组（`system` / `tool` / `memory` / `summary`），每组多版本
- 版本状态：`draft` / `published` / `archived`；每组有且仅有一个 `is_active` 的生效指针
- **发布 = 「标 published」+「换生效指针」在同一个事务里**
  ⚠️ 否则会出现「版本已标成 published 但生效指针没换」的半成功 ——
  结果是改了提示词但对话还跑旧的
- ⚠️ **生效指针这个 key 必须注册进配置 registry**（哪怕 `hidden: true`）——
  不注册的话写侧抛校验错（发布接口返 400 但版本已被标成 published），
  读侧直接返回 null → **改了的提示词永远不生效**
- 改完**立即生效，不用重启**（每轮对话读库）
- 回滚 = 把某个旧版本重新设为生效（不删历史）
- 提示词内容里的占位符：`{{tools}}` `{{memories}}` `{{skills}}` `{{date}}`
  ⚠️ **未识别的占位符原样保留**（不要清空 —— 清空会把用户写的模板内容吞掉）
- 提示词改动写审计（`PROMPT_PUBLISHED` / `PROMPT_ROLLED_BACK`）

**验收**：

- [ ] 改系统提示词 → 发布 → **下一轮**对话行为改变（不重启）
- [ ] 回滚到上一版 → 行为恢复
- [ ] 发布接口失败时**不会**留下「已 published 但未生效」的半状态
- [ ] 提示词里的 `{{tools}}` 被替换成真实工具列表
- [ ] 提示词里的未知占位符 `{{foo}}` 原样保留

## A5 · 通用配置 · P1

**需求**：一批可改的应用级配置项，在设置页里分组展示，保存后立即生效。

**技术要求**：

- **配置项的元信息（类型 / 范围 / 分组 / 说明）写在代码的 registry 里**；
  `app_settings` 表只存用户改过的值 —— 跟「租户只存改过的值」一个路子
- 本期分组与项（**共 20 项 / 6 组**）：

  | 分组     | 配置项                                                                              |
  | -------- | ----------------------------------------------------------------------------------- |
  | 通用     | `system_language` · `timezone` · `max_tool_steps` · `tool_timeout_ms` · `workspace_root` |
  | 模型     | `default_temperature` · `default_max_tokens` · `thinking_budget` · `multi_tool_calls` |
  | 记忆     | `memory_enabled` · `memory_relevance_enabled` · `memory_top_k` · `memory_token_budget` · `summary_enabled` · `summary_token_budget` |
  | 成本     | `monthly_token_budget` · `cost_budget_block` · `warn_ratio`                          |
  | 安全     | `allow_private_egress` · `shell_enabled` · `tool_confirm_level`                       |
  | 工具     | `tool_output_max_chars` · `tool_output_truncate`                                      |

- **支持 string / number / boolean / json 四种类型**（string 是第一次出现，
  要带 `maxLength` 上限 + 多行输入框）
- ⚠️ **boolean 项要能清除覆盖**（回到默认值）——
  只存「改过的值」的话，清除 = 删掉这一行，不是写 `false`
- 改配置**立即生效**（每轮读库，不缓存到进程）
- 配置项在 registry 里登记 `scope`（`platform` / `model`）——
  模型级配置（供应商地址、密钥、限流）**留在 `.env`，不在页面露出**
- 配置改动写审计

**验收**：

- [ ] 改 `max_tool_steps` → 下一轮对话的工具循环上限立刻变
- [ ] boolean 项能「清除覆盖」回到默认值
- [ ] 数值项超出范围 → 保存被拒（400），并指明哪个字段
- [ ] 改配置不重启即生效
- [ ] `.env` 里的敏感项（密钥、SSRF 开关、预算硬闸）在页面上**看不到**
