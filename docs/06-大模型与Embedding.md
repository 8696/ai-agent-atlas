# 06 · 大模型与 Embedding

## 6.1 模型接入方式

本项目**只用两个供应商适配器**，都能指 `base_url` 指向兼容端点：

| 适配器                       | 协议                | 典型可指的服务                       |
| ---------------------------- | ------------------- | ------------------------------------ |
| `@langchain/anthropic`       | Anthropic 兼容     | Anthropic 官方 / 智谱 GLM 兼容端点  |
| `@langchain/openai`          | OpenAI 兼容        | OpenAI 官方 / 硅基流动 / DeepSeek …  |

**模型解析链**（`services/model.ts`）：

```
按 usage_scope 选：
  chat    → 对话模型
  memory  → 记忆抽取模型
  summary → 会话摘要模型
  embed   → 嵌入模型

回落链：用途专用模型 → 同 scope 的默认模型 → 平台默认（.env）
```

- 平台默认（`.env`）：`LLM_PROVIDER` / `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`
- 用户配的模型（`model_configs` 表）**优先于**平台默认
- ⚠️ **没有可用模型时不能 500**：前端要显示「还没配置模型」的空状态 + 跳转按钮

## 6.2 供应商差异（踩过的坑）

| 坑                                       | 现象                                   | 处理                                        |
| ---------------------------------------- | -------------------------------------- | ------------------------------------------- |
| **系统提示词必须走 `system` 参数**        | 塞进 messages 的 system 角色 → 供应商 400 | LangChain 的 `systemMessage` / `system` 字段 |
| **智谱的 Anthropic 端点不吃 `cache_control`** | `cache_read_tokens` 恒为 0            | 提示词缓存在该供应商上无效，UI 要说明         |
| **推理模型思考 token 全额算输出 token**    | 成本比预期高好几倍                     | 单独配 `usage_scope='memory'` 的便宜模型      |
| **部分供应商不支持 `parallel_tool_calls`** | 并行工具调用报错                       | 降级为串行（配置项 `parallel_tools`）          |
| **部分供应商不接受 `tool_choice='required'`** | 强制工具调用报错                     | 检测到 400 时重试为「不强制」                |

## 6.3 工具调用

- 工具定义用 **LangChain 的 `tool()`** 或 `StructuredTool`（zod schema 自动转 JSON Schema）
- 工具 schema 由 `tools/registry.ts` 统一产出 → 图的 `ToolNode` 直接吃这批工具
- ⚠️ **不要在工具 description 里写实现细节** —— description 是给模型看的，
  写「这个工具会读 /etc/passwd」等于教模型怎么越权
- ⚠️ **工具数量会挤占上下文**：工具太多时模型选错。
  本期工具少（5 个内置 + Skill + MCP），不做「按场景动态裁剪工具池」，
  但要**预留这个扩展位**（按当前问题相关度过滤工具池）

## 6.4 提示词（system prompt）的组装顺序

```
1. 基础人格与安全边界（内置，不可被用户改）
2. 当前生效的提示词版本（用户可在 UI 改）
3. 长期记忆（按相关性召回的 top N 条，条数 + token 双重裁剪）
4. 已加载的 Skill 说明（命中 Skill 时）
5. 工具使用规范（可用工具列表 + 权限档说明）
```

> ⚠️ **顺序有意义**：记忆要排在提示词版本之后 —— 冲突时以「提示词版本」为准？
> 不，规则要写清楚：**工具输出的事实 > 长期记忆 > 提示词里的通用知识**。
> 记忆是「关于这个用户的偏好」，不是「世界事实」。
> ⚠️ **工具返回的内容必须标注为「不可信数据」**（外部内容可能含注入指令），
> 不能和系统指令同等对待。

## 6.5 Embedding

| 用途         | 用哪些向量                | 说明                                |
| ------------ | ------------------------- | ----------------------------------- |
| 长期记忆召回 | `memory`                  | 每条记忆一条向量                    |
| Skill 匹配   | `skill`                   | 技能描述的向量                      |

- 嵌入模型走 `usage_scope='embedding'` 的模型配置；没配则用平台默认
- ⚠️ **维度固定**：sqlite-vec 建表时定死（见 [05-b §5.2](./05-b-数据模型-向量库.md)）
- ⚠️ **换嵌入模型 = 旧向量作废**（维度可能变；即使维度相同，语义空间也不同）
  → 依据 `memories.embedding_model` 判定，标记「待重算」，后台逐批重算
- ⚠️ **嵌入调用失败不能阻断对话**：记忆召回降级为「按时间倒序」

## 6.6 思考 / 推理预算

- 每条模型配置有 `thinking_budget`（token 数，0 = 关）
- 用户在聊天页也可以临时勾选「思考模式」→ 请求体带 `thinking`
- 解析顺序：`resolveThinkingBudget(模型配置, 用户勾选)`
  - 配了 > 0 → 一直生效
  - 没配但用户勾了 → 用兜底预算（1024）
  - 没配也没勾 → 0（关）
- ⚠️ **推理模型的思考 token 全额算输出 token** —— 这是「抽取成本实测 2000+」的原因
- ⚠️ **部分供应商不支持思考参数** → 传了报 400 时要能降级为「不带思考参数重试」

## 6.7 重试与抖动

- AI SDK **没有**给 LangChain 这条路加抖动；上游挂掉时所有并发请求在同一毫秒一起重试（惊群）
- 自己在 `lib/retry.ts` 里做：**全抖动** `random(0, min(cap, base * factor^n))`
- 尊重 `Retry-After` 头
- ⚠️ **只包非流式调用**：流式中途失败已经吐了一半，重来会吐两遍
- ⚠️ **工具调用同理不重试**：工具可能有副作用（写文件、发请求），
  重试 = 执行两遍。工具的错误**回灌给模型**让模型自己决定怎么办

## 6.8 熔断

- 按 `provider|base_url` 分桶，连续失败到阈值就断开，期间快速失败
- 冷却后半开一个探活
- ⚠️ **进程内状态**：多实例部署时每个实例各断各的（本期单机，不构成问题）

## 6.9 成本

| 项                     | 口径                                                     |
| ---------------------- | -------------------------------------------------------- |
| 输入 token             | `usage.prompt_tokens`                                     |
| 输出 token             | `usage.completion_tokens`（**含推理模型的思考 token**）    |
| 缓存命中 token         | `usage.cached_tokens`（⚠️ 智谱恒为 0）                   |
| 单价                   | 按模型配置里的价格表（可配）· 没配就用内置默认价          |
| 记账时点               | **每一轮结束立刻记**（`cost_logs`），不能等会话结束才记   |
| ⚠️ 记忆抽取 / 摘要      | **单独记**（`usage_scope` 区分），别混进对话成本里       |

> ⚠️ **换模型要能换价**：价格表跟着模型配置走，
> 否则「换了便宜模型但成本反而涨了」这种问题会查不出来。

## 6.10 不做的事

- ❌ **不做微调 / 训练**
- ❌ **不做本地模型部署**（但 base_url 可以指本机服务 —— 生产默认禁私网地址，
  指本地要显式放行）
- ❌ **不做提示词自动优化**（A/B 对比只做「跑两遍比结果」，不做自动改写）
- ❌ **不做向量模型的自训练**
