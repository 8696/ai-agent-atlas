# 01 · 需求与场景

## 1.1 一句话目标

**做 Atlas —— 一个跑在本地、通用型的 AI Agent**。

- 后台跑一个 HTTP 服务（编排用 **LangGraph.js**）
- Web 端打开就能发起对话
- Agent 判断用户意图 → **调用工具** → 把结果回灌 → 汇总回答

```
用户（Web 端）
  │  发一句话
  ▼
[Atlas 后端 HTTP 服务]  ← LangGraph.js 状态图
  ├─ 意图识别 → 决定调哪个工具
  ├─ 工具执行（危险操作先要人确认）
  ├─ 结果回灌上下文 → 再判断（可循环）
  └─ 汇总作答（流式吐字）
```

> **它跟「文档问答 SaaS」的根本区别**：
> 那类系统靠**预先灌进向量库的知识**回答问题；Atlas 靠**当场调工具**获取事实 ——
> 读磁盘上的文件、执行命令、发 HTTP 请求。
> 知识来自工具和记忆，不来自一个必须先上传的语料库。
>
> 本期**不做** RAG 检索（那是「有语料时」的补充能力，不是通用 Agent 的地基）。

三步流程：

```
装模型配置
  └─ /admin/models 填一条（base_url + model id + key）→ 启用

开聊
  └─ Web 端 /chat 发一句话 → 图开始跑 → 流式回字 + 工具卡片

工具干活
  └─ 读文件 / 列目录 / 跑命令 / 发请求 → 结果回灌 → 继续或收尾
```

## 1.2 用户角色（1 层登录）

> 本系统**只有一层身份**：跑这个实例的人。
> **没有租户**，**没有 SaaS 平台方**。

| 层                  | 谁有这种身份                | 登录入口 | 账号字段     | 用途                                                 |
| ------------------- | --------------------------- | -------- | ------------ | ---------------------------------------------------- |
| **使用者**（user）  | 部署这台机器的人（就是你自己） | `/login` | 邮箱 + 密码 | 聊天 / 配模型与提示词 / 装工具与 Skill / 看成本与链路 |

**为什么保留 `users` 表**（虽然只有一个账号）：

1. 长期记忆、对话历史、工具流水都要有归属主体（`user_id`），
   将来「多用户共用一台机器」时不用重做表结构；
2. 本地 Web 端不能完全裸奔 —— 端口一开就是局域网可见，
   有一道口令比没有强（**这是威胁模型的一部分，不是因为要做 SaaS**）。

**明确不做**：

- ❌ 租户号（`tenant_code`）、租户隔离、跨租户数据域
- ❌ 平台方（system）子系统、跨租户 KPI、建租户流程
- ❌ 角色矩阵（就一个角色）、权限继承、菜单权限

## 1.3 首次启动的标准流程

```
首次 yarn dev
  │
  ├─ 自动建库（SQLite）+ 跑迁移 + 写入默认配置（内置提示词 / 默认预算）
  │
  ▼
打开 http://localhost:5180
  │  → /login 看到「首次使用，请创建本地账号」
  │  输入 邮箱 + 密码（≥ 8 位）
  ▼
系统创建本地账号（全局唯一一个）→ 标记「必须改密」→ 跳转 /change-password
  │
  ▼
改完密码 → 落到 /chat
  │
  ▼
侧栏「设置 → 模型」填一条模型（base_url / model id / API Key）→ 启用
  │
  ▼
回 /chat 发第一句话 → Agent 开始调工具
```

> ⚠️ **没配模型时不能报 500**：聊天页要明确显示「还没有可用模型，去配置」，
> 并给一个跳转到模型配置页的按钮。空状态报错是这个项目的第一号体验事故。

## 1.4 要在演示里跑通的 5 条用户故事

1. **看目录**：「我桌面上有哪些文件？」→ Agent 调 `list_dir` → 列出条目
2. **读文件**：「把 `notes.md` 里没做完的 TODO 列出来」→ 调 `read_file` → 抽取回答
3. **跑命令**：「帮我跑一下 `npm test`」→ 调 `shell` → **弹出确认卡片** → 批准 → 执行 → 回输出
4. **联网查**：「查一下今天美元兑人民币」→ 调 `http_get` → 回
5. **记住偏好**：「记住，我用 pnpm 不用 npm」→ 抽取成长期记忆 → 下一轮自动带上

## 1.5 不做（Out of Scope · 本期）

- **不做多租户 / 平台方**（见 §1.2）
- **不做 RAG 知识库检索**（本期靠工具 + 记忆；「上传 PDF 建向量库」是另一类产品的地基，
  不是通用 Agent 的必需件 —— 后面要加走 `04-a` 提到的扩展位）
- **不做接真实业务系统**（不内置「查订单 / 退款 / 工单」这类电商 mock 工具 ——
  Atlas 是通用型，工具要通用：文件 / 命令 / 请求 / 时间）
- **不做原生移动 App**（响应式 Web 即可）
- **不做云端多机部署**（单机单实例；多实例的锁 / 限流问题本期不处理）
- **不做语音 / 视频通道**
- **不做「转人工」**（没有坐席角色）
- **不做插件市场 / 工具商店**（工具只能本地注册或接 MCP）
- ⚠️ **不承诺「MCP 全生态兼容」**：本期只做「接一个外部 MCP server，
  发现它的工具并能调用」这一条链路，不做 MCP 的全部能力（resources / prompts / sampling）。

## 1.7 非功能需求

| 维度         | 要求                                                                                |
| ------------ | ----------------------------------------------------------------------------------- |
| **启动**     | `yarn dev` 一条命令起前后端；不需要 Docker、不需要外部数据库                        |
| **首次可用** | 从 clone 到能聊天 ≤ 15 分钟（含装依赖、配一个模型）                                 |
| **响应**     | 首字延迟 ≤ 2 秒（不含工具执行时间）；工具执行超过 5 秒要有「正在执行…」的可见状态  |
| **不崩**     | 任何工具异常都不能让整轮对话 500 —— 错误要变成模型能读懂的一段文本继续往下走       |
| **数据**     | 全量数据在本地（SQLite 文件 + 本地向量库），可整目录打包迁移                        |
| **可恢复**   | 进程被 kill 后重启，未完成的对话能从断点继续（LangGraph checkpointer 落盘）          |
| **隐私**     | 磁盘上的对话与文件内容不上云（除非用户自己配的模型供应商会带过去 —— 这条要在 UI 提示） |
| **成本**     | 每一轮都能查到花了多少钱；超预算有硬闸                                            |
| **可观测**   | 每轮对话有完整 trace（哪一步、哪个工具、多久、多少 token）                          |
| **跨平台**   | macOS / Linux / Windows 都能跑（Shell 工具的差异要显式处理）                         |

## 1.8 验收标准

### 最小可用集合（MVP · 先跑起来）

- [ ] `yarn dev` 能起来，前端能打开，登录能过
- [ ] 能配一条模型（base_url / model id / key），启用后聊天真的能返回文字
- [ ] 对话是**流式**的（不是等全部生成完一次性出现）
- [ ] Agent 能识别意图并**真的调用工具**，结果体现在回答里
- [ ] 工具卡片在回答上方可见（点了能看到调了什么、传了什么、返回了什么）
- [ ] 危险工具（Shell / 写文件 / 删除）执行前弹确认
- [ ] 对话历史落库，关掉浏览器再打开还在
- [ ] 每一轮都能查到 token 消耗和耗时

### 全量集合（本期做完）

- [ ] 长期记忆：能被抽取、被召回、能手动增删
- [ ] Skill：能装一个本地技能包，Agent 自动在合适时用上它
- [ ] 提示词可改、可发布、可回滚，改完立即生效
- [ ] trace 能看到完整调用链（含工具调用节点）
- [ ] 评测集能跑批、能打分
- [ ] 成本预算超了会拦

### 高级能力（后续期）

- MCP server 接入
- 多代理 / 子代理
- 浏览器自动化
- 定时任务 / 主动触发

## 1.9 关键用户路径（5 条）

### 路径 1 · 首次启动到第一次成功对话

```
yarn dev → 浏览器打开 → 首次创建本地账号 → 强制改密
  → 配置模型（填 base_url / model id / key → 启用）
  → 回 /chat 发「你好」→ 流式回字
```

### 路径 2 · 一次工具调用（读文件）

```
用户在 /chat 发「看下 /tmp/a.txt」
  → 图路由到「需要工具」节点 → 生成 tool_call
  → 工具执行（read_file）→ 结果回灌 state
  → 图再次路由 → 判断「信息够了」→ 汇总流式作答
  → 回答上方出现工具卡片
```

### 路径 3 · 危险操作的人工确认

```
用户发「把 /tmp/x 删了」
  → 图路由到 shell 节点 → 命中危险策略 → **interrupt 挂起**
  → SSE 推一条「待确认」卡片 → 图状态落盘
  → 用户点「批准」→ Command(resume) → 工具真正执行 → 继续
  → （用户点「取消」→ 工具不执行，模型收到一句「用户拒绝了这个操作」）
```

### 路径 4 · 记住一件事

```
用户发「以后都用 pnpm」
  → 记忆抽取触发（正则预筛 → LLM 抽取）
  → 写入长期记忆（fact 类型，带向量）
  → 下一轮：按与当前问题的相关性召回 → 注入 system prompt
```

### 路径 5 · 改提示词立即生效

```
/admin/prompts 编辑 → 保存草稿 → 发布
  → 下一轮对话读到新版本（不重启、不等缓存过期）
  → 可回滚到上一版
```

## 1.10 风险与边界

| 风险                     | 表现                                              | 对策                                                |
| ------------------------ | ------------------------------------------------- | --------------------------------------------------- |
| **Shell 工具等于给了 RCE** | 模型被诱导执行危险命令                            | 危险策略默认「需确认」；命令黑名单；可整体关掉该工具 |
| **路径逃逸**              | 工具读写到工作区外的文件                          | 工具的根目录沙箱（可配），路径规范化后再校验        |
| **SSRF**                  | HTTP 工具被指向内网 / 云元数据地址                | 出网地址校验（默认禁私网，可配放行）                  |
| **提示词注入**            | 文件 / 网页内容里藏指令，模型照做                 | 工具结果与用户消息分角色注入；危险工具仍走确认闸门   |
| **无限循环**              | 模型反复调同一个工具烧钱                          | 工具循环上限（步数 / 同工具重复次数）+ 总预算闸     |
| **上下文爆炸**            | 大文件塞进上下文                                   | 工具输出截断 + 分页读取 + token 预算裁剪            |
| **LangGraph 抽象泄漏**    | 图节点里塞业务逻辑，换框架要重写                  | 图只管编排，业务逻辑在 tool / service 层             |
| **MCP 供应链风险**        | 接进来的第三方 server 带恶意工具                    | MCP 工具默认进「需确认」档；按 server 粒度授权       |
| **SQLite 并发**           | 长对话 + 工具执行时并发写                         | WAL 模式 + 单写者；重活放异步                       |
