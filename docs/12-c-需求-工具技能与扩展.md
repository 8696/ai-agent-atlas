## C1 · 统一工具注册表 · P0 ✅

**需求**：内置工具、Skill 自带工具、MCP 暴露的工具，在模型看来是同一池工具。

**技术要求**：

- **唯一入口 `tools/registry.ts`**：
  三种来源各自产出一批工具定义 → 合并成同一份工具池 → 交给图的 `ToolNode`
- 工具定义统一形态：名称（模型可见、唯一）· 描述（给模型看）· 入参 JSON Schema ·
  敏感档 · 实现 · 来源 · **执行后端**（本地 / 子代理可调用 / 不可子代理调用）
- **来源标记**：`builtin` / `skill` / `mcp`
  —— 来源**从声明处读**（内置在代码里、Skill 在 `SKILL.md` frontmatter、
  MCP 在 `data/mcp.json`），库里**没有工具表**
- ⚠️ **工具名全局唯一**：冲突时 Skill / MCP 的工具**改名或拒绝注册**，
  并在**启动日志里打印冲突详情**（工具名 + 双方来源）——
  ⚠️ **启动即失败，不要静默覆盖内置工具**
- 工具可**单独启停**：
  - 内置工具 → 代码里 `enabled: false`
  - Skill → `SKILL.md` frontmatter 里 `enabled: false`
  - MCP → `data/mcp.json` 里该 server 的 `enabled: false`
  - 停用的工具不进工具池（模型看不到）
- **改描述立即生效**（下一轮对话就能看出模型调不调它）——
  改代码 / 改文件后重启即生效，**描述不要缓存到进程**
- 工具调用**必须走 `agent/tool-node.ts` 的统一入口**，
  ⚠️ **不许在图节点里直接 `await tool.invoke()`** —— 否则权限闸（interrupt）被绕过
- ⚠️ **工具池按相关度裁剪**（对标 Hermes 的 toolset 机制）：
  每轮按「工具名 + 描述」与当前问题的相关度打分，只给模型 top N
  （``.env` 的 `MAX_TOOLS_PER_TURN``，默认 12）；裁剪发生在**调用模型之前**，
  被裁掉的工具在这一轮里模型完全看不到

**验收**：

- [x] 内置工具 + 一个 Skill 工具 + 一个 MCP 工具，模型能在**一次调用**里选到任意一个
      （三种来源**合并成同一池**（`tools/registry.ts` 的 `mergeToolGroups`）；
      集成测试 `tests/integration/tool-sources.test.ts`：
      一轮对话里模型看到的工具清单**同时包含**内置 / Skill / MCP 三个）
      （**三种来源都接上了** —— Skill 见 [C4](#c4--skill-机制含自演化--p1-)、
      MCP 见 [C5](#c5--mcp-接入--p2-)；
      `mergeToolGroups()` 统一处理三种来源）
- [x] 停用某个工具后，模型不再看到它
      （`enabled: false` → 不进工具池；`SHELL_ENABLED=false` → `shell` 也不进）
      ⚠️ **2026-11-01 才真的不进** —— 以前只在权限层拦，
      模型照样看得见 `shell`、照样会调，然后收到一句「已被全局开关禁用」
- [x] 工具名冲突 → **启动失败**并打印冲突详情，不静默覆盖
      （两个内置撞名 → `ToolConflictError` → **启动即失败**；
      第三方来源撞名 → 改名 `<来源>__<名>`，改完还撞就不注册）
- [x] 改工具描述 → 重启后下一轮模型行为变化
      （描述直接来自代码，**不缓存到「下一次调用」**）
- [x] 工具数超过上限时，超出部分在这一轮对模型不可见
      （`MAX_TOOLS_PER_TURN`，默认 12 · 裁剪发生在调模型之前）

## C2 · 内置工具集 · P0 ✅

**需求**：一组**通用**工具，让 Agent 能看文件、跑命令、联网、浏览、跑脚本、知道时间。

**技术要求**：

**本期 14 个核心内置工具**（对齐 Hermes 的能力面）：

### C.2.1 工具集构成（对标 Hermes）

| 批次   | 加什么                                                                    | 量级      | 状态 |
| ------ | ------------------------------------------------------------------------- | --------- | ---- |
| **1a** | `read_file` `write_file` `list_dir` `shell` `http_request` `current_time` | 8–10 人日 | ✅   |
| **1b** | `search_files` `delete_path` `web_fetch` `web_search`                     | 4–6 人日  | ✅   |
| **1c** | `browser` `execute_code`                                                  | 8–12 人日 | ✅   |
| **2a** | `memory` `memory_forget`                                                  | 2–3 人日  | ✅   |

> ⚠️ **每个新工具都要过三关**：① 明确敏感档 ② 明确沙箱/出网边界 ③ 写验收项。

### C.2.2 核心 14 个清单

_文件与目录（5）_

| 工具           | 作用          | 敏感档   | 关键约束                                                                          |
| -------------- | ------------- | -------- | --------------------------------------------------------------------------------- |
| `read_file`    | 读文件内容    | normal   | 路径沙箱内；大文件截断；支持行范围                                                |
| `write_file`   | 写 / 追加文件 | **high** | 路径沙箱内；覆盖写要显式 `overwrite` 参数                                         |
| `list_dir`     | 列目录        | low      | 路径沙箱内；分页；不递归（递归用 `search_files`）                                 |
| `search_files` | 按名/内容搜索 | low      | 路径沙箱内；glob + 文本匹配；默认排除 `node_modules` / `.git` / `data/vectors.db` |
| `delete_path`  | 删除文件/目录 | **high** | 路径沙箱内；⚠️ **不可撤销**；不跟随软链删除                                       |

_执行（1）_

| 工具    | 作用     | 敏感档   | 关键约束                                                 |
| ------- | -------- | -------- | -------------------------------------------------------- |
| `shell` | 执行命令 | **high** | 沙箱工作目录；命令黑名单；默认需确认；超时 30s；输出截断 |

_网络（3）_

| 工具           | 作用           | 敏感档 | 关键约束                                                                                            |
| -------------- | -------------- | ------ | --------------------------------------------------------------------------------------------------- |
| `http_request` | 发 HTTP 请求   | normal | 出网校验（禁私网）；超时；大小限制；重定向上限；只 http/https                                       |
| `web_fetch`    | 抓网页转纯文本 | normal | 同上 + HTML→正文提取；正文大小上限                                                                  |
| `web_search`   | 联网搜索       | normal | 需配搜索后端（⚠️ **只支持 SearXNG 兼容** —— 返回 `{results:[{title,url,content}]}`）；⚠️ **没配就明确报「未配置搜索」**，不要假装能用 |

_浏览器（1）_

| 工具      | 作用         | 敏感档   | 关键约束                                                                                                    |
| --------- | ------------ | -------- | ----------------------------------------------------------------------------------------------------------- |
| `browser` | 浏览器自动化 | **high** | Playwright；动作集：navigate / click / type / read / screenshot；超时；**只能访问白名单允许的域**；**默认需确认** |

> 📌 **域名白名单**（`.env` 的 `BROWSER_ALLOWED_DOMAINS`，逗号分隔）：
> 留空 = 不限域名（**但云元数据 / 链路本地地址照样禁**）·
> 填了之后只有名单里的域名能访问（`*.example.com` 认「本身」与「子域」）。
> ⚠️ **每一个请求都过一遍白名单** —— 重定向、子资源一样拦。

_沙箱代码（1）_

| 工具           | 作用       | 敏感档   | 关键约束                                                                                                              |
| -------------- | ---------- | -------- | --------------------------------------------------------------------------------------------------------------------- |
| `execute_code` | 沙箱跑脚本 | **high** | 受限运行时跑 **JavaScript**；⚠️ **脚本内可通过 RPC 调其他工具**（多步管线不占对话上下文）；默认无网络；超时；输出截断 |

> ⚠️ **`execute_code` 是 Hermes 的招牌能力**：
> 模型写一段 JS，脚本里 RPC 调 `http_request` / `read_file` 等，
> **中间结果不进入对话上下文**，只把最终输出带回来 —— 一次推理完成多步管线。
> 📌 **实现细节见 [C.2.3](#c23-沙箱代码execute_code怎么实现的-⚠️)**。

_时间（1）_

| 工具           | 作用          | 敏感档 | 关键约束           |
| -------------- | ------------- | ------ | ------------------ |
| `current_time` | 当前时间/时区 | low    | 纯本地计算，不出网 |

_记忆（2）_

| 工具             | 作用                     | 敏感档   | 关键约束                                                             |
| ---------------- | ------------------------ | -------- | -------------------------------------------------------------------- |
| `memory`         | 记忆的查看/新增/改写/归档 | normal   | 走 `services/memory/`；写前扫描；归档=软删（文件里还看得见）        |
| `memory_forget`  | 永久删除 / 清空           | **high** | ⚠️ **不可恢复**；默认需确认；子代理不可调（`executor: 'none'`）      |

> 📌 **为什么拆成两个工具** —— 敏感档是**按工具**定的、不是按参数定的：
> 一个工具做不到「新增不确认、删除要确认」。
> ⚠️ **子代理不碰记忆** —— 记忆是跟用户直接对话的事，
> 子代理静默改写用户画像不合适。
> 📌 **需求见 [12-d D5](./12-d-需求-记忆与配置.md)**。

> ⚠️ **工具集到此为止** —— 本期就是这 14 个。
> ⚠️ **浏览器只到 click/type/read**，不做 DOM 级操作。

**通用约束**：

- **路径沙箱**：所有文件路径先 `resolve`（含 symlink）再判断是否在 `workspace_root` 内；
  越界返回明确错误（不是静默失败）
- **工作区根目录可配**（``.env` 的 `WORKSPACE_ROOT``，代码常量，默认 `data/workspace/`）
- ⚠️ **`shell` 的三个特殊处理**：
  ① 超时（默认 30 秒）→ 杀掉进程并返回超时错误

  ③ Windows 下用 `cmd /c`，Unix 下用 `/bin/sh -c` —— **命令构造要跨平台**
- ⚠️ **`http_request` / `web_fetch` 只允许 http/https**；禁止 `file://` / `gopher://` 等

  - Node 的 `vm` 模块**不是安全沙箱**（能拿 `require` 就等于拿到系统）
  - 必须用**子进程 + 受限环境**（不给 `NODE_OPTIONS`、不给网络、

  - ⚠️ **在文档里写明这不是针对恶意代码的强隔离** ——
    它防的是「模型手滑写出破坏性脚本」，不是防有人故意投毒

### C.2.3 沙箱代码（`execute_code`）怎么实现的 ⚠️

> 📌 **它是 Hermes 的招牌能力** —— 模型写一段 JS，
> 脚本里 RPC 调别的工具，**中间结果不进对话上下文**。

```
模型 → execute_code({ code })          → 高危档 → 弹确认
     → 父进程起一个 Node 子进程（cwd = 工作区，环境变量走白名单 —— 见 `lib/security/env.ts`）
     → 子进程把脚本跑在 vm 的独立上下文里
          ├─ 没有 require / process / fetch / Buffer
          ├─ 有 atlas.call(工具名, 参数) → 一路回到父进程执行真正的工具
          └─ 脚本返回值 + console 日志 → 回灌给模型
```

| 边界              | 做法                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| **进程隔离**      | 子进程 · 超时（默认 120 秒）**直接杀进程** · 不给 `NODE_OPTIONS` / 代理 |
| **环境变量**      | **白名单**（`PATH` / `HOME` / `LANG` / `TZ` / `USER` / `SHELL` / `TMPDIR`）—— ⚠️ **不给任何 API Key** |
| **语言隔离**      | `vm` 独立上下文 · **禁掉「字符串生成代码」**（`codeGeneration.strings=false`）|
| **原型链**        | 沙箱对象**无原型** —— 否则 `this.constructor.constructor('return process')` 能逃出去（`vm` 的经典漏洞）|
| **⚠️ 宿主对象不外泄** | 暴露给脚本的 `atlas` / `console` / 定时器**全部在上下文 realm 里创建**，宿主实现只作为**闭包变量**被捕获 —— ⚠️ **否则 `atlas.call.constructor('return process')()` 能拿到宿主 `process`**（`codeGeneration` 只管上下文自己的 `Function`，管不到宿主传进来的函数）|
| **返回值**        | 宿主返回的值**深拷贝**后交给脚本 · 异常**在上下文里重建** · 定时器句柄**换成数字** —— 三处任一漏了都会漏出宿主对象 |
| **权限**          | 沙箱里**只准调不需要确认的工具** —— 高危工具（`shell` / `write_file` / `delete_path`）一律拒绝 |
| **网络**          | 脚本**没有 `fetch`** —— 要联网就 `atlas.call('http_request', …)`（父进程那边照常过出网校验）|

> ⚠️ **这不是针对恶意代码的强隔离** —— Node 的 `vm` 从来不是安全沙箱。
> 它防的是「**模型手滑写出破坏性脚本**」，不是防有人故意投毒。
>
> 📌 **「宿主对象不外泄」这一条是 2026-11-01 补上的** ——
> 之前宿主函数直接挂进上下文，`codeGeneration.strings=false` 管不到它们，
> 脚本能拿到宿主 `process`（能读任意文件、能执行任意命令）。
> 回归测试：`tests/integration/sandbox-code.test.ts` 的

## C3 · 工具权限与危险策略 · P0 ✅

**需求**：不同工具的危险程度不同，危险的要人确认。

**技术要求**：

- 每个工具一个**敏感档**：`low` / `normal` / `high`
  —— 内置工具写在代码里，Skill 写在 `SKILL.md` frontmatter，
  MCP 工具默认 `high`（第三方来源一律当高危）
- **判定结果有四档**：`allow`（直接执行）· `await`（挂起等确认）· `blocked`（禁止）· `reject`（拒绝并回灌）
- 策略来源（按优先级）：
  1. **硬禁**（``.env`的`SHELL_ENABLED` = false` → `blocked`）
  2. **命令黑名单**（`shell` 的命令命中 → `blocked`，**不给确认的机会**）
  3. **MCP server 粒度策略**（`data/mcp.json` 的 `toolPolicy`：`ask` / `auto` / `off`）
  4. **工具敏感档**（`high` → `await`）
  5. **全局档位**（``.env` 的 `TOOL_CONFIRM_LEVEL``：`none` / `normal` / `high`）
  6. ⚠️ **注入命中 → 档位收紧到 `high`**（见 [10 §10.7](./10-安全方案.md)）——
     ⚠️ **收紧必须发生在权限闸里** —— 只收紧「给模型看的那份副本」是空的
- ⚠️ **MCP 工具默认 `ask`** —— 第三方来源的工具一律要确认，
  这是接 MCP 的安全前提
- **命令黑名单**（`shell` 专用）：`rm -rf /`、`mkfs`、`dd if=`、`shutdown`、`reboot`、
  `:(){:|:&};:`、`curl | sh` 等 → `blocked`（直接拒绝，不给确认的机会）
- 黑名单**可扩展**（代码常量里存 JSON 数组）
- ⚠️ **黑名单是兜底不是主防线** —— 主防线是「默认要确认」
- 命中 `blocked` → 工具**不执行**，把原因回灌给模型，模型换条路走
- ⚠️ **三个高危工具的额外约束**（对标 Hermes 的容器隔离理念）：
  - `browser`：只能访问**白名单里**的域名（⚠️ **白名单留空 = 不限域名**，
    但云元数据 / 链路本地地址照样禁；回环地址默认放行 ——
    ⚠️ **也就是说它能访问本机服务**，浏览器是 `high` 档，批准前先看清要开哪个网址）
  - `execute_code`：默认**无网络**；``.env` 的 `ALLOW_PRIVATE_EGRESS`` 不影响它（它不是 HTTP 工具）
  - `delete_path`：路径必须**完全落在工作区内**，且工作区根目录本身不可删
- ⚠️ **`execute_code` 的沙箱逃逸不算黑名单能管的事** ——
  它靠的是「受限子进程」，不是命令匹配

**验收**：

- [x] `shell` 默认弹确认；`read_file` 默认直接执行
- [x] `browser` / `execute_code` / `delete_path` 默认都弹确认
      （三个都是 `high` 档 → `TOOL_CONFIRM_LEVEL=high` 时一律 `await`；
      `delete_path` 一直如此，`browser` / `execute_code` 是 1c 批次补上的）
- [x] 黑名单命令 → 直接拒绝，工具没执行，模型收到原因
      （命中 → 工具**不执行**，原因回灌给模型让它换条路）
- [x] `SHELL_ENABLED=false` → `shell` 直接不可用（不是「还要确认」）
      （⚠️ **模型仍看得见它** —— 禁用是在**权限闸**里判的，
      调了会被 `blocked` 并回灌原因；
      「模型看不到」需要注册表层面过滤，**本期没做**）

      （`TOOL_CONFIRM_LEVEL=none`）

## C4 · Skill 机制（含运行时自演化） · P1 ✅

**需求**：支持「技能包」—— 一份说明 + 可选脚本 —— Agent 在合适的场景自动用上它；
**并且能在干活过程中自己沉淀出新技能**。这是 Hermes 的招牌能力。

**技术要求**：

- **技能包目录约定**（放在 `data/skills/<name>/`）：

  ```
  data/skills/pdf-report/
  ├── SKILL.md          # 必需：说明（frontmatter + 正文）
  ├── scripts/          # 可选：脚本
  └── references/       # 可选：参考资料
  ```

- **`SKILL.md` 格式**（对齐 [agentskills.io](https://agentskills.io) 开放格式）：
  - frontmatter：`name` · `description`（**触发条件描述，给模型看**）·
    可选 `version` · 可选 `enabled`（默认 true）· 可选 `sensitivity`（脚本敏感档，默认 `high`——
    ⚠️ **声明了也不能低于 `high`**，脚本就是执行代码）
  - 正文：给模型看的使用说明（步骤、约束、输出格式）
- ⚠️ **安装 = 手动把目录拷进 `data/skills/`**；**卸载 = 删掉目录**
  —— 没有上传界面
- **发现**：启动时扫描 `data/skills/`；重启后生效
- **注入**：命中的 Skill 的 `SKILL.md` 正文注入 system prompt（受 token 预算约束）
- **匹配**：⚠️ **跟 Hermes 一样改成 FTS5 全文检索**（不用向量）——
  拿用户的问句去搜 Skill 的 `name` + `description` + 正文摘要，
  按 FTS5 排名取 top N
  - **相似度阈值不写死**（不同分词器基线差很多）→ 只做**相对排序**
  - ⚠️ **中文分词**：SQLite FTS5 默认 `unicode61` 分词器不切中文
    → 用 **`tokenize='trigram'`**（SQLite ≥ 3.34），子串匹配，不需要额外编译
    （Hermes 自己为 FTS5 编译过 `native/fts5_cjk/`，说明这块有坑，见 D3）
- **技能自带脚本**：Skill 可以声明一个「执行入口」，Agent 通过统一工具入口调用
  （⚠️ 走同一套权限闸 —— **Skill 脚本不能绕过确认**）
- ⚠️ **Skill 是「不可信代码」**：装进来的脚本能执行任意代码 ——
  拷目录时终端会打印一行提醒；该 Skill 的脚本**默认 `high` 敏感档**

### C4.2 · 运行时自演化（自动沉淀技能）

**需求**：干完一件复杂的事，Agent 自己把经验写成可复用的 Skill。

**技术要求**：

- **触发**：每轮对话结束后，**异步**问模型一句
  「这轮有没有值得沉淀成技能的经验？」（⚠️ **不阻塞本轮回答**）
- ⚠️ **复杂度门槛**：本轮工具调用次数 **≥ `SKILL_MIN_TOOL_CALLS`**（默认 5）
  才问 —— **闲聊（0 次工具调用）不该沉淀技能**，
  否则 `data/skills/` 会被垃圾填满，匹配时全是噪音
  （对齐 Hermes 的「5+ 次工具调用才合成技能」）
- **两个新工具**（走统一入口与权限闸）：
  - `skill_create` —— 入参 `name` · `description` · `body` ·（可选）`scripts`
  - `skill_update` —— 入参 `name` · 新正文（改进已有技能）
- **写盘流程**：
  1. 校验 `name` 合法（kebab-case，不与已有技能重名）
  2. 校验 frontmatter 格式
  3. ⚠️ **写盘前过一遍危险内容检查**（`rm -rf` / `curl | sh` / 「忽略之前指令」这类）
     —— 模型写的技能也是**不可信内容**，不能直接落盘
  4. 写入 `data/skills/<name>/SKILL.md`
  5. 写审计 `SKILL_AUTOCREATED` / `SKILL_AUTOUPDATED`
- ⚠️ **节制**：
  - 每轮**最多自动创建 1 个**技能
  - 同一技能 **24 小时内不重复自动更新**
  - `.env` 的 `SKILL_AUTOCREATE_ENABLED=false` → 完全关闭
  - ⚠️ **本轮工具调用次数 < `SKILL_MIN_TOOL_CALLS` → 根本不问**
- ⚠️ **自动创建的技能默认可信度低**：
  - frontmatter 里标 `autoCreated: true`
  - **注入时在描述前加一行**「（自动沉淀，未经人工确认）」，
    让模型知道这条描述可能不准
- **人工确认后可解除标记**：手动编辑过 → `autoCreated` 去掉

### C4.1 · 实现说明（2026-10 已落地）

> **代码落点**：`src/skills/`（`types` · `frontmatter` · `store` · `match` · `inject` ·

> 注入入口 `{{skills}}`（`prompts/system.md`）· 沉淀提示词 `prompts/skill.md`。

**技能包长这样**：

```
data/skills/weekly-report/
├── SKILL.md          # 必需
├── scripts/          # 可选：脚本（每个带脚本的技能会生成一个工具）
└── references/       # 可选：参考资料
```

**frontmatter 实际支持的字段**：

| 字段            | 必填 | 说明                                                       |
| --------------- | ---- | ---------------------------------------------------------- |
| `name`          | 是   | 技能名（**必须与目录名一致** —— 不一致算名字冲突，启动失败） |
| `description`   | 是   | 触发条件描述（**给模型看** —— 决定它什么时候被用上）         |
| `version`       | 否   | 版本号                                                     |
| `enabled`       | 否   | 默认 `true`；`false` = 不注入、不生成工具                  |
| `sensitivity`   | 否   | 脚本敏感档（默认 `high`）—— ⚠️ **不能低于 `high`**，脚本就是执行代码 |
| `autoCreated`   | 否   | 自动沉淀标记（**人工删掉这一行 = 解除标记**）              |
| `autoUpdatedAt` | 否   | 上次自动更新的时间（**24 小时冷却用**）                    |

**技能脚本怎么被调用**：

- **每个带脚本的技能生成一个工具**，名字是 `skill_<技能名>`（如 `skill_weekly-report`），
  描述里列清楚有哪些脚本可跑
- ⚠️ **走统一入口与权限闸** —— ⚠️ **脚本工具一律 `high` 档**（2026-11-01 起：
  frontmatter 声明的 `sensitivity` **不能把脚本往下压** —— 脚本就是执行任意代码，
  跟它「打算做什么」无关；要无人值守就走定时任务的 `autoApprove` 白名单）
  → 默认弹确认，**技能脚本不能绕过确认**
- ⚠️ **脚本路径必须落在技能目录内** —— resolve symlink 之后还要再判一次
- ⚠️ **脚本内容也要过命令黑名单** —— 手工装进来的技能没经过写盘扫描

**中文匹配怎么做的**（**这是本条需求最大的技术点**）：

- SQLite FTS5 的 `trigram` 分词器**按 3 个字符切** → 「周报」这种 2 字词
  **没法作为查询短语**（不足 3 字符切不出 token）
- → **索引侧与查询侧都做「二元组 + 空格」展开**（`src/lib/text.ts` 的 `expandForTrigram`）：
  「写周报时使用」展开成 `写周 周报 报时 时使 使用 `，
  查询「帮我写一份周报」展开成 `帮我 助写 写一 一份 份周 周报 `
  → 二者都能切出 trigram，**2 字中文词也能命中**
- 📌 **只做相对排序**（bm25）—— **不写死相似度阈值**
- ⚠️ **FTS5 不可用 → 退回覆盖率打分**（`lib/text.ts` 的 `scoreRelevance`）—— 功能少一半但不影响对话

**生效时机**：

- 📌 **启动时扫描** `data/skills/` —— **装错 / 重名 → 启动直接失败并报告**
- 📌 **运行期新建的技能立刻能被命中**（写盘后同步重建 FTS 索引）——
  比「重启后生效」更好，但**技能脚本的工具要等工具池刷新**（下一次调用模型时自动刷新）

**写盘前的安全检查**（`scanSkillContent`）：

| 命中           | 处理                                   |
| -------------- | -------------------------------------- |
| 提示词注入    | **拒绝写入**（「忽略之前的指令」这类） |
| 危险命令      | **拒绝写入**（复用 `shell` 的黑名单）  |
| 疑似凭据      | **拒绝写入**                           |
| ⚠️ 不可见 Unicode | **拒绝写入**（零宽字符 / 双向控制符 —— 能把文字「藏」起来）|

⚠️ **命中就拒绝，不是告警** —— 技能是**持久化**的注入通道，
写进去以后每一轮都在上下文里。

**自演化的节制**（`src/skills/autocreate.ts`）：

- 本轮工具调用次数 **< `SKILL_MIN_TOOL_CALLS`（默认 5）→ 根本不问模型**
- 每轮**最多自动创建 1 个**技能
- 同一技能 **24 小时内不重复自动更新**（`autoUpdatedAt`）
- `SKILL_AUTOCREATE_ENABLED=false` → 完全关闭
- ⚠️ **沉淀是 fire-and-forget** —— 不阻塞本轮回答

## C5 · MCP 接入 · P2 ✅
