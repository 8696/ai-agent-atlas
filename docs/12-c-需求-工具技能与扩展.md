# 12-c · 需求 · 工具、技能与扩展（C 类需求）

> 编号接续 [12-b](./12-b-需求-对话与编排.md)。

## C1 · 统一工具注册表 · P0

**需求**：内置工具、Skill 自带工具、MCP 暴露的工具，在模型看来是同一池工具。

**技术要求**：

- **唯一入口 `tools/registry.ts`**：
  三种来源各自产出一批工具定义 → 合并成同一份工具池 → 交给图的 `ToolNode`
- 工具定义统一形态：名称（模型可见、唯一）· 描述（给模型看）· 入参 JSON Schema · 敏感档 · 实现
- **来源标记**：`builtin` / `skill` / `mcp`；来源信息进 `tools` 表
- ⚠️ **工具名全局唯一**：冲突时 Skill / MCP 的工具**改名或拒绝注册**，
  并在 UI 里明确报告冲突 —— 不能静默覆盖内置工具
- 工具可**单独启停**；禁用的工具不进工具池（模型看不到）
- **改描述立即生效**（下一轮对话就能看出模型调不调它）——
  ⚠️ 描述不要缓存到进程
- 工具调用**必须走 `agent/tool-node.ts` 的统一入口**，
  ⚠️ **不许在图节点里直接 `await tool.invoke()`** —— 否则权限闸（interrupt）被绕过

**验收**：

- [ ] 内置工具 + 一个 Skill 工具 + 一个 MCP 工具，模型能在**一次调用**里选到任意一个
- [ ] 禁用某个工具后，模型不再看到它
- [ ] 工具名冲突 → 拒绝注册并报告，不静默覆盖
- [ ] 改工具描述 → 下一轮模型行为变化

## C2 · 内置工具集 · P0

**需求**：提供一组**通用**工具，让 Agent 能看文件、跑命令、发请求、知道时间。

**技术要求**：

**本期 5 个内置工具**（⚠️ 刻意做少 —— 工具多会让模型选错，也会让上下文膨胀）：

| 工具           | 作用             | 敏感档   | 关键约束                                            |
| -------------- | ---------------- | -------- | --------------------------------------------------- |
| `read_file`    | 读文件内容       | normal   | 路径沙箱内；大文件截断；支持行范围                  |
| `write_file`   | 写 / 追加文件    | **high** | 路径沙箱内；覆盖写要显式 `overwrite` 参数           |
| `list_dir`     | 列目录           | low      | 路径沙箱内；分页；不递归（递归用 `search`）          |
| `shell`        | 执行命令         | **high** | 路径沙箱内的工作目录；命令黑名单；默认需确认        |
| `http_request` | 发 HTTP 请求     | normal   | 出网校验（禁私网）；超时；大小限制；重定向上限      |

> ⚠️ **本期不做**：`delete_path`（危险且少用）、`search`（grep 全盘，慢且容易越界）、
> 浏览器自动化、Git 操作、多文件批量编辑。
> 加工具时先想清楚「模型会不会频繁选错」。

**通用约束**：

- **路径沙箱**：所有文件路径先 `resolve`（含 symlink）再判断是否在 `workspace_root` 内；
  越界返回明确错误（不是静默失败）
- **工作区根目录可配**（`workspace_root` 配置项），默认 `data/workspace/`
- ⚠️ **`shell` 的三个特殊处理**：
  ① 超时（默认 30 秒）→ 杀掉进程并返回超时错误
  ② 输出截断（默认 4000 字符）→ 保留尾部（错误信息通常在尾部）并标注原始长度
  ③ Windows 下用 `cmd /c`，Unix 下用 `/bin/sh -c` —— **命令构造要跨平台**
- ⚠️ **`http_request` 只允许 http/https**；禁止 `file://` / `gopher://` 等
- **每个工具的入参都要有长度上限**（字符串 ≤ 1 万字符，数组 ≤ 100 项）
- 工具调用**统一超时**（`tool_timeout_ms`，默认 30 秒）

**验收**：

- [ ] `list_dir` 能列出工作区内的目录内容
- [ ] `read_file` 读工作区**外**的文件 → 明确报错「路径超出工作区」
- [ ] `read_file` 读超大文件 → 截断并标注原始长度
- [ ] `write_file` 覆盖已有文件且未传 `overwrite` → 拒绝
- [ ] `shell` 执行 `ls` → 正常返回；执行超长命令 → 超时被杀
- [ ] `http_request` 指向 `http://169.254.169.254/` → 被拒
- [ ] `http_request` 指向 `file:///etc/passwd` → 被拒

## C3 · 工具权限与危险策略 · P0

**需求**：不同工具的危险程度不同，危险的要人确认。

**技术要求**：

- 每个工具一个**敏感档**：`low` / `normal` / `high`
- **判定结果有四档**：`allow`（直接执行）· `await`（挂起等确认）· `blocked`（禁止）· `reject`（拒绝并回灌）
- 策略来源（按优先级）：
  1. **硬禁**（配置 `shell_enabled=false` → `blocked`）
  2. **MCP server 粒度策略**（`tool_policy`：`ask` / `auto` / `off`）
  3. **工具敏感档**（`high` → `await`）
  4. **全局档位**（配置 `tool_confirm_level`：`none` / `normal` / `high`）
- ⚠️ **MCP 工具默认 `ask`** —— 第三方来源的工具一律要确认，
  这是接 MCP 的安全前提
- **命令黑名单**（`shell` 专用）：`rm -rf /`、`mkfs`、`dd if=`、`shutdown`、`reboot`、
  `:(){:|:&};:`、`curl | sh` 等 → `blocked`（直接拒绝，不给确认的机会）
- 黑名单**可扩展**（配置项存 JSON 数组）
- ⚠️ **黑名单是兜底不是主防线** —— 主防线是「默认要确认」
- 命中 `blocked` → 工具**不执行**，把原因回灌给模型，模型换条路走

**验收**：

- [ ] `shell` 默认弹确认；`read_file` 默认直接执行
- [ ] 黑名单命令 → 直接拒绝，工具没执行，模型收到原因
- [ ] `shell_enabled=false` → `shell` 直接不可用（不是「还要确认」）
- [ ] 关闭全局确认档 → `high` 档工具也直接执行（说明这是用户的主动选择）

## C4 · Skill 机制 · P1

**需求**：支持装「技能包」—— 一份说明 + 可选脚本 —— Agent 在合适的场景自动用上它。

**技术要求**：

- **技能包目录约定**（放在 `data/skills/<name>/`）：

  ```
  data/skills/pdf-report/
  ├── SKILL.md          # 必需：说明（frontmatter + 正文）
  ├── scripts/          # 可选：脚本
  └── references/       # 可选：参考资料
  ```

- **`SKILL.md` 格式**：
  - frontmatter：`name` · `description`（**触发条件描述，给模型看**）· 可选 `version`
  - 正文：给模型看的使用说明（步骤、约束、输出格式）
- **发现**：启动时扫描 `data/skills/`，也支持运行时热加载（装完立即生效）
- **注入**：命中的 Skill 的 `SKILL.md` 正文注入 system prompt（受 token 预算约束）
- **匹配**：用 `description` 的向量做相似度匹配（`kind='skill'`）
  —— ⚠️ **相似度阈值不写死**（不同嵌入模型的基线差很多，写死阈值换个模型就失效）→
  只做**相对排序**，取 top N
- **技能自带脚本**：Skill 可以声明一个「执行入口」，Agent 通过统一工具入口调用
  （⚠️ 走同一套权限闸 —— **Skill 脚本不能绕过确认**）
- **安装 / 卸载 / 更新**：UI 可上传 `.zip` 或从本地目录选择；装完写审计
- ⚠️ **Skill 是「不可信代码」**：装进来的脚本能执行任意代码 ——
  安装时要显式提示，且默认该 Skill 的脚本走 `high` 敏感档

**验收**：

- [ ] 装一个 Skill → 下一轮对话中 Agent 能用上它的说明
- [ ] Skill 的脚本能被调用，且**执行前弹确认**
- [ ] 卸载 Skill → 下一轮不再注入它的说明
- [ ] Skill 名冲突 → 拒绝并报告

## C5 · MCP 接入 · P2

**需求**：能接一个外部 MCP server，把它暴露的工具接进工具池。

**技术要求**：

- ⚠️ **前置依赖**：C1（统一注册表）与 C3（权限策略）**必须先落地** ——
  否则接进来的第三方工具会绕过安全闸直接执行
- 支持传输：`stdio`（本地起一个进程）· `sse` · `http`
- 工具发现：连接后拉取 server 的 tool list → 转成本项目的工具定义 → 走 C1 注册
- ⚠️ **MCP 工具的描述是第三方写的** → 视为不可信内容，
  在描述里标注来源（`[来自 MCP: <server>]`），
  并**禁止第三方描述里出现「忽略之前的指令」这类内容时不加处理**
- 工具入参 schema 用 JSON Schema 原样转（不做 Zod 推导）
- **工具名冲突**：MCP 工具统一加前缀（`<server>__<tool>`）避免撞名
- 断线重连：指数退避；连续失败 → 标记 `error` 并在 UI 上显示原因
- **不实现**：MCP 的 resources / prompts / sampling；不做 MCP 市场

**验收**：

- [ ] 接一个 MCP server → 工具出现在工具管理页
- [ ] 该工具能被模型调用
- [ ] MCP 工具默认弹确认
- [ ] server 断线 → UI 显示错误原因，不影响其他工具

## C6 · 工具调用流水 · P1

**需求**：每次工具调用都有记录，可查、可筛。

**技术要求**：

- 数据落 `tool_call_logs` 表，**由工具执行包装层写入**（唯一出口，不会漏记）
- 记录：会话 · 发起消息 · 工具名 · 来源 · 状态 · 入参 · 出参 · 错误 · 耗时 · 是否需确认
- 状态：`pending` / `running` / `success` / `error` / `rejected` / `timeout`
- UI：`/settings/tools` 下方或独立页，可按工具 / 状态 / 时间 / 关键词筛
- ⚠️ **入参出参里的密钥要打码**后再入库
- ⚠️ **长出参入库要截断**（保住诊断信息，不撑爆库）

**验收**：

- [ ] 每次工具调用都有流水
- [ ] 被用户取消的调用状态是 `rejected`（不是 `error`）
- [ ] 流水里搜不到明文密钥
