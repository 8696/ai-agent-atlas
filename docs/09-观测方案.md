# 09 · 观测方案

> 目标：**出问题时能定位到具体是哪一步、哪个工具、哪次调用花的**。
> 需求侧见 [12-e E1/E2](./12-e-需求-观测安全与验收.md)，模块侧见 [07-e 模块 13-14](./07-e-模块-可观测与评测.md)。

## 9.1 三层观测

| 层       | 看什么                       | 工具                          |
| -------- | ---------------------------- | ----------------------------- |
| **日志** | 发生了什么（文本）           | pino → `logs/app-*.log`       |
| **链路** | 这一轮经历了什么（结构化）   | `traces` / `spans` 表         |
| **指标** | 整体健康度（数字）           | `cost_logs` + 实时聚合查询    |

> ⚠️ **日志不是链路**：日志给人看（grep），链路给机器看（查询 / 时间线）。
> 二者不要混成一张表。

## 9.2 Trace / Span

### 结构

```
trace: chat.complete  (status=success, duration_ms=8420)
 ├── span: agent.recall        (kind=retrieval, 12ms)
 ├── span: agent.plan          (kind=agent, 1100ms)
 │    └── span: llm.generate   (kind=llm, 1080ms, tokens in/out)
 ├── span: agent.tools         (kind=agent, 5200ms)
 │    ├── span: tool.invoke read_file  (kind=tool, 30ms)
 │    └── span: tool.invoke shell      (kind=tool, 5100ms)
 ├── span: agent.plan          (kind=agent, 900ms)
 ├── span: agent.answer        (kind=agent, 1100ms)
 │    └── span: llm.generate   (kind=llm, 1080ms)
 └── span: cost.record         (kind=cost, 1ms)
```

### 关键约定

- ⚠️ **span 的 `parent_span_id` 必须一路转发** ——
  中间哪一层没转发，调用树就断在那儿（前端按父子关系缩进渲染，断了就散成一片）
- ⚠️ **对话 trace 的 `duration_ms` = 用户感知耗时**
  （收到请求 → 最后一个 chunk 吐完）。
  记忆抽取 / 摘要**另起 trace**，不挂在这条上
- span 的输入输出**要截断**（工具输出可能 1MB）
- ⚠️ **trace 是结束时一次性写的**（内存里攒 → 一个事务写 trace + spans）——
  进程在请求中途被 kill 会丢这一条

### 数据保留

- `traces` / `spans` 保留 30 天（可配），到期清理任务每天跑一次
- `logs/trace-<日期>.jsonl` 同周期滚动
- ⚠️ **清理要按 `created_at` 删**，别全表扫

## 9.3 指标

### 实时聚合（不建分钟级聚合表）

| 指标         | 口径                          | 来源            |
| ------------ | ----------------------------- | --------------- |
| 今日对话数   | `traces` where kind='chat'    | `traces`        |
| p95 延迟     | chat trace 的 `duration_ms`   | `traces`        |
| 今日成本     | `cost_logs` 求和             | `cost_logs`     |
| 错误率       | `status='error'` / 总数       | `traces`        |
| 工具调用数   | `tool_call_logs` 计数         | `tool_call_logs`|

> ⚠️ **原生 SQL 的时间窗口有时区错位**：
> DATETIME 按 **UTC 墙钟**存，但驱动把 `Date` 渲染成**本地**墙钟字符串，两边对不上。
> 症状：**「今日对话数 / 今日成本」在每天的前 8 小时（UTC+8）恒为 0**。
> → 统一用一个 `utcWallClock()` 工具函数渲染时间参数。
> ⚠️ **走 ORM 的参数化查询不受影响**（绑定的是 UTC 值）
- ⚠️ **没有分钟级聚合表**（`metrics_minutely`）—— trace 到十万级时查询会变慢；
  本期量级不做预聚合

## 9.4 告警

| 规则           | 默认阈值        | 动作                       |
| -------------- | --------------- | -------------------------- |
| p95 延迟       | 10 秒           | 顶栏告警条 + 日志 warn     |
| 错误率         | 5%              | 顶栏告警条 + 日志 error    |
| 单轮成本       | 1 元            | 顶栏告警条                 |
| 月度预算       | 预算 × 80%      | 顶栏告警条                 |

- 阈值**可配**（通用配置页「成本」分组）；**填 0 = 不看这一项**
  ⚠️ **不要写成 `v > 0 ? v : 默认值`** —— 那会让「设 0 = 关」变成「设 0 = 用回默认值」
- ⚠️ **告警窗口是「今天」不是 5 分钟**（早期设计稿写的是 5 分钟，实现按天）
- 本地项目**不主动推送**（无 webhook / 邮件）→ 只在 UI 与日志里体现

## 9.5 日志

- **pino**，结构化 JSON，文件落 `logs/app-<日期>.log`
- 级别：debug / info / warn / error
- ⚠️ **脱敏**：`api_key` / `authorization` / `token` / `password` 一律打码
  （脱敏是「写进历史库前的最后一道防线」，**不给开关**）
- 每条日志带 `requestId` + `sessionId` + `traceId`（能串起来）
- ⚠️ **工具入参 / 出参要截断**再打日志

## 9.6 前端页面

### `/traces` 调用链路

- 表格：时间 · 类型 · 状态 · 耗时 · token · 费用 · 会话
- 筛选：状态 / 会话 / 时间范围 / 类型
- ⚠️ **「总数」卡显示筛选后的数**（不是全量）—— 常见 bug

### `/traces/:id` 链路详情

- **时间线**：按父子关系**缩进**渲染（不是平铺）
- 每个 span 可展开看输入 / 输出
- 工具 span 显示：工具名 · 参数 · 结果 · 耗时
- LLM span 显示：模型 · token · 耗时

### `/cost` 成本分析

- KPI 卡：本月总额 · 本月 token · 单轮均价 · 最高单轮
- 四张图：按天 · 按模型 · 按用途 · 按会话
- ⚠️ 日期桶的时间口径与 [05-a §5.3](./05-a-数据模型-sqlite.md) 一致

## 9.7 已知边界

- ⚠️ **trace 结束时才写** → 中途崩溃丢这一条
- ⚠️ **指标是实时聚合查询**，没有预聚合表
- ⚠️ **告警窗口是「今天」**
- ⚠️ **客户端断开记 success**（否则用户自己关页面会把错误率刷高）
- ❌ 不做分布式追踪（不接 OpenTelemetry）
- ❌ 不做告警外推（邮件 / webhook / 钉钉）
