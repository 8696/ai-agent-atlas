## D1 · 短期记忆与会话状态 · P0

**需求**：Agent 记得这轮对话里说过什么，跨轮不丢上下文。

**技术要求**：

- **两层**：
  - **消息历史**（`messages` 表）：用户 / 助手 / 工具结果
  - **图状态**（`graph_checkpoints`）：LangGraph 的完整状态
- 两者都要有：消息历史用于「展示与统计」，图状态用于「继续跑」
- **长会话不能无限增长**：超出 token 预算时触发**摘要压缩**
  - 被裁掉的早期轮次调一次 LLM 折成摘要，写进 `sessions.summary`
  - `sessions.metadata.summary_boundary` 记「摘要覆盖到哪条消息为止」
  - 下一轮按边界把历史切成两段 —— **边界之前不再喂原文**
    （否则原文 + 摘要两种说法并存）
  - **滚动重写**：输入是「旧摘要 + 新丢掉的轮次」，输出是一份全新的完整摘要（不是追加）
- 摘要**模型可独立配**（`usage_scope='summary'`），回落链「摘要模型 → 对话模型 → 平台默认」
- 摘要**另起一条 trace**（`kind='summary'`），⚠️ **不挂在对话 trace 上** ——
  对话 trace 的 duration 要保持「用户感知耗时」
- 摘要开关：`summary_enabled`（可关）+ `summary_token_budget`
- ⚠️ **摘要是 fire-and-forget**：进程在写完前被 kill，这段摘要就丢了（下一轮重来）；
  重复摘要只是多花一次钱，不会写坏数据（写之前会重读边界）

**验收**：

- [ ] 多轮对话里，Agent 能引用前面说过的信息
- [ ] 长会话触发摘要后，早期内容不再以原文形式出现在上下文里
- [ ] 摘要开关关掉后，超长会话走「截断」而不是「摘要」
- [ ] 摘要调用不计入对话 trace 的耗时

## D2 · 长期记忆 · P1

**需求**：Agent 能记住「关于这个用户的事实」，跨会话生效。

**技术要求**：

- **一条记忆 = 一条关于用户的事实**，分四类：
  `preference`（偏好）/ `fact`（事实）/ `context`（情境）/ `profile`（画像）
- **三级更新机制**：
  1. **T1 正则信号预筛**（零成本）：对话里出现「记住 / 我喜欢 / 我叫 / 我用 …」
     这类信号才触发抽取 —— 挡住大部分对话
  2. **T2 调 LLM 抽取**：把现有记忆一起喂给模型，模型决定**新增 / 改写 / 归档**
  3. **T3 用户手动改**：用户自己增删改
- **注入走 system prompt**，且排在检索资料段**前面**
  ⚠️ 冲突时以工具返回的事实为准（记忆是「偏好」，不是「世界事实」）
- **注入哪几条按「与当前问题相不相关」排**（不是固定顺序）：
  - **相关性是主序**，优先级（来源 > 置信度 > 更新时间）是兜底
  - ⚠️ **没有向量的记忆按 0 分算**（跟「有向量但不相关」同档）——
    不会被「缺向量」饿死
- **每轮 top N 条 + token 预算双重裁剪**
- **向量存 `memories` 表上**（`embedding` JSON 数组 + `embedding_model`），
  ⚠️ **不放向量库** —— 量级小（单用户 ≤ 50 条自动记忆 + 手写几条），
  几百条向量在 DB 里算余弦是毫秒级；放向量库得重新手写一遍归属过滤
- **写入时算向量**（新建 / 改内容 / 自动抽取后批量补算，尽力而为）；
  存量数据在下一轮对话**后台补算**（不阻塞那一轮）
- ⚠️ **任何一步失败都退回固定顺序**（按时间倒序）：embedding 服务挂 / 没配 / 迁移没跑 →
  功能少一半，**对话不受影响**
- **抽取模型可独立配**（`usage_scope='memory'`），
  ⚠️ **推理模型的思考 token 全额算输出**（一次实测 2000+）——
  租户（这里是用户）单独配条便宜模型是唯一能压成本的手段
- ⚠️ **抽取是 fire-and-forget**：对话结束几秒后记忆才落库，
  「刚说完就立刻追问」的那一轮用不上新记忆

**验收**：

- [ ] 说「记住我 prefers pnpm」→ 下一轮回答里体现用了这个偏好
- [ ] 召回是按相关性排的（不相关的记忆不会挤占预算）
- [ ] embedding 服务不可用 → 对话照常，记忆退回按时间倒序
- [ ] 抽取调用独立成一条 trace，不影响对话 trace 的耗时

## D3 · 记忆管理界面 · P1

**需求**：用户能看到、能改、能删自己的记忆；也能一键关掉自动记忆。

**技术要求**：

- 页面 `/settings/memory`：列表（内容 / 类型 / 来源 / 置信度 / 更新时间 / 被召回次数）
- 支持：手动新增 / 编辑 / 归档（软删）/ **物理删除**
- ⚠️ **「物理清空」与「归档」是两件事**：
  归档只是软删；用户行使「删除我的全部个人数据」的权利时要的是**真删**
  → 提供「永久删除单条」与「永久清空全部」
- **一键关闭自动记忆**（`memory_enabled=false`）：不再抽取，已有记忆保留
- 物理删除时**同步删向量**（业务库与向量库两边一起）
- 删除写审计（`MEMORY_DELETED`）

**验收**：

- [ ] 能增删改查记忆
- [ ] 归档后不再被召回；物理删除后向量库里也没有了
- [ ] 关掉自动记忆后不再产生新记忆
- [ ] 删除操作有审计记录

## D4 · 预算与成本控制 · P1

**需求**：每一轮都能查到花了多少钱；有预算上限，超了有闸。

**技术要求**：

- **每轮结束立刻记账**（`cost_logs`），token 用量取自模型返回的 `usage`
- **月度 token 预算**（`monthly_token_budget`）+ **告警比例**（`warn_ratio`，默认 80%）
- **超预算默认只告警不拦截**；配置 `cost_budget_block=true` 才拦
  ⚠️ **拦的时候要说清楚**：「本轮因超出预算未执行」，而不是静默失败
- **单轮内的预算也要管**：图状态里带 `budget_used`，每一步累加，
  超单轮上限直接进 `answer` 并说明
- ⚠️ **工具调用不计入 LLM token 预算**（工具不是模型调用），
  但要单独统计工具耗时
- 成本分析页：按天 / 按模型 / 按用途（chat / memory / summary）· 按会话 四维拆解
- 顶栏告警条：超过告警比例时显示

**验收**：

- [ ] 每轮对话后能看到 token 与费用
- [ ] 超月度预算 → 告警条出现
- [ ] 开启 `cost_budget_block` → 超预算后请求被拦，且错误信息说清原因
- [ ] 成本页四个维度的数字能对上 `cost_logs`
