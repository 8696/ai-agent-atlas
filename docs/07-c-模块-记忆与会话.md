## 模块 07 · 会话与消息

**职责**：会话的增删改查 + 消息的落库与读取。

**数据**：`sessions` / `messages` 表（⚠️ **无 `users` 表**，本期无鉴权、无归属主体）

**关键约束**：

- 消息落库**两个字段**：`content`（纯文本）+ `parts`（JSON，结构化 part）
  - ⚠️ **parts 是「刷新后卡片还在」的依据** —— 前端渲染工具卡片读的是它
  - ⚠️ **落库的 parts 与推给前端的必须同源**（否则刷新后卡片内容会变）
- 消息写入时机：**一轮结束时**（不是一个 part 一个 part 写），
  ⚠️ **先图状态后消息**（宁可重复一条消息，也不要丢图状态）
- 标题：首条用户消息截断（≤ 30 字）
- 删除会话 → **级联删** 消息 / 工具流水 / 检查点（不留孤儿行）
- 列表排序用 `last_active_at`（冗余字段，避免列表页 N+1）
- **消息写入时同步写 `messages_fts`**（⚠️ **同一事务** ——
  分两次写会出现「消息在但搜不到」）

**降级**：DB 写失败 → 记录错误但**不中断已生成的回答**（内容先返回给用户）。

> 📌 **「对账」是当前的消息落库机制**（`syncMessages`）：
> 前端每次请求都带上完整历史，后端拿它跟库里的行对账 ——
> **公共前缀保留、多的删掉、少的补上**。
> 「重新生成」（前端把那条 assistant 砍掉再重发）天然表现为「删掉多余的行」，

## 模块 08 · 会话摘要压缩

**职责**：长会话超出 token 预算时，把早期轮次折成摘要。

**触发**：历史 token 数 > `SUMMARY_TOKEN_BUDGET`（或消息条数超阈值）
**手动触发**：斜杠命令 `/compress` → **走同一个函数**（不是另一条代码路径），
**忽略 token 阈值**，立即把当前全部历史折成摘要

**关键约束**：

- **边界标记**：`sessions.metadata.summary_boundary` 记「摘要覆盖到哪条消息为止」
- 下一轮**按边界把历史切成两段** —— 边界之前**不再喂原文**
  （否则原文 + 摘要两种说法并存，模型会摇摆）
- **滚动重写**：输入是「旧摘要 + 新丢掉的轮次」，输出是一份**全新的完整摘要**
  （不是追加 —— 追加会越滚越长且矛盾）
- 摘要**不另起记录** —— 花费直接记进 `cost_logs` 的 `usage_scope='summary'`
  （对话 trace 的 duration 必须保持「用户感知耗时」）
- ⚠️ **摘要用同一个模型**（本期只配一个模型，没有独立的摘要模型）
- 摘要开关 ``.env` 的 `SUMMARY_ENABLED``（关掉则退回复制「截断」）
- ⚠️ **手动压缩后历史消息仍在**（消息表没删，只是不再进模型上下文）——
  用户还能在界面上翻到

**降级**：

| 情况                | 行为                                |
| ------------------- | ----------------------------------- |
| 摘要调用失败        | 退回「截断」（按预算保留最近 N 条） |
| 摘要写入失败        | 边界不推进（下轮重试）              |
| 进程在写完前被 kill | 这段摘要丢失（下一轮重来）          |
| 摘要开关关掉        | 直接走「截断」，**不调模型**        |

> 📌 **本期做到哪（2026-10）**：
>
> - ✅ 服务 `src/services/session-summary.ts`：
>   `compressSession()`（手动 / 自动共用）· `trimByBoundary()` · `prepareSessionContext()`
> - ✅ **在 `prepare` 节点里做**（`src/agent/nodes/prepare.ts`）——
>   每轮开头裁一次，工具循环里不重复裁
> - ✅ **边界按消息 id 定位**（`sessions.metadata.summary_boundary`）——
>   「重新生成」会删掉中间的消息，按下标裁会裁错
> - ✅ **摘要开关关掉 → 走截断**（`truncateOldest()`）
> - ✅ **摘要的花费单独记一条**（`usage_scope='summary'`）
> - ✅ **`/compress` 斜杠命令** → 同一个函数（见 [12-b B9](./12-b-需求-对话与编排.md)）

**已知边界**：

- ⚠️ **摘要滞后一轮**：本轮丢掉的轮次要到下一轮才进摘要（fire-and-forget）
- ⚠️ **摘要有损**：模型改写过的内容跟原文不完全一致，细节可能丢
- ⚠️ **长对话每轮可能多一次 LLM 调用**（可关 / 可配便宜模型）
- ⚠️ **摘要在 system prompt 里不是消息**（语义上略差，检索型问答影响不大）

## 模块 09 · 长期记忆（Markdown 文件） ★

**职责**：记住「关于这个用户的事实」，跨会话召回，并允许用户直接编辑 / 删除。

**数据**：`data/memory/MEMORY.md`（Agent 侧）+ `data/memory/USER.md`（用户侧）
（库里只有 FTS5 索引 `memory_fts`，没有记忆本体表）

**条目格式**（每个 `##` 小节 = 一条记忆）：

```markdown
## prefers-pnpm

- kind: preference # preference | fact | context | profile
- confidence: 0.9
- source: auto # auto | manual
- status: active # active | archived（归档 = 软删）
- updated: 2026-10-31

用户用 pnpm，不用 npm（装依赖、跑脚本都是）。
```

**三级更新机制**：

| 级别 | 做法                                                            | 成本     |
| ---- | --------------------------------------------------------------- | -------- |
| T1   | 正则信号预筛（「记住 / 我喜欢 / 我叫 / 我用 …」）               | 零       |
| T2   | 调 LLM 抽取（把现有记忆一起喂进去，模型决定新增 / 改写 / 归档） | 一次调用 |
| T3   | 用户手动改：**直接编辑文件** 或 `yarn memory:*`                 | 零       |

**关键约束**：

- **一条记忆 = 一条事实**（正文一句话；太长就拆成多条）
- ⚠️ **不存长文本** —— Markdown 文件不是日志，是「索引式的事实清单」
- 注入走 system prompt，排在检索资料段**前面**
- ⚠️ **冲突时以工具返回的事实为准**（记忆是「偏好」，不是「世界事实」）
- **召回排序**：FTS5 相关性为主序，优先级（来源 > 置信度 > 更新时间）为兜底
  - ⚠️ **没有索引的记忆按 0 分算**（与「有索引但不相关」同档）——
    不会被「缺索引」饿死，但也没法靠相关性排上来
- **每轮 top N + token 预算双重裁剪**
- ⚠️ **抽取模型可独立配**（`usage_scope='memory'`）——
  推理模型的思考 token 全额算输出（实测 2000+），
  配条便宜模型是唯一能压成本的手段

### 9.1 · 文件写入的并发安全（Markdown 没有事务）

- 抽取是 fire-and-forget，可能和用户手动编辑撞车
- 写入流程必须是「**重读 → 合并 → 原子写**」
  （写临时文件 + `rename`），⚠️ **不能直接原地覆盖**
- ⚠️ **原子写失败不能留半个文件** —— 记忆文件损坏 = 用户全部记忆丢失
- **归档**：条目 `status: archived`（软删：不再被召回，但文件里还看得见）
- **永久删除 = 真的从文件里移除**（用户行使「删除我的全部个人数据」的权利时要的是真删）
- 删除写审计（`MEMORY_DELETED`）

### 9.2 · 检索（FTS5，与跨会话检索共用一套）

- 记忆条目写入后同步进 `memory_fts` 虚表（⚠️ **全量重建**，不是增量 upsert ——
  量级小：≤ 50 条，全量重建是毫秒级；增量同步的 bug 面大得多）
- 分词器 `tokenize='trigram'`（⚠️ 不切中文就搜不了中文，见 [05-b §5.2](./05-b-数据模型-全文检索.md)）
- 召回流程：FTS5 命中 → **交给 LLM 摘要成一段** → 注入上下文
  （⚠️ 不是把命中原文全塞进去 —— 那会撑爆预算）

**降级**：

| 情况             | 行为                                         |
| ---------------- | -------------------------------------------- |
| FTS5 不可用      | 退回固定顺序（按时间倒序），**对话不受影响** |
| 查询词 < 3 字符  | 该次查询不查（trigram 的硬限制），不报错     |
| 抽取调用失败     | 忽略这一轮（对话照常）                       |
| 记忆文件写入失败 | 保持原文件不动 + 记 warn（**不写坏文件**）   |
| 写入前扫描命中   | **拒绝写入** + 告警（注入 / 密钥 / 不可见字符） |

>
> - ✅ 服务 `src/services/memory/`：
>   `store.ts`（读写 · 原子写 · 上限）· `inject.ts`（召回 · 用量表头）·
>   `extract.ts`（T1 预筛 + T2 抽取）· `scan.ts`（写前扫描）
> - ✅ **条目解析跳过围栏代码块** —— 出厂模板里的示例不是一条真的记忆
> - ✅ **写入即重建索引**（`memory_fts` 全量重建，毫秒级）
> - ✅ **命令行**：`yarn memory:list|add|edit|archive|delete|clear`
> - ✅ **写前扫描命中 → 拒绝写入**（不是告警 ——
>   记忆是**持久化的注入通道**，写进去以后每轮都会被注入）

**已知边界**：

- ⚠️ **抽取是 fire-and-forget**：对话结束几秒后记忆才落库，
  「刚说完就立刻追问」那一轮用不上新记忆
- ⚠️ **只能改得动「最近 N 条」记忆**（模型的目标 id 取自喂给它的快照）
- ⚠️ **没有遗忘机制**：只增不减，靠条数上限 + 冲突时归档收敛
- ⚠️ **召回是关键词匹配不是语义相似** —— 用户换个说法可能就搜不到了
  （这是选 Markdown + FTS5 而不是向量的代价，见 [05-b §5.8](./05-b-数据模型-全文检索.md)）
- ⚠️ **「本轮用了哪几条记忆」查不到**（注入结果没回传前端）
