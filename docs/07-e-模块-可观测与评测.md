# 07-e · 模块 · 可观测与评测（模块 13-15）

> AI 模块规格。需求侧见 [12-e](./12-e-需求-观测安全与验收.md)。

---

## 模块 13 · Trace / Span

**职责**：记录「这一轮发生了什么」，并能按父子关系还原调用树。

**数据**：`traces`（一轮一条）+ `spans`（多段）

**Span 类型**：

| kind         | 谁产生                       | name 例             |
| ------------ | ---------------------------- | ------------------- |
| `agent`      | 图节点                       | `agent.plan`        |
| `llm`        | 模型调用                     | `llm.generate`      |
| `tool`       | 工具执行                     | `tool.invoke`       |
| `retrieval`  | 记忆召回                     | `memory.recall`     |
| `cost`       | 记账                         | `cost.record`       |

**关键约束**：

- ⚠️ **父子 id 必须一路转发** —— 中间哪一层没转发，调用树就断在那儿
- ⚠️ **对话 trace 的 duration = 用户感知耗时**（收到请求 → 最后一个 chunk 吐完）
- 记忆抽取 / 摘要**另起 trace**（`kind='memory'` / `'summary'`），⚠️ **不挂在对话 trace 上**
- trace **结束时一次性写**（内存里攒 → 一个事务写 trace + spans）
- 副本落 `logs/trace-<日期>.jsonl`
- ⚠️ **工具输出要截断后入 span**（别把 1MB 文件塞进 DB）

**降级**：写 trace 失败 → **不影响对话**（只记日志）。

**已知边界**：

- ⚠️ **进程在请求中途被 kill 会丢这一条 trace**（结束时才写）
- ❌ 不做实时 trace（要等一轮结束才能看到）
- ❌ 不做 trace 采样（每轮都记）

## 模块 14 · 成本

**职责**：算钱、记账、告警。

**关键约束**：

- **每一轮结束立刻记**（不能等会话结束）
- token 口径：`prompt_tokens` / `completion_tokens`（⚠️ **含推理模型的思考 token**）/
  `cached_tokens` / `reasoning_tokens` 分开记
- **单价跟着模型配置走**（换模型要能换价）
- ⚠️ **记忆抽取 / 摘要单独记**（`usage_scope` 区分），别混进对话成本
- 告警：`monthly_token_budget` × `warn_ratio` → 顶栏告警条
- 硬拦：`cost_budget_block=true` 时超预算直接拦，
  ⚠️ **要说清楚原因**（「本轮因超出预算未执行」），不能静默失败

**降级**：价格表缺失 → 用内置默认价；还是没有 → 记 token 数，费用留空。

**已知边界**：

- ⚠️ **限流与成本累计是进程内 / DB 状态**，多实例部署时上限会放大（本期单机）
- ❌ 不做本地模型的成本估算

## 模块 15 · 评测

**职责**：用一组题跑批打分，支持提示词改动后的自动回归与 A/B 对比。

**关键约束**：

- ⚠️ **评测的检索 / 记忆口径必须跟线上对齐** ——
  线上对话与评测**走同一个入口**（一个 `planRetrieval()` 这类统一函数），
  ⚠️ **不许评测里另写一套**（否则「改坏提示词 → 分数跌」的基线是歪的）
- 跑批**后台异步**（接口返 202）；单次最多 50 题（成本闸门）
- 打分：LLM-as-Judge，四维（准确性 / 完整性 / 相关性 / 格式）+ 总分
- ⚠️ **提示词发布 / 回滚后自动跑前 10 题**，且：
  - **永不阻塞发布**（没评测集 / 评测关着 / 起跑失败 → 一律跳过）
  - **显式传刚发布的版本号**（不依赖「当前生效指针」——
    发布与回归之间隔着一次 HTTP，中间可能又发了一版）
- ⚠️ **版本不存在直接 400，不静默回落默认** ——
  回落会让「这一版比上一版好还是差」的对比结果骗人
- 逐题配对：按 `item_id` 精确配 → 配不上按题目文本兜底 → **一对一**（一条只能被领走一次）

**降级**：评测模型调不通 → 该题记为失败（不阻塞整批）；整批失败 → run 标记 failed。

**已知边界**：

- ⚠️ **跑批本身要花钱**（一题 = 2 次 LLM 调用：生成 + 裁判）
- ⚠️ **A/B 对比是「同一批题跑两遍」的离线对比**，不是流量分流
- ⚠️ **对比结果不保证「差异只来自提示词」**（模型不同 / 记忆变了也有影响）
- ❌ 不做定时自动跑全量（要常驻定时器，成本不可控）
