> 实现落点见 [03-b](./03-b-技术栈-后端栈.md)（后端） / [03-c](./03-c-技术栈-前端栈.md)（前端）。
> 编号 A~E 全部需求共 41 条，索引见 [12-e §E5](./12-e-需求-观测安全与验收.md)。

> 🎯 **形态对标 [Hermes Agent](https://github.com/NousResearch/hermes-agent)**
> （Nous Research，2026-02 开源，MIT）—— 本地跑、通用 Agent、无登录、
> 配置在文件里、记忆是 Markdown、技能能自动沉淀。
>
> 📌 **「抄能力，不抄平台」** —— 这条是本项目的范围基准：
>
> | ✅ 抄（Agent 能力）                                               | ❌ 不抄（平台集成）                                          |
> | ----------------------------------------------------------------- | ------------------------------------------------------------ |
> | 记忆（Markdown + FTS5）· 人格（`SOUL.md`）· 上下文（`AGENTS.md`） | Telegram / Discord / 微信 / 飞书 / Slack 等 20+ 聊天平台网关 |
> | Skill 机制 + **运行时自演化** · MCP 接入                          | Docker / SSH / Modal / Daytona 等远程执行后端                |
> | 子代理并行 · 定时任务（cron）· 斜杠命令                           | Bot 群聊模式 · 实时语音 / 语音转写                           |
> | 沙箱代码执行 · 浏览器自动化 · 联网搜索                              | 插件市场 / Skills Hub（社区分享）                            |
> | **多供应商**（Anthropic 兼容端点：智谱 / MiniMax / DeepSeek / 千问）· 无鉴权 | ACP 编辑器集成 · RL 轨迹导出 / Atropos 训练接入              |
>
> **理由**：平台集成都要**外部账号与 token**（bot token、云服务密钥），
> 而本项目是「跑在自己机器上的个人 Agent」——
> **能力才是它值钱的地方，平台接入只是分发渠道。**
> ⚠️ Hermes 是 **Python**、我们是 **Node/TS** —— 「抄」= 抄行为契约，**不是抄代码**。

> ⚠️ **前端只有 3 条路由**：`/chat` · `/sessions` · `/stats`（用量统计）。
> ⚠️ **没有登录页、没有鉴权、没有设置页、没有观测页** ——
> 配置在**代码 / 配置文件**里改（见 [04-c · 配置入口](./04-c-ui-配置入口.md)）。
>
> 📋 **每条需求标题末尾的徽标 = 实现状态**（⬜ 未实现 / 🟡 部分实现 / ✅ 已实现），
> 规则与进度速览见 [12-e §E5](./12-e-需求-观测安全与验收.md)。

## A1 · 本地外壳与边界（无鉴权） · P0 ✅

**需求**：打开网页就能用，不登录、不注册、不改密。

**技术要求**：

- **完全无鉴权**：前端没有登录页、没有 JWT 存储、没有 401 拦截；
  后端所有接口（含 `/api/v1/chat`）一律免 token
- `users` 表**不建**（全库没有「谁在用」这个概念）
- ⚠️ **默认只监听回环地址**：`HOST=127.0.0.1`（`src/config.ts` 的默认值）
  —— Agent 有 shell 权限，一个免鉴权的本地服务等于把本机 shell 敞给局域网
- ⚠️ **启动时打印边界告警**：
  - `HOST` 是回环 → 打印「无鉴权 · 仅本机可访问」
  - `HOST` 不是回环（如 `0.0.0.0`）→ **红色告警**：
    「⚠️ 无鉴权且监听非回环地址 —— 局域网内任何人都能用本 Agent 执行命令。
    请确认这是你要的，或改回 `HOST=127.0.0.1`」
- CORS 只允许本机来源（`localhost` / `127.0.0.1` 的前端 dev server）
- 不做注册、不做「记住我」、不做登录失败锁定
- ⚠️ **路径基准 = 项目根，不是 cwd**（见 [02 §路径基准](./02-系统架构与目录.md)）：
  - `.env` 从项目根读（不是 `cwd/.env`）
  - 所有相对路径（数据库 / 提示词 / 记忆 / 技能 / 日志）一律经 `resolvePath()` 解析
  - **从任何目录启动都指向同一份数据**（systemd / cron / IDE / `npx` 都一样）
- **启动时确保目录与文件都存在** —— 新机器拉代码后直接能跑：
  | 缺失什么                            | 怎么处理                                                                             |
  | ----------------------------------- | ------------------------------------------------------------------------------------ |
  | 标准目录                            | `ensureDirs()` 建（`data/` `data/memory/` `data/skills/` `data/workspace/` `logs/`） |
  | `prompts/*.md`                      | 从 `src/prompts/defaults.ts` 的**兜底模板写回**                                      |
  | `SOUL.md`                           | 同上                                                                                 |
  | `data/memory/MEMORY.md` · `USER.md` | 从**模板**新建（**空文件** —— 只装条目，不带默认头注）                         |
  | `data/cron.json`                    | 写 `{"tasks": []}`                                                                   |
  - ⚠️ **已存在的文件一律不动**（哪怕是空的 —— 用户可能故意清空过）
  - ⚠️ **只补缺失的，不覆盖** —— 覆盖等于丢用户数据
  - 启动日志会打印「已初始化 N 个文件」
  - 📌 **记忆文件是例外**：出厂头注已于 2026-11-01 去掉，
    启动时若发现文件开头正是那段旧模板就**摘掉它**（条目原样保留）

> 📌 **本期做到哪（2026-10）**：
>
> - ✅ 边界告警（`src/lib/boundary.ts`）：回环 → 「无鉴权 · 仅本机可访问」；
>   非回环 → **红色框告警**，说清「局域网内任何人都能执行命令」
> - ✅ CORS **只放本机来源**（`src/lib/cors.ts`）—— 放行 `localhost` / `127.0.0.1` / `::1`，
>   其余来源**一个 CORS 头都不回**（浏览器自己拦）
> - ✅ 路径基准 = 项目根（`src/config/paths.ts`）· 目录与出厂文件自动补齐
> - ✅ 库里**没有 `users` 表** —— 全库没有「谁在用」这个概念

**验收**：

- [x] 打开 `http://localhost:5180` → **直接进 `/chat`**，没有登录页
- [x] 不带 token 直接 `curl /api/v1/chat` → 能通
      （集成测试 `tests/integration/chat-sse.test.ts` 就是裸 POST，无 token）
- [x] `lsof -i :3100` 显示只监听 `127.0.0.1`
- [x] `HOST=0.0.0.0` 启动 → 日志打印**红色告警**，说清风险
      （`src/lib/boundary.ts` 的 `describeBoundary()`；启动时红色框打印）
- [x] 库里没有 `users` 表
      （库里只有 `sessions` · `messages` · `SequelizeMeta`）
- [x] **从 `/tmp` 启动**（cwd 不是项目根）→ 仍然读到项目根的 `.env`、
      仍然指向同一个 `data/atlas.db`（**不是**在 `/tmp` 建一个新库）
      （实测：`cd /tmp && npx tsx <项目>/src/server.ts` → 日志
      `injected env (44) from ../../<项目>/.env`，`/tmp` 下什么都没建）
      ⚠️ **为此把模型从装饰器改成了显式 `Model.initialize()`** ——
      装饰器要靠 tsconfig 的 `experimentalDecorators` 才能编译，
      而 tsx 是**按 cwd 找 tsconfig** 的，从 `/tmp` 启动会直接编译失败
- [x] 删掉 `data/` 下所有目录后启动 → 目录被自动重建
      （实测：新目录启动 → `已初始化 8 个文件`，`data/` `prompts/` `logs/`
      `backups/` 与 `data/memory/` `data/skills/` `data/workspace/` 全自动建好）

## A2 · Web 应用外壳 · P0 ✅

**需求**：一套骨架贯穿全站 —— 侧栏（会话）、顶栏（主题 / 状态）、内容区。

**技术要求**：

- **本期只有 3 条路由**：

  | 路径                 | 页面         | 备注               |
  | -------------------- | ------------ | ------------------ |
  | `/`                  | → `/chat`    | 重定向             |
  | `/chat`              | 聊天         | 主界面             |
  | `/chat?session=<id>` | 聊天（指定） | 打开指定会话       |
  | `/sessions`          | 历史会话     | 列表 / 搜索 / 收藏 |
  | `/stats`             | 用量统计     | token 用量与花费  |
  | `*`                  | 404          |                    |

  > ⚠️ **没有 `/login`** —— 无鉴权（见 A1）

- **每条路由挂 `errorElement: <ErrorPage />`**
  ⚠️ React Router v7 自带的内部错误边界比顶层 `<ErrorBoundary>` 更靠近路由组件，
  不挂的话用户看到的是默认英文页 + 堆栈
- 侧栏只有**一组**（历史会话）：
  - 新对话 → `/chat`
  - 会话列表 + ★ 只看收藏 + 🔍 搜索
- 顶栏：页面标题 · 主题切换（☀/🌙）· **连接状态 / 当前模型** · 用户菜单（只有「退出登录」→ 改成「重置会话」？不对——没有登录，**用户菜单改成「关于 / 版本信息」**）
  - ⚠️ **没有预算告警条** —— 预算改在代码里，超预算按 [D4](./12-d-需求-记忆与配置.md) 走错误提示
- 主题：token 三层（品牌 / 浅色 / 深色），`localStorage` 持久化，未设置时跟随系统
  ⚠️ **背景色不能共用一份** —— 共用则切暗色仍是白底
- 窄屏（< 992px）自动折叠侧栏，**且要有手动展开按钮**（折叠了打不开 = 功能不可达）
- 403 / 404 / 500 各有专门文案（不显示英文原始错误）
- 页面里写死的浅色一律换成 antd token

**验收**：

- [x] 直接打开 `/chat` · `/sessions` · `/stats` → 正常渲染，无跳转
- [x] 切深色模式后**全站无写死浅色**（逐页目视 + `preview_inspect` 抽查）
- [x] 任意路由渲染抛错 → 显示 500 页而不是白屏 / 英文堆栈
      （每条路由都挂 `errorElement`（`routes.tsx`）+ 顶层 `<ErrorBoundary>`；
      ⚠️ **错误页不透出 `error.message`** —— 那多半是英文的 JS 报错，
      原始错误只进控制台（`web/pages/error-view.ts` 的 `describeRouteError`，
      单元测试 `tests/unit/error-view.test.ts`））
      （`errorElement` + 顶层 `<ErrorBoundary>` 都已挂上，**但还没人为造错验证过**）
- [x] 窄屏侧栏自动折叠，且有手动展开按钮
      （⚠️ antd 的 `Layout.Sider` **默认不渲染折叠按钮** —— 必须自己加，否则折叠了打不开）

## A3 · 模型供应商与配置 · P0 ✅

**需求**：在 **`.env`** 里配一个模型（一个 Base URL + 一个 Key + 一个模型标识），可另配一个备用模型。

**技术要求**：

- ⚠️ **只有一个模型，纯标量配置** —— **一个 Base URL + 一个 Key + 一个模型标识**：
  ```dotenv
  LLM_BASE_URL=https://open.bigmodel.cn/api/anthropic
  LLM_API_KEY=sk-xxxx
  LLM_MODEL=glm-5.3
  ```
  - ⚠️ **`.env` 里没有 JSON、没有数组、没有供应商前缀**
  - 可选：`LLM_FALLBACK_BASE_URL` / `LLM_FALLBACK_API_KEY` / `LLM_FALLBACK_MODEL`
    （**留空 = 没有兜底**）· `LLM_THINKING_BUDGET` · `LLM_MAX_TOKENS` · `LLM_TEMPERATURE`
- ⚠️ **换供应商只改这三行，不改代码** —— 四家国产模型**全都提供 Anthropic 兼容端点**
  → **只需要一个 `anthropic` 适配器**（`@langchain/anthropic`）
  🎯 **已实测五项能力全绿**（对话 / 思考 / 工具调用 / 流式 SSE / tool_result 回灌）：
  智谱 · MiniMax · DeepSeek · 千问（详见 [06 §6.1.1](./06-大模型与模型解析.md)）
- ⚠️ **只有一个模型的取舍**：
  - **记忆抽取 / 会话摘要** 都用这同一个模型（⚠️ 抽取也用主模型 = 成本更高）
  - ⚠️ **没有第二组模型配置** —— 视觉 / 图像生成 / TTS 这类**需要独立模型的能力不做**
    （工具集里就没有这三个，见 [12-c C2](./12-c-需求-工具技能与扩展.md)）
- **支持的供应商**：

  | 供应商       | 说明                                                                                        |
  | ------------ | ------------------------------------------------------------------------------------------- |
  | `anthropic`  | Anthropic 官方                                                                              |
  | **国产四家** | 智谱 / MiniMax / DeepSeek / 千问 —— **全都提供 Anthropic 兼容端点**，换 `LLM_BASE_URL` 即可 |

  > ⚠️ **只有一个 `anthropic` 适配器**（`@langchain/anthropic`）——
  > 凡是提供 Anthropic 兼容端点的服务都接得上，换供应商只改 `.env` 三行。
  > ⚠️ **不接 OpenAI 原生协议**（`@langchain/openai` 没被用到）——
  > 所以 OpenAI / Gemini 这类原生端点**直接指过去是不通的**。

  > ⚠️ **本地模型**：同理，**只有提供 Anthropic 兼容端点的本地服务能直连**。
  > ⚠️ **Ollama / LM Studio / vLLM 提供的是 OpenAI 兼容端点**，
  > 直接把 `LLM_BASE_URL` 指过去**是不通的** ——
  > 要用本地模型，得先给它套一层 Anthropic 兼容的代理。

- **模型解析**（唯一实现处 `services/model.ts`）：
  主模型（`LLM_*`）→ 备用模型（`LLM_FALLBACK_*`，没配就没有）→ **没有可用模型**
  ⚠️ 对话 / 记忆抽取 / 摘要都从这里拿 —— 不许各处自己 new ChatModel
- **API Key 不入库**：启动时从 `.env` 读进内存即可；
  **不落库、不写日志、不在任何接口里回显**
- ⚠️ **启动时校验**（`src/config.ts` 的 `envSchema` + 跨字段校验）：
  - 配了 `LLM_MODEL` 但缺 `LLM_BASE_URL` → **启动失败**并指出缺哪个
  - 配了 `LLM_MODEL` 但缺 `LLM_API_KEY` → **启动失败**
    ⚠️ **例外：回环端点可以不要 Key** ——
    本机跑的、没有鉴权的服务（比如套了 Anthropic 兼容代理的本地模型）没有 Key 这回事
  - 备用模型三项只给了一部分 → **启动失败**
  - ⚠️ **`LLM_MODEL` 留空是合法的** —— 「还没配置模型」是**运行时**状态
    （聊天时提示），不是启动失败
- ⚠️ **`LLM_BASE_URL` 走 SSRF 校验**（`src/lib/security/model-endpoint.ts`）：
  - **协议只允许 http / https**
  - **禁止指向云元数据 / 链路本地地址**
    （`169.254.169.254` · `169.254.170.2` · `100.100.100.200` ·
    `metadata.google.internal` · `169.254.0.0/16` · `fe80::/10` · `0.0.0.0/8`）
  - ⚠️ **回环地址是例外**（`127.0.0.1` · `localhost` · `::1`）——
    本机服务就住在那儿，**必须允许**
  - ⚠️ **私网自建（`10/8` · `172.16/12` · `192.168/16`）放行** ——
    NAS 上的推理机是合法用法（和 HTTP 工具那道闸的口径不同：
    那道闸管的是「模型主动发起的请求」）
  - ⚠️ **启动时校验一次**（静态：协议 + 主机名 / IP 字面量）→
    **每次调用前再校验一次**（加 DNS 解析 → 域名被劫持到元数据地址也拦住）
- **备用模型**：`.env` 的 `LLM_FALLBACK_*` 三项（**留空 = 没有兜底**）；
  ⚠️ **仅在「一个内容 chunk 都还没吐出去」时切** ——
  已经吐过字再换模型，用户会看到两段拼接的答案
  （见 [12-b B3](./12-b-需求-对话与编排.md) 与 `src/agent/model-stream.ts`）
- ⚠️ **供应商不支持思考参数 → 自动降级**：报错里提到 `thinking` / `reasoning`
  就**关掉思考重试一次**（不关就整轮失败）
- **没有可用模型**时：后端返回 503 + 「还没配置模型」，
  前端显示提示并**指明改 `.env` 的 `LLM_MODEL`**，**不是 500**

**验收**：

- [x] 配一条 `anthropic` 模型 → 重启后 `/chat` 能正常对话
      （已用智谱 GLM 的 Anthropic 兼容端点跑通：对话 / 流式 / 思考 全绿）
- [x] 回环端点 → **不需要 API Key**
      （`createChatModel` 对回环端点不强制 Key，填个占位串给适配器；
      `validateRelations` 也放行「回环端点缺 Key」）
- [x] `LLM_MODEL` 留空 → 聊天页提示「还没配置模型」并指出改 `.env`，不报 500
      （后端返 **503 + `MODEL_NOT_CONFIGURED`**，前端聊天区出提示条 + 输入框禁用）
- [x] `LLM_BASE_URL` 填 `http://169.254.169.254/` → 启动即报错
      （`validateRelations` → `modelEndpointProblem` → 启动失败并指出是哪个地址）
- [x] `LLM_BASE_URL` 填回环地址（`http://127.0.0.1:…`）→ **允许**（不被 SSRF 拦）
- [x] 主模型 500 时自动切备用，且**在已吐字之后不切**
      （`src/agent/model-stream.ts`：吐过内容就抛错不切；没吐过才切备用）
- [x] API Key 不出现在日志、错误信息与任何接口响应里
      （`GET /api/v1/models` 只回模型名；错误信息统一过 `sanitizeMessage()` 打码）
  - [x] 配了 `LLM_MODEL` 却漏了 `LLM_BASE_URL` → **启动失败**并指出缺哪个
  - [x] 换一家供应商（只改 `.env` 三行）→ **不用改代码**就能用

## A4 · 上下文文件与提示词 · P0 ✅

**需求**：Agent 的「人格 / 项目指令 / 各类提示词」全部用**文件**表达，改完下一轮生效。

**技术要求**：

### 人格与记忆的六层 ⚠️

> **「人格记忆」不是一个东西，是六层** —— 每层的**更新方式**不一样。
> 这是本项目记忆体系的骨架（对齐 Hermes 的分层记忆）。

| 层              | 载体                        | 装什么                         | **会自更新吗** | 谁更新                        |
| --------------- | --------------------------- | ------------------------------ | -------------- | ----------------------------- |
| **L0 人格**     | `SOUL.md`（项目根）         | 语气 / 风格 / 身份             | ❌ **不会**    | **人**手写                    |
| **L1 项目指令** | `AGENTS.md`（项目根）       | 项目约定、构建命令、禁忌       | ❌ **不会**    | **人**手写                    |
| **L2 语义记忆** | `data/memory/MEMORY.md`     | 环境事实、踩过的坑、工具怪癖   | ✅ **会**      | T2 LLM 抽取                   |
| **L3 用户画像** | `data/memory/USER.md`       | 偏好、身份、沟通风格、技术水平 | ✅ **会**      | T2 LLM 抽取                   |
| **L4 程序记忆** | `data/skills/*/SKILL.md`    | 「怎么做这件事」               | ✅ **会**      | 运行时沉淀（工具调用 ≥ 5 次） |
| **L5 情节记忆** | `data/atlas.db` + FTS5 检索 | 做过什么、说过什么             | ✅ **会**      | 对话本身                      |

> ⚠️ **L0 / L1 永远不被模型改写** —— 这是刻意的：
> 人格与项目指令是「**你**定义我是谁」，
> 让模型自己改自己的身份 = 开一个**持久化的提示词注入口**
> （对话里塞一句「以后你的语气改成…」就能永久生效）。
> **Hermes 也不改 `SOUL.md`。**
> ⚠️ 记忆层（L2/L3）**会**自更新，所以**写入前必须过安全扫描**
> （见 [12-e E4](./12-e-需求-观测安全与验收.md)）—— 否则记忆投毒能绕过对话层的注入检测。

### 上下文与提示词文件

| 文件                      | 作用                                    | 生效时机   |
| ------------------------- | --------------------------------------- | ---------- |
| `AGENTS.md`（项目根目录） | 项目级指令 —— 相当于 Hermes 的同名文件  | **每轮读** |
| `SOUL.md`（项目根目录）   | 人格 / 语气 / 风格 —— Hermes 的人格文件 | **每轮读** |
| `prompts/system.md`       | 系统提示词                              | **每轮读** |
| `prompts/tool.md`         | 工具使用规范                            | **每轮读** |

> 📌 **`prompts/tool.md` 走 `{{tool}}` 占位符** ——
> ⚠️ **模板里没写 `{{tool}}` 也会追加到末尾** ——
> 否则用户改过 `prompts/system.md` 之后，`tool.md` 就又变回「写了没人读」的文件。
> 📌 **回复语言走 `{{language}}`**（`.env` 的 `SYSTEM_LANGUAGE`）——
> 它管的是**Agent 回复用什么语言**，不是界面语言（界面文案是写死的中文）。
| `prompts/memory.md`       | 记忆抽取 / 召回的指令                   | **每轮读** |
| `prompts/summary.md`      | 摘要指令                                | **每轮读** |

> ⚠️ **`AGENTS.md` / `SOUL.md` 只读** —— Agent 的工具集里**没有**写这两个文件的工具，
> 只能人手动改。
> ⚠️ **「只读」包括 `shell`** —— 路径沙箱只管**命令的工作目录**，
> 管不住**命令写到哪里**（`echo x > AGENTS.md` 直接落在项目根）。
> 所以另有一道**上下文文件保护**（`lib/security/context-files.ts`）：
> **事前拦**（明显的写入命令直接拒绝）+ **事后还原**（被改了就地还原并如实告诉模型）。
> 技能脚本走同一条路。

- ⚠️ **没有版本表、没有发布指针、没有「已发布但未生效」的半状态**
  —— **文件当前内容就是生效内容**；版本与回滚 = git
- 每轮对话**读文件**（不缓存到进程）→ 改完**下一轮立即生效，不用重启**
- `AGENTS.md` 不存在 → 跳过（它是**项目**的指令文件，不是 Atlas 的出厂文件）
- ⚠️ **`SOUL.md` / `prompts/*.md` 缺失 → 启动时从 `src/prompts/defaults.ts`
  的兜底模板写回文件**（不是运行时悄悄用默认值）——
  这样文件始终存在，每轮读的都是文件，**不会出现「有的读文件、有的读内存」的两种行为**
  - ⚠️ 正常情况下用的是**仓库里的完整出厂版**（进 git，可 diff 可回滚），
    兜底模板只在文件被删时启用，且**很短**（够跑就行，不重复仓库内容）
- 提示词内容里的占位符：`{{tools}}` `{{memories}}` `{{skills}}` `{{date}}`
  `{{summary}}` `{{retrieval}}` **`{{agents}}`**
  ⚠️ **未识别的占位符原样保留**（不要清空 —— 清空会把用户写的模板内容吞掉）
  - 📌 `{{summary}}` —— **会话摘要**（早期对话折出来的那一段）
  - 📌 `{{retrieval}}` —— **跨会话检索**的摘要（排在记忆后面）
  - 📌 `{{agents}}` —— **项目指令**（`AGENTS.md` 的正文；没有文件就不出现这一段）
- **文件缺失** → 启动时从 `src/prompts/defaults.ts` 写回兜底版本，
  并在响应里标注「用了兜底提示词」—— 不要静默降级
- 提示词改动写审计（`PROMPT_UPDATED`，记文件路径 + 内容 hash + git commit）

### A.4.1 `AGENTS.md` 怎么进上下文 ⚠️

> ⚠️ **「每轮读」不等于「每轮全量注入」** ——
> 项目指令文件动辄一两万字，全量注入就是每轮 1 万多 token
> （月度 token 预算按 20 万算，几十轮就见底了）。

| 机制                          | 说明                                                                 |
| ----------------------------- | -------------------------------------------------------------------- |
| **系统提示词带前一截**        | `{{agents}}` 注入 `AGENTS.md` 的**前 `AGENTS_MAX_CHARS` 字**（默认 6000） |
| **截断要说清楚**              | 截了就在末尾写「已截断，共 N 字」—— 别让模型以为看到了全文            |
| 📌 **砍掉的部分要「可达」**  | **文件远大于上限时，注入章节目录（带行号）** —— 光截断没用：模型不知道后面还有规矩，就永远不会去读 |
| **模型能自己读全文**          | `read_file` 传 `"AGENTS.md"` / `"SOUL.md"` → **读得到项目根那份**      |
| **读全文不过全局截断**        | 截掉头只剩尾比读不到更糟 —— 上下文文件一次给够（上限 2 万字）          |
| **只认裸文件名**              | `sub/AGENTS.md` · `../AGENTS.md` · `.env` **都不行** —— 只开这两个口子  |
| **依然只读**                  | 写这两个文件照样越界（它们不在工作区里，写工具到不了）                  |

> 📌 **`AGENTS_MAX_CHARS` 可配**（`.env`）——
> 想要全文就调大（`18451` 就够本仓库），想省 token 就调小。
> ⚠️ **调小之后，模型自己读全文这条路更重要** ——
> 截断提示里会告诉它「要用 `read_file` 读 AGENTS.md」。
>
> 📌 **「前 N 字」常常是错的取舍**（2026-11-01 优化批次实测）——
> 项目指令文件往往是「**前面一大段项目介绍，后面才是真正的规矩**」。
> 本机 27,152 字的 `AGENTS.md`：
> **前 6,000 字只到「§1 项目是什么」的中段** ——
> §3 协作模式 / §4 默认行为 / §5 不主动做的事 **一个字都没进上下文**。
>
> → **目录 + 行号** 让被砍掉的部分**可达**：
> `read_file` 支持 `offset`（行号）与 `limit`，
> 有了「第 360 行」这个信息，模型能**精确读那一节**，
> 而不是把整个文件再读一遍。
> ⚠️ **目录只在「文件远大于上限」时生成** ——
> 只超一点点时缺的那点不值 400 token 的目录。
>
> 📌 **实测的账**（27,152 字的 `AGENTS.md`）：
>
> | 方案                   | AGENTS.md 段 | 系统提示词合计 |
> | ---------------------- | ----------- | -------------- |
> | 前 6000 字（原来）     | 3,360       | 4,824          |
> | 前 6000 字 + 目录      | 3,783       | 5,230          |
> | **前 3000 字 + 目录**  | **2,111**   | **3,558**      |

**验收**：

- [x] 改 `prompts/system.md` → **下一轮**对话行为改变（不重启）
- [x] 改 `AGENTS.md` → 下一轮 Agent 按新指令行事
      （**实测**：`AGENTS.md` 的 §4.1 在第 10174 字，默认只注入前 6000 字 →
      模型自己 `read_file` 读了全文 → 照 §4.1「停服务 / 跑测试 / 列问题 / 打勾 / 停下来」回答；
      注入部分够时它直接答，**零工具调用**）
- [x] 改 `SOUL.md` → 下一轮语气 / 风格改变
- [x] 📌 **文件远大于上限时 → 注入章节目录（带行号）** ——
      模型能据此用 `read_file` 的 `offset` 精确读某一节
- [x] 📌 **没远大于上限时 → 不加目录**（不白花那 400 token）
- [x] ⚠️ **Agent 没有任何工具能改写 `SOUL.md` / `AGENTS.md`**（人格与项目指令只读）

- [x] `git checkout` 回上一版 → 行为恢复（回滚 = 改文件）

## A6 · 上下文构成报告（`/context`） · P1 ✅

**需求**：能查出「**这一轮到底给模型发了什么**」。

⚠️ **上下文是隐形的** —— 人格、项目指令、长期记忆、技能、跨会话检索、会话摘要……
六段东西每轮都塞进系统提示词，**界面上一个字都看不见**。
于是「它怎么知道这个的」「为什么它忘了我说过的话」这类问题
**没有任何手段能查** —— 只能去翻源码猜。

**技术要求**：

- **一个斜杠命令 `/context [问题]`**（服务端解析 · **零 LLM 调用**）
- **固定段**（每轮都有）：

  | 段        | 来源                       |
  | --------- | -------------------------- |
  | 人格      | `SOUL.md`（本会话切过的那个）|
  | 系统提示词 | `prompts/system.md`        |
  | 工具规范  | `prompts/tool.md`          |
  | 回复语言  | `.env` 的 `SYSTEM_LANGUAGE` |
  | 项目指令  | `AGENTS.md`（**含截断标记**）|

- **动态段**（**给了问题才算得出来**）：长期记忆 · 技能（FTS5 匹配）· 跨会话检索命中
- 每段给四样东西：**字符数 · token 估算 · 是否截断 · 为什么在 / 为什么不在**
- 另给：**工具池**（总数 · 本轮上限 · 名字）· **会话历史规模**（条数 / 字数 / token）
- ⚠️ **检索只列命中，不调模型摘要** —— 斜杠命令**不能花钱**
- ⚠️ **token 是估算**（中文 1 字 ≈ 1 token · 英文 4 字符 ≈ 1 token）——
  够看出「哪一段最占地方」就行
- 落点：`services/context-report.ts`（`buildContextReport` / `renderContextReport`）

**验收**：

- [x] `/context` → 列出固定段 + 工具池 + 历史规模，**零模型调用**
      （集成测试 `tests/integration/slash-commands.test.ts` 断言 `modelCalls === 0`）
- [x] `/context <问题>` → 额外给出长期记忆 / 技能 / 跨会话检索命中三段
- [x] `AGENTS.md` 超长 → 报告里标「已截断」并写明用了前几个字
- [x] 会话历史规模按库里真实的消息算（条数 / 字数 / token 估算）

> 📌 **为什么值得有** —— 上下文是 Atlas 最「黑盒」的部分：
> 这一条命令把黑盒拆开给用户看，而且**不花一分钱**。

## A7 · 辅助模型（脏活走便宜模型） · P1 ✅

**需求**：记忆抽取、会话摘要、跨会话检索摘要、技能沉淀判断、cron 表达式解析——
这些「**脏活**」可以走一个便宜的辅助模型，不必拿主模型（尤其开了思考的）干。

📌 **为什么这是省钱的大头** —— 这几件事的共同点是
「**输入长、输出短、不需要多强的推理**」：
记忆抽取要喂整份记忆文件，会话摘要要喂整段历史，
检索摘要要喂一堆命中片段 —— **主模型的钱全花在这些地方最冤**。

**技术要求**：

- `.env` 三行（**留空 = 没有** → 全部走主模型，行为与之前一致）：

  ```dotenv
  LLM_AUX_BASE_URL=
  LLM_AUX_API_KEY=
  LLM_AUX_MODEL=
  ```

- ⚠️ **三项要么都给，要么都不给** —— 只给一半**启动即报错**
- ⚠️ **辅助模型的端点也要过 SSRF 校验**（`model-endpoint.ts`）——
  别让它变成一条绕过闸的旁路
- ⚠️ **辅助模型不思考**（`thinkingBudget = 0`）—— 「脏活」不需要推理
- ⚠️ **对话主路径不用它** —— 用户在问的问题永远交给主模型
- 落点：`services/model-utility.ts` 的 `resolveUtilityModel()`
  （**单独一个模块** —— 这样测试里 `vi.mock('./model.js')` 能拦得住它对主模型的调用）

**验收**：

- [x] 配了辅助模型 → 抽取 / 摘要 / 检索摘要 / 沉淀判断 / cron 解析都走它
      （`cost_logs.model` 记的是**辅助模型的名字**）
- [x] 没配 → 行为与之前完全一致（走主模型）
- [x] 只配了 `LLM_AUX_MODEL` → **启动即报错**并指出缺哪个
- [x] `LLM_AUX_BASE_URL` 指向云元数据地址 → **启动即报错**

> 📌 **主模型仍然是「那个干正事的模型」** —— 辅助模型只是分担杂活，
> 不会改变用户对话的质量。

## A8 · 提示词缓存 · P1 ✅

**需求**：系统提示词每轮都要重复注入（`AGENTS.md` + 记忆 + 技能 + 工具清单），
命中缓存时这一段**按打折价计费**。

**技术要求**：

- `.env` 的 `LLM_PROMPT_CACHE`（**默认关** —— 国产兼容端点未必支持）
- 给系统提示词那条消息打上 Anthropic 的 `cache_control: { type: 'ephemeral' }`
- ⚠️ **端点不支持 → 自动去掉标记重试** ——
  报错里带 `cache_control` 就退回不缓存，
  **与「供应商不支持思考参数」的降级是同一套路**
  （见 [12-a A3](./12-a-需求-应用外壳与上下文.md) 与 `agent/model-stream.ts`）
- ⚠️ **只缓存系统提示词** —— 其余消息逐轮变化，缓存没有意义
- 命中缓存的 token 记在 `cost_logs.cached_tokens`（字段已有）·
  `/usage` 与 `yarn cost:report` 单列一行（见 [12-d D4](./12-d-需求-记忆与配置.md)）
- 📌 **系统提示词要拆成「稳定段 / 易变段」** ——
  Anthropic 的缓存是**前缀缓存**：
  从消息开头到 `cache_control` 块为止的内容必须**逐字节相同**才命中。
  以前整套提示词是一个块、断点打在末尾，
  于是**每轮都变**的 `{{tools}}`（工具池按相关度裁剪）·
  `{{skills}}` · `{{memories}}` · `{{retrieval}}` · `{{summary}}` · `{{date}}`
  把整个前缀作废了 → **命中率恒为 0**
  （实测 `cost_logs`：65 次真实调用、221,860 输入 token，`cached_tokens` 全是 0）
  - **稳定段**（断点之前）：人格 `SOUL.md` + 工具规范 `prompts/tool.md`
    + 项目指令 `AGENTS.md` + 语言指令 + 模板里不含易变占位符的那部分
  - **易变段**（断点之后）：日期 · 可用工具 · 技能 · 会话摘要 · 长期记忆 · 跨会话检索
  - 拆分规则见 `services/prompt.ts` 的 `splitTemplate`：
    **按行拆，含易变占位符的行归易变段；标题跟着它那一节走**
- 📌 **端点支不支持缓存要能测出来** ——
  兼容端点对缓存的支持分三档，
  **最坑的是「静默失效」档**：接受 `cache_control`、不报错、但缓存根本没生效
  （智谱的 Anthropic 兼容端点就是这一档 —— 实测 25,217 token 的稳定前缀
  连发两次，`cache_read_input_tokens` 恒为 0）
  → `yarn cache:probe` 发两次**一模一样**的长前缀请求，
  看第二次有没有命中，**当场给出结论**

**验收**：

- [x] `LLM_PROMPT_CACHE=true` → 系统提示词那条消息带缓存标记
- [x] 端点报「不支持 cache_control」→ **自动退回不缓存**，这一轮照常跑完
- [x] 缓存 token 记进 `cost_logs.cached_tokens`（出口已有）
- [x] 关掉 → 行为与之前完全一致（不带标记）
- [x] 📌 **系统提示词拆成稳定段 / 易变段** ——
  断点只打在稳定段末尾，易变内容在断点之后
- [x] 📌 **关掉缓存时仍然发一整块字符串** —— 行为与改动前完全一致
- [x] 📌 `yarn cache:probe` 能当场测出端点支不支持缓存，
  并区分「报错不支持」与「静默失效」
